# Design: diffcheck-auto-rewrite

## Context

在 `app/pipeline/generate.py` 中，多平台生成初稿后会执行 `diffcheck.evaluate(bodies, tags)` 计算成稿两两重合率与篇幅。
目前，当存在两两重合超标时（如 `gzh∩zhihu = 16.67%`），系统仅将诊断警告写入 `qa.warnings` 依赖人工审阅。
本设计在 `generate.py` 的后置评估阶段增加自动化定向重写收敛分支。

## Goals / Non-Goals

**Goals:**
- **自动化收敛**：在不增加人工干预的前提下，将超标重合度降至 `diff_max_overlap`（≤10%）阈值内。
- **精准改写反馈**：基于 `pairwise_overlap_sentences` 提取的真实冲突例句构建 `feedback`，只改冲突句子，不破坏已有事实骨架。
- **严格成本控制**：默认最多重写 1 轮（`DIFF_MAX_REWRITE_ROUNDS=1`），仅对重合最严重的冲突平台发起重写，防止调用风暴。
- **平滑降级（Fail-Safe）**：若改写后重合度未改善或 QA 失败，保留历史更优版本，不阻断整批交付。

**Non-Goals:**
- 不支持跨多轮的大规模全量重跑（每次改写仅针对单一后发冲突平台）。
- 不改变单平台内的 FactGuard 事实纠错逻辑（两套质检互不干扰、依次生效）。

## Decisions

### 1. 改写目标平台选择策略 (Target Selection)
- **决策**：当检测到平台对 `(A, B)` 重合超标时，优先选择在 `req.platforms` 中**排序靠后的平台**作为改写目标。
- **理由**：排在前面的平台（如长文长篇公众号）通常承载更完整的基准事实体系，后发平台（如知乎问答、小红书笔记）应当以不同视角从主稿中分化，因此重写后发平台最为合理。

### 2. 差异化定向反馈格式 (Targeted Diff Feedback)
- **决策**：利用 `diffcheck.pairwise_overlap_sentences()` 提取的精确句子列表，组装成结构化改写指令：
  ```
  【跨平台去重改写】本稿与平台 {other} 存在 {overlap:.0%} 逐字重合。
  以下句子被判定为跨平台重复，请务必换词、换句式、从本平台特有视角（如知乎侧重底层反思/小红书侧重避雷点）重新表达，严禁整句复用：
  - 「冲突句1」
  - 「冲突句2」
  注意：素材中的核心数据与事实必须保留，变的是语言外壳与段落节奏。
  ```
- **备选考虑**：若只给空泛的“请降低重合率”，模型往往只微调一两字；直接给冲突句清单能精确打击“一字不差”的搬运现象。

### 3. 可观测性与 RunLog 事件
- **决策**：通过 RunLog 发出 `平台:{code}:去重改写{attempt}` 阶段事件，并在日志中记录改写前后的重合率对比。

## Risks / Trade-offs

- **[耗时与 API 消耗增加]** → 缓解：严格受 `diff_max_rewrite_rounds`（默认 1 轮）限制，且仅当 `overlap > max_overlap` 时按需触发；单平台禁用时不增加任何开销。
- **[改写后字数或 QA 产生次生问题]** → 缓解：改写后必须重新运行 `run_qa(dna, draft, mat)` 质检，只有在质量合格且重合度未恶化的前提下才采纳替换。
