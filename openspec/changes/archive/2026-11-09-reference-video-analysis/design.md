# Design

## Context

- `run_transcribe`（ASR/字幕）✓、`extract_keyframes` / `scene_times` ✓、`describe_frames` ✓ 都在
- `llm.chat_json` 已是通用 JSON 调用 ✓
- 视觉调用已修好两个坑（请求头 / 推理型 token 预算）✓

## Decisions

### D1：不新造分析模型，把三路证据拼成一次 JSON 调用

输入给模型的是：**转写全文 + 关键帧描述（带时刻）+ 场景切换时刻 + 时长** ✓。
一次调用出一个 JSON ✓。被否：分多次问（更贵、还容易自相矛盾 ✗）。

### D2：数字自己算，不让模型算

语速（字/分）、段数、切换次数**本地算好**再给模型 ✓ —— 模型的算术不可信 ✗。
模型只管**判断与措辞**（这段是开场还是论证、钩子靠什么留住人）✓。

### D3：没有语音时不假装

转写为空 → 明确写"无语音" ✓，只分析画面与节奏 ✗ 不编台词。

### D4：只读，不动用户的库

分析结果**不落库**（返回即用）✓ —— 它是参考，不是素材 ✗。

## Risks

- [模型过度归纳] 短视频结构松散，可能被强行总结成三段式 → prompt 里要求"没结构就说没结构" ✓
- [成本] 每条 1 转写 + 6 视觉 + 1 分析
