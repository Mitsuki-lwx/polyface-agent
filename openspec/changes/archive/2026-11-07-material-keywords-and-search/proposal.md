# Proposal

## Why

**素材找不到，就没法复用。** 现在 `material` 表的字段是
`raw_text / source_kind / title / core_message / tone / audience / facts_json / parent_id / angle / format`
—— **没有任何索引字段** ✗。你手上素材一多，只能靠翻列表和记忆找"之前写过 AI 周报那篇"。

对照：`asset` 表**有** `tags_json` ✓ —— 二进制资产能按标签找，文本素材反而不能 ✗。

另外一个现实：长文拆成 10 条子素材后，每条都是独立选题 ✓ —— 复用时你要找的往往是
**其中某个角度**，而不是整篇 ✗。所以索引必须挂到**子素材**上。

## What Changes

- **素材关键词**：每条素材（含拆分子素材）带 1~8 个关键词，可增删改。
- **自动候选 + 人工确认**：解析素材时顺带产 3~8 个候选关键词；**必须经你确认才落库**
  （自动产出≠写进库 ✗ —— 落库前可改可删）。
- **检索**：按关键词过滤（多词取交集）+ 按正文全文搜（FTS5）；两档可叠加。
- **复用入口**：从检索结果**直接开新一轮生成** —— 否则"查到"和"用上"之间还隔着复制粘贴 ✗。

## Capabilities

### New Capabilities

- `material-index-and-reuse`: 文本素材的**关键词索引与检索复用** —— 关键词的产生与确认、
  两层挂载（素材 + 子素材）、关键词/全文两档检索、以及"查到即可复用"的闭环。

### Modified Capabilities

（无）

## Impact

- **存储**：`material` 加 `tags_json`；新增 FTS5 虚表 + 触发器（**前提待验证**，见 tasks 0）
- **Python**：`understand` 产出候选关键词；`StructuredMaterial` 增字段
- **Java**：素材列表/详情增查询参数；保存时接收确认后的关键词
- **前端**：① 素材的确认步骤显示候选并允许编辑；素材历史加搜索框
- **成本**：解析多几个 token（关键词在同一批输出里，不额外调用）
- **风险**：FTS5 在 sqlite-jdbc 里若不启用 ✗ → 退回 `LIKE`（功能保留，性能差一档）
