# Design

## 关键决定

### 一、读事件，不加接口

Java 在每平台调用前后已经写了 `stage="平台"` 的 start/end/fail 事件（编排者才知道边界）。
直接解析这个文件，不新增进程间协议。

### 二、状态只有四种

`pending`（还没轮到）/ `running` / `done` / `failed`。
未知值一律按 pending —— 界面的容错比协议精确更重要。

### 三、半行 JSON 跳过

两个进程追加同一个文件，可能读到写一半的行；解析失败就跳过（与 `JobProgress.read` 同一条规矩）。

### 四、顺序与请求一致

返回的数组按 `params.platforms` 顺序，而不是事件里的出现顺序 —— 否则界面会跳来跳去。
