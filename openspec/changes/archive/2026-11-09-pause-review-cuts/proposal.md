# Proposal

## Why

今天剪停顿**只看声学** ✗：`silencedetect`/VAD 判到静音超过阈值就剪。
可是"停 2 秒"有两种，声学上完全一样：

| 现场 | 该不该剪 |
|---|---|
| 卡壳、想下一句、犹豫 | **该剪** ✓ |
| 故意留白、强调、段落之间的呼吸 | **不能剪** ✗ |

规则永远分不清，差别只在**语义**。用户拿到粗剪后逐条手工回听，就是在补这一刀。

## What Changes

新增**停顿复核**：把规则犹豫的停顿点交给模型，只回答"剪 / 留 + 理由"。

- 一个 Python 模块 `pausereview`：造候选 → 一次批量调用 → 按判定改剪点
- 粗剪 CLI 新增 `--pause-review`（默认**关**）
- 界面新增一个勾选框，旁边明确写"会把转写文本发给你配的 LLM"

**不改变**：剪点仍然由程序给时间，模型只投票；默认行为与今天完全一致。

## Capabilities

### New Capabilities
- `pause-review`: 停顿点的语义复核（规则判不了的"留白 vs 卡壳"）

## Impact
- Python：新模块 + 1 个提示词 + 粗剪入口接线
- Java：参数透传（无新端点）
- 成本：**一次**调用 / 条视频；候选 ≤80 条，输入约 4k token

## Non-Goals
- 不让模型决定**时间戳**（它看不到音频）
- 不让模型做整片重剪（那不是这个能力）
- 不默认开启（数据边界：转写文本会出本机）
