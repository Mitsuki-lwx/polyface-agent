# 参考视频分析 —— 交付说明

> openspec change: `reference-video-analysis`

## 一、做什么

输入一条**别人的**视频 → 输出结构 / 节奏 / 钩子分析（JSON）✓。只读，不落库 ✗。

```
POST /analyze-reference        （Python）
POST /api/reference/analyze   （Java 代理）
```

## 二、最关键的设计：数字本地算，模型只做判断

| 谁算 | 算什么 |
|---|---|
| **本地** ✓ | 字数、语速（字/分）、镜头切换次数、平均镜头时长、切换时刻 |
| **模型** ✓ | 这段是开场还是论证、钩子靠什么留住人、画面是什么类型、能抄什么 |

模型**数数不可信** ✗ —— 让它"数一下说了多少字"它会给你一个看起来合理但错的数字 ✓。

## 三、实测（47 秒口播，41 秒完成）

```
数字: 47.02s · 233 字 · 297 字/分 · 镜头切换 1 次 · 平均镜头 23.5s

hook: 反常识 ——「只要有人出头帮你争取利益，你只需要做一件事…」
      why: 把结论压成极简指令，且与「当老好人」的直觉相反

structure:
  0.0–6.7s    开场  直接抛结论
  6.7–13.1s   论证  立反面靶子「最傻的做法就是去当老好人」
  13.1–25.2s  举例  买衣服砍价的生活场景
  25.2–31.2s  转折  反问「你以为你大度吗」
  31.2–38.5s  收尾  给行动指令

visual: 口播（三张关键帧同一人、全片只切 0.1s 一次 → 一镜到底）

takeaways: 4 条全是**动作**（"开头第一句就把结论压成…"），没有"内容要优质"这类空话 ✓
```

**可核对性**：`structure` 带秒数 ✓，按 13 秒跳过去确实是"买衣服砍价"那段 ✓。

## 四、防呆（写进 prompt 的硬规则）

1. **不许编台词** ✗ —— 无语音时明确写"无语音"，只分析画面与节奏 ✓
2. **不许强行三段式** ✗ —— 结构松散就说"无明显分段" ✓
3. **数字用材料给的** ✗ 不要自己算
4. **takeaways 必须是动作** ✓，不是评价 ✗

## 五、测试

`tests/test_reference.py`（4 条）：数字本地算 / 零时长不崩 / **无语音不编台词** / 转写截断到 4000 字 ✓。

## 七、踩到的坑：新的 scene 必须登记版本

加完 `scene="reference"` 后全量测试红了 ✗：

```
这些 scene 没有登记版本号：['reference']
```

项目有一层**提示词版本追踪** ✓：代码里出现的每个 `scene` 都要登记到 `SCENE_BUILDERS` ✓，
否则那个提示词改了也没人知道 ✓。

登记时又撞第二个坑 ✗：版本号靠**函数源码**算指纹 ✓，而我把提示词写成了**模块级常量** ✗ ——
常量算不出指纹（返回空字符串 ✓）。改成 `system_prompt()` 函数才通过 ✓。

> 教训：在这个仓库里"加一个提示词"不是只写一段字符串 ✓ ——
> 还要登记 + 让它是可被算指纹的函数 ✓。
