# 任务书：质检加固 + 观测修复（修到不误导用户）

- 文档类型：task（事前三件套之一）
- 版本：v1.0 · 日期：2026-09-15
- 关联：FR-60（QA 质量门）、FR-71（可观测）、FR-70（调用加固）、ADR-009（事实清单防幻觉）、ADR-016（观测）
- 前置：另一 AI 于 2026-09-14 完成的评估（`outputs/项目可行性与现实推进建议-2026-09-14.md`）指出 6 类问题，**均已识别但未修复**

---

## 1. 背景（问题来自独立评估，经我逐条复核确认）

2026-09-14 的独立评估给出关键判断：

> **值得继续，但应从"全平台内容工具"收缩为"已有原创长文 → 小红书建议稿 → 人工校改"的可靠工作流。下一张开发任务应是"修质检和事实确认闭环"，不是"再加一个功能"。**

**已复核确认的问题（代码级）**：

| # | 问题 | 代码位置 | 严重度 |
|---|---|---|---|
| 1 | **规则 warnings 在真实模式被丢弃** | `_llm_qa(dna, draft, mat, issues)` 只接收 issues；`warnings=llm_warns` 覆盖了规则 warnings | 🔴 高 |
| 2 | **`bool(data.get("passed"))` 使字符串 `"false"` 被判为 True** | `generate.py:274` | 🔴 高 |
| 3 | **LLM 返回的 issues 不参与 passed 判定** | `passed = ... and not issues`（issues 仅指规则 issues） | 🔴 高 |
| 4 | **空正文可通过质检** | `_rule_qa` 无正文非空校验 | 🔴 高 |
| 5 | **`trace_span` 会替换业务异常** | `observability.py` 上下文管理器在 `yield` 处捕获异常后再次 `yield` → `RuntimeError: generator didn't stop after throw()` → 被误分类为普通 `LLMError`，**破坏限流重试语义** | 🔴 严重 |
| 6 | **`flush()` 未先判断启用开关** | `observability.py` + `main.py` 无条件调用 | 🟡 中 |

**后果**：系统会显示"✅ QA 通过"，但实际存在未披露的问题（正文含无依据数字、甚至正文为空）。**这会让用户误信可靠性，比功能缺失更危险。**

## 2. 目标

1. **不再误报通过**：任何已知阻断问题都不得显示"QA 通过"
2. **告警不丢**：规则的数字/格式告警必须在真实模式中保留并展示
3. **观测不改业务语义**：观测成功与否，业务异常类型与重试行为必须完全一致
4. **诚实表述**："未发现错误"与"保证正确"在 UI/文档中明确区分
5. **不破坏既有能力**：mock 模式、5 平台生成、既有测试全部保持通过

## 3. 范围

### In（本任务做）

| # | 事项 |
|---|---|
| 1 | **严格解析 LLM 质检返回**：`passed` 只接受真正的布尔值；字符串/数字等一律视为类型不合约并**记入问题** |
| 2 | **合并全部问题源**：规则 issues + 规则 warnings + LLM issues 统一参与判定；**有阻断问题一律不通过** |
| 3 | **补结构校验**：正文非空（去空白后）、标题非空、平台必填字段；空正文/结构异常直接判不通过 |
| 4 | **规则 warnings 保留**：真实模式返回的 `QaReport.warnings` 必须同时包含规则与 LLM 的告警 |
| 5 | **修复 `trace_span`**：span 创建失败才降级；**业务异常必须原样抛出**，不得被观测层替换 |
| 6 | **`flush()` 先判开关**：未启用时**绝不**初始化客户端 |
| 7 | **补回归测试**：覆盖上述全部边界（至少 20 个确定性场景，含报告建议的场景清单） |
| 8 | 交付说明 + 更新文档表述边界 |

### Out（本任务不做）

| 事项 | 原因 |
|---|---|
| 事实集的增删改保存、生成时复用已确认事实 | 属**下一个任务**（"事实确认闭环"），本任务先把"不误报"做扎实 |
| 稿件正文编辑/保存/导出 | 同上 |
| 历史稿正文补齐 | 同上 |
| Java 180s 超时 vs 250s 生成的预算冲突 | 独立问题（涉及任务模型设计），另开任务 |
| "数据不出本机"表述修正、start.bat 去开发机路径、CORS 收紧 | 属"内测版交付"任务（第二关） |
| 自动成片、海外平台、模板学习扩展 | 报告明确建议暂缓 |

## 4. 修复标准（来自评估建议）

> 严格解析模型返回结构；合并全部规则和模型问题；**有阻断问题一律不得显示通过**；空正文和结构异常必须拒绝；标题、正文及关键数字关系纳入校验；保留人工终审。**"没有发现错误"应与"保证正确"明确区分。**

补充判定原则（本任务确立）：

| 原则 | 说明 |
|---|---|
| **fail-closed** | 解析不确定时判**不通过**，而非默认通过 |
| **问题不丢** | 任何来源的问题都必须出现在报告里 |
| **类型严格** | LLM 返回类型不合约按"不合格"处理并记明原因 |
| **观测透明** | 观测层异常绝不可改变业务异常类型 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 判定变严导致真实生成大量"不通过" | 体验变差 | 这是**正确行为**（宁可提示风险也不误报通过）；同时确保 warnings 可见，让用户能判断 |
| 上游额度受限，真实链路难验证 | 无法端到端 | mock 覆盖全部边界；真实链路尽力而为并**显式标注未验证部分** |
| 修改 QA 影响既有测试 | 回归 | 先跑基线，改后对比；既有 38 测试必须全绿 |
| 修复过宽导致行为大改 | 不可控 | 严格限定在"判定与告警"路径，不动生成逻辑 |
