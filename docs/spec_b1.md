# spec —— B1 图文成片

版本：2026-10-11　　对应 tasks：`docs/tasks_b1.md`　　验收：`docs/checklist_b1.md`
上游依据：`docs/05` FR-52/54 · `docs/08` ADR-018 · `docs/49` §4 §5（三条必须正视的约束）· `docs/71`

---

## 1. 背景

`docs/49` §4 的事实基础（当时实测）：**做 B1 的地基已经在了** ——
ffmpeg/ffprobe 可用、音视频探测与音轨抽取已实现且全本地、本地 ASR 已实现（可选依赖 + 降级）、
**剪辑单已交付**（`run_clip_sheet()`，分镜含 `script`/`subtitle`/`visual`/`duration_hint`/`sound`）。

缺的只有一步：**把剪辑单变成 MP4**。

这一步要吸收 `docs/49` §5 的三条约束 —— 它们是设计约束，不是实现细节：

| 约束 | 含义 |
|---|---|
| **§5.1 平台规则** | 抖音官方把「单图 + 大量文字」「模板感强的图片轮播」列为**低质** —— 最省事的图文成片恰好是被打击的形态 |
| **§5.2 行业现实** | 是「AI 预剪 + 模板参数 + **人工审片**」，不是零人工全自动 |
| **§5.3 TTS 与数据边界** | 云端 TTS 要把成稿全文再发一家服务商（ADR-017 要扩）；本地 TTS 给发布包加几百 MB |

## 2. 目标用户

**现阶段只有作者本人**。他有一份成稿 + 几张自己的图 + 一首自己的 BGM，
想要一个能直接发（或改两下就能发）的初剪成片。

## 3. 能力清单（一句话一条）

1. **从剪辑单起步**：用成稿附带的剪辑单（分镜）作为成片结构 —— 不重新"想"一遍怎么剪
2. **配音（可选）**：分镜的 `script` → 语音；**没装 TTS 就降级成"无声 + 字幕"并给安装指引**，
   绝不因为缺一个可选依赖就整体失败
2b. **选人声**：列出可用音色让用户挑（本机实测 SAPI 有三个），不替他定死一个
2c. **导入用户自己的配音**：每个分镜可以给一个 `voice_file`（自己的录音、或别的工具导出的），
   给了就用它、不调 TTS。**这条比 TTS 重要** —— 真人配音永远比合成好，
   而 TTS 只是"没录的时候别空着"
3. **画面由用户给**：每个分镜配一张图（上传或从素材库选）；`visual` 是**提示**不是素材
4. **动起来**：每张图给缓慢推拉/平移（Ken Burns）—— 对 §5.1 的直接回应：
   动起来的图与死板轮播在观感上是两回事
5. **字幕**：分镜的 `subtitle` 烧进成片；字幕时间**跟着配音走**
6. **转场**：分镜之间给转场（默认一个克制的基础转场）
7. **BGM + 卡点**：用户给音频文件；检测节拍；按选定策略对齐（见关键决定二）
8. **两种对齐策略**：默认**配音优先**（脚本完整），可切**卡点优先**（严格踩点，允许改分镜时长）
9. **产物是"初剪"**：一个 MP4 + 一份"这次怎么剪的"记录（分镜时长、节拍、用了哪些图），
   供人工定稿 —— 不做"零人工出网感"的承诺（§5.2）
10. **任务化**：分钟级，必须能看进度、能取消、**能断点续跑**（复用 M8）

## 4. 非功能要求

- **数据边界不变**：TTS 与节拍检测都**本地**跑。**不引入任何新的外部服务商** ——
  ADR-017 与 README 的「数据边界」表**都不需要改**
- **不内置素材**：图片与 BGM 都由用户提供。既避开版权与体积，也避开"模板感"
- **可选依赖必须真可选**：`asr.py` 已经立过这个先例（检测到才用，缺失则降级 + 安装指引）。
  TTS 与 librosa 走**同一条路**：缺了功能降级，不整体失败
- **发布包不显著变大**：新增的只是代码；大依赖（TTS 模型、librosa）**不进包**
- **合成必须可复现**：同一份输入 + 同一份参数 → 同样的成片（除编码抖动）
- **失败要指到具体分镜**：第几个分镜的图缺失/音频读不出，要能直接说出来
- **不覆盖源素材**：所有产物都是新文件

## 5. 设计骨架

```
成稿 + 剪辑单(scenes)                用户的图        用户的 BGM
        │                              │                │
        ├─ 配音：script → TTS ──────────┤                │
        │   （缺 TTS → 无声 + 字幕）    │                │
        │                              │                │
        └────────► 每个分镜的**实际时长**（由配音决定，默认）│
                       │                │                │
                       ▼                ▼                ▼
                   缓动(Ken Burns)   图片            节拍检测(librosa)
                       │                │                │
                       └──────┬─────────┘                │
                              ▼                          ▼
                          逐分镜视频段 ──► 转场拼接 ──► 对齐 BGM ──► MP4
                                                          │
                                                    初剪记录（分镜时长/节拍/素材）
```

**关键决定一：分镜时长由「配音长度」决定，不由模板决定。**

`duration_hint` 是**提示**，不是约束。真正的时长来自配音实际说了多久 ——
否则要么截断脚本、要么留白，两种都伤成片。这条是"配音优先"的物理基础。

**关键决定二：卡点是「尽量多」，不是「必须全」；两种策略都提供，默认配音优先。**

分镜时长不能既由配音决定、又由节拍决定 —— 这是硬冲突。所以：

| 策略 | 行为 | 代价 |
|---|---|---|
| **配音优先（默认）** | 时长不动；**平移 BGM 的起始偏移**，让**尽量多**的分镜边界落在节拍上 | 不保证每个切换都精确踩点 |
| **卡点优先** | 每个边界精确落在节拍上，不够长就拉、超了就截 | **会改变脚本时长**（配音跟着伸缩或留白，字幕跟着变） |

默认配音优先，因为"脚本完整"比"踩点精准"重要得多 —— 而且观感上，边界**多数**落在节拍上
已经足够"有卡点感"。

**关键决定三之前：TTS 不是终点，**用户自己的配音**才是。**

合成音色永远不如真人。所以时间线的每个分镜都可以带 `voice_file` ——
用户用自己的录音、或用别的工具（剪映之类）导出的配音都行。
**TTS 的定位是"没录的时候别空着"，不是"替你配音"。**
选音色同理：列出可用的让用户挑，不替他定死一个（本机 SAPI 实测有中文女声/英文女声/英文男声）。

**关键决定三：TTS 与节拍检测都是「可选依赖 + 降级」，复用 `asr.py` 已经立好的先例。**

- 缺 TTS → 出**无声 + 字幕**的成片，并给安装指引（不是报错退出）
- 缺 librosa → **不做节拍对齐**，BGM 从 0 秒起原样铺，并说明"未做卡点"

这条让 ADR-017 完全不用动：**没有任何数据离开本机**。

**关键决定四：不内置图片与 BGM。**

版权是用户的、体积是发布包的、而"模板感"恰恰是 §5.1 打击的东西。
用户自己的图与音乐既合法又不"模板"。

**关键决定五：产物是「初剪」，并附一份可复核的记录。**

§5.2 明说了不做"零人工全自动"。所以除了 MP4，还要输出**这次怎么剪的**：
每个分镜的实际时长、用了哪张图、节拍在哪、BGM 偏移多少。
人工定稿时看这份记录，比重新猜快得多。

**其它骨架决定：**

- 走**任务化**（复用 M8）：分钟级 + 进度 + 取消 + **断点续跑**
- 分镜级落盘（复用 `done/` 契约）：每个分镜的视频段做完就落盘，中断了不用重头
- 复用现有能力：`rc.cut_video` 的 ffmpeg 调用风格、`rc.burn_subtitles` 的字幕烧制、
  `rc.preview_frame` 的抽帧、`RunLog` 的阶段事件
- 参数（转场时长、缓动强度、字幕样式、BGM 音量）全部**可从命令行/配置到达**

## 6. Out of Scope（本版不做）

- **B2 智能剪已有视频**（FR-53）—— 排在 B1 之后（ADR-018）
- **图像生成**（按 `visual` 描述生成图）—— 会引入新服务商，且"AI 配图"未必比真实图好
- **内置曲库 / 内置图片素材**（见关键决定四）
- **真人出镜 / 口型对齐 / 数字人** —— 那是另一条技术线
- **自动发布**（沿用 ADR-010）
- **语音克隆 / 情感配音** —— 先用 TTS 的默认音色
- **多轨音频混音台**（BGM 淡入淡出之外的高级处理）
- **成片的人工定稿界面**（时间轴编辑）—— 定稿先用外部工具；本项目已有时间线模块可后续接
