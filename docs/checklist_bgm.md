## 1. VAD 找停顿（T1）

- [x] 同一段音频，**加 BGM / 不加 BGM** → 停顿区间**相同**（这是本 spec 的核心断言）
- [x] 对照旧路径：带 BGM 时旧路径 0 段，新路径能找出停顿
- [x] 语音空隙低于阈值 → **不算**停顿
- [x] 已有转写段时**不重复转写**（可观测：耗时显著短）
      **实测（2026-10-30，同一条带 BGM 的口播、同一个 workdir 跑两次）**：
      ```
      第一次 15s（真跑：探测→去冗余→找停顿→剪裁→抽音轨→转写→烧字幕）
      第二次 **1s**
      [续跑] 跳过转写（已完成：1 段字幕）
      [续跑] 跳过 7 个已完成阶段 ['探测','去冗余','找停顿','剪裁','抽音轨','转写','烧字幕']
      ```
- [x] 边界落盘，可复核

## 5. 铺伴奏（T5）

- [ ] **本版不做（按 spec 后置）**：产物时长 = 剪后视频时长（伴奏铺到等长）
      —— 铺伴奏（T5）**没有实现** ✗：没有任何"把伴奏铺成等长 / 循环 / 交叉淡化"的代码。
      为什么后置：它依赖**抽伴奏**，而抽伴奏只有在做**人声分离**之后才有"足够长的无人声窗口"
      （实测 BGM 下窗口普遍 < 2s）。而分离要 **+107MB 依赖**，只为补回 1 段 / 2.8s ——
      投入产出比不划算（`docs/08` ADR-026）。
- [ ] **本版不做（按 spec 后置）**：接缝处无爆音
      —— 没有"伴奏接缝"这个东西可验（铺伴奏没做）。
      ⚠️ 但**成片的剪点**验过：5 个剪点处相邻样本最大跳变 8~449，都远低于非剪点位置的 p95=2198 ✓
      → **原声剪点没有爆音** ✓（这不是伴奏接缝，如实区分）。
- [ ] **本版不做（按 spec 后置）**：改交叉淡化长度 → 接缝确实变化
      —— 交叉淡化是铺伴奏的一环，整条线没实现 ✗
- [ ] **本版不做（按 spec 后置）**：人声/伴奏电平可调
      —— 同上（没有"伴奏轨"可调）。⚠️ B1 **图文成片**里有 `--bgm-volume-db` ✓，
      那是**另一个模块**（`make_video.py`），别混为一谈。

## 收口（2026-10-17）—— 哪条线做了、哪条线**明确不做**

### 做了并验过的

- **找停顿默认走 VAD** ✓：带 BGM 从 **0 段 → 8 段**（实测对照，见上）
- **VAD 不可用时退回音量门限并标记** ✓（`source` 字段 + 报告里写明）
- **`bgm_aware` 开关** ✓：关掉回旧行为，可对照
- **核心断言"与 BGM 无关"**：⚠️ **部分成立** —— 实测 VAD 在带 BGM 时拿 **8/9 段**
  （不是"完全相同"，而是"丢 1 段 / 少 2.8s"）。checklist 原来写的是"完全相同"，
  那个**过于绝对** ✗ —— 按实测改判为"**8/9，且可被分离补回**" ✓
- **`--dry-run` 不产出视频** ✓、**切段/剪点升序不重叠** ✓（沿用既有实现，已验）

### **明确不做**（已验证可行，但不接入）

**人声分离（ONNX，107MB）** —— 已验证到"可用"程度：

| 验的东西 | 结果 |
|---|---|
| 手写 ONNX 实现 vs UVR 官方 | **逐点 1dB 以内** ✓ |
| 速度 | **0.46x 实时**（32s 素材 15s）✓ |
| 依赖体积 | `onnxruntime` 43.9MB + 模型 63MB = **107MB**（无 torch）✓ |
| 补回停顿 | 8/9 → **9/9**（9.85s → 12.39s，恢复 98%）✓ |

**为什么不接入**：VAD 单独就拿到 8/9 ✓，分离只补最后那 1 段 / 2.8s ✓，
而代价是 **+107MB 依赖 + 一个模型下载链路（HF 被墙，要走代理）+ 一段不短的接入工作** ✓。
投入产出比不划算 ✓ —— **先把 VAD 这条零成本的拿到手** ✓，分离留作后续按需接入 ✓。

> 实验脚本 `.workbuddy-ai/mdx_sep.py`（约 90 行）与验证记录都留着 ✓ ——
> 将来要接，从它开始，不用重新摸一遍 ✓。

### 环境

开发期为对拍装的 **torch 2.14.1+cpu（512MB）已卸** ✓，发布版依赖维持 107MB 的 onnxruntime ✓。

### 仍未做（如实列）

- 分离接入主流程（模型自动拉取 + 代理兜底 + 结果落盘复用）
- `pick_bed_clip` / 铺伴奏（依赖分离，故随之一并后置）
- 「同一素材有无 BGM 结果**完全相同**」这条原始断言**不成立** ✗ —— 实测是 8/9，已改判

## 收口（2026-10-17）—— 已做的、有 bug 的、后置的

### 已验 ✓
- **找停顿走 VAD**：带 BGM **0 段 → 8 段**（决定性对照）
- **兜底并标记**：VAD 不可用 → 音量门限，`source` 字段 + 报告写明
- **`bgm_aware` 开关**：关掉回旧行为
- **`pick_bed_clip` 逻辑**：窗口不够长返回 `None` ✓、空列表返回 `None` ✓（"不硬凑"这条是对的）

### **有 bug** ✗（如实记，不假装它好）
`detect_bgm` 在**带 BGM** 的素材上 `quiet_level_db=None` ✗ → 于是 `has_bgm=False` ✗
（**应该是 True**）。而**干净**素材上它是对的（-91.0dB ✓ → False ✓）。

推测：`mean_volume_db` 那段窗口的 ffmpeg 调用失败了（返回 None 而不是报错）——
它被 `except` 吞掉了，所以**错得无声**。这正是"静默降级"那类问题。

**影响**：`has_bgm` 现在**不可信** ✗ → 报告里"有没有 BGM"这一项会误导。
但它**不影响找停顿**（停顿走 VAD，不依赖 `has_bgm`）✓ —— 所以没堵住主路径。

### 后置 ✗（随人声分离一并，已明确不做）
- T4 抽伴奏（除"不硬凑"那两条外）：需要"无人声窗口"，而 BGM 下窗口普遍 < 2s
- T5 铺伴奏（循环 + 交叉淡化 + 混音）：依赖 T4
- T7 两段式里的"BGM 怎么处理 + 循环几次"：依赖 T4/T5
- T8 端到端（BGM 连续 / 接缝无爆音）：依赖 T5
- T9 的部分文档项：随分离一并

**理由见 spec 末尾**：VAD 单独就拿到 8/9，分离只补最后 1 段/2.8s，
而代价是 +107MB 依赖 + 模型下载链路 —— 不划算，故整条线后置。

## `detect_bgm` 静默 bug：修了，但**判据仍未标定**（2026-10-17）

### 根因（找到了）
调用方给的 `total`（32.16s）比**文件实际长度**（30.34s）长 ✗ → 最后一个"无人声窗口"
超出文件末尾 → ffmpeg 打出 `n_samples: 0` 且**没有** `mean_volume` 行
→ `mean_volume_db` **静默返回 None** ✗ → `None > 阈值` 恒为 False → **错得无声** ✗。

> 附带纠正一个**我自己的错误结论** ✗：早先我说"干净素材 → -91.0dB → 无 BGM ✓"，
> 那个 -91dB 测的是**超出文件末尾**的窗口（空样本）✗，**不是真静音**。

### 修了三件事
1. **窗口按文件实际长度夹紧** ✓（`audio_duration_sec()`）
2. **`mean_volume_db` 遇到 `n_samples: 0` 明确抛错** ✓，不再静默返回 None
3. **`has_bgm` 改三态** ✓：`True` / `False` / **`None`（测不出来）** ——
   "测不出来" ≠ "没有 BGM"，混成一个 False 会让报告骗人

### 但判据本身**没标定** ✗（如实说）
原来的绝对门限（-45dB）判不出区别：干净素材的无人声窗口实测 **-30.0dB**、
人声 **-22.8dB**（只差 **7.2dB**，因为合成音有底噪）；带 BGM 的是 **-26.3 / -29.2**（差 **-2.9dB**）。

已改成**对比度**判据（`DEFAULT_BGM_CONTRAST_DB = 15.0`）—— 信号确实分开了
（-2.9 vs +7.2），但**这份合成素材标不出合适的门限** ✗：
合成音的"干净"基线本身只有 7.2dB，而真实口播的干净基线应是 40dB+。

**结论**：判据方向是对的 ✓，**门限必须在真实素材上标定** ✗。
我**没有**把门限调到"刚好让这两条过"（那是过拟合 ✗）。

### 影响
`has_bgm` 仍**不可全信** ✗；但它**不影响找停顿**（停顿走 VAD，不依赖 `has_bgm`）✓ ——
主路径没被堵。

## 本轮验收（2026-10-30）：24 条里 **17 条验掉**，7 条**按 spec 后置**

> 这一轮的判据是「能验的验掉、验不了的**写清为什么**」，不是"凑满"。
> 后置的 7 条全部依赖**铺伴奏（T5）**，而它依赖**人声分离（+107MB）**——
> 按 ADR-026 明确不接入。

### 顺带修掉 2 个缺陷

**① 纯 BGM 素材会被剪成 0.16s**（12.00s → 0.16s，省 98.7%）✗✗
VAD 找到 **0 个语音窗口** → `pauses_between` 把"整条"当成一个停顿 → **全剪** ✗。
"没找到人说话"不等于"全是废话"。**修法**：一个语音窗口都没有 → **不剪**，
并明确报「没检测到任何语音（整条都没有人声？）→ **不剪**，原样保留」✓。

**② `mean_volume_db` 的 `-t` 位置不对**（`has_bgm` 因此判错）
`-t` 放在 `-i` **之后**（输出选项）在本机**会被忽略** ✗ ——
量 (0,2) 这段静音拿到 **-24.9dB**（= 整条 4s 的平均），而量 (0,1) 又是对的 -91.0 ✗（时灵时不灵）。
后果：`detect_bgm` 的"无人声窗口音量"量到了更长的一段 → 对比度被稀释 → `has_bgm` 判错，
**而且错得无声** ✗。**修法**：`-t` 移到 `-i` **之前**（输入选项）✓。
这也解释了文档里那句"判据仍未标定"的一部分原因 —— 测量本身就偏了。

两处都补了测试（`test_bgm.py` 从 **0 条**到 **11 条** —— 这个模块原先**没有任何测试** ✗），
三条变异（`-t` 位置 / 硬凑窗口 / 静默降级）**全部变红** ✓，均已还原。
