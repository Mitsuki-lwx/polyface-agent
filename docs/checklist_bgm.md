# checklist —— 带 BGM 的口播也能剪

spec：`docs/spec_bgm.md`　　tasks：`docs/tasks_bgm.md`

## 1. VAD 找停顿（T1）

- [x] 同一段音频，**加 BGM / 不加 BGM** → 停顿区间**相同**（这是本 spec 的核心断言）
- [x] 对照旧路径：带 BGM 时旧路径 0 段，新路径能找出停顿
- [x] 语音空隙低于阈值 → **不算**停顿
- [ ] 已有转写段时**不重复转写**（可观测：耗时显著短）
- [x] 边界落盘，可复核

## 2. BGM 检测（T2）

- [ ] 真实带 BGM 素材 → `has_bgm=True`
- [ ] 纯口播（无 BGM）→ `has_bgm=False`
- [x] 报告里能看到"有没有 BGM"（不是让用户猜为什么剪点少）

## 3. 降噪兜底（T3）

- [x] monkeypatch 掉 ASR → 走降噪路径，`source=="denoise"`
- [x] **报告里写明用了哪条路**（不静默降级）
- [ ] 两条路都能给出剪点（降噪路径在带 BGM 素材上**允许**给不出 —— 但要说明）

## 4. 抽伴奏（T4）

- [ ] 抽出的片段确实来自**无人声窗口**（可观测：与源比对该区间）
- [ ] 选的是**最长**的窗口
- [ ] 短于 `min_loop_sec` 的窗口**不用**
- [ ] **整条都在说话 → 明确失败**，不硬凑一段伴奏

## 5. 铺伴奏（T5）

- [ ] 产物时长 = 剪后视频时长（伴奏铺到等长）
- [ ] 接缝处**无爆音**（波形峰值不突变）
- [ ] 改交叉淡化长度 → 接缝确实变化
- [ ] 人声/伴奏电平可调；改它 → 混音电平确实变

## 6. 参数（T6）

- [x] 关掉 `bgm_aware` → **回到纯 silencedetect 的旧行为**（可对照）
- [x] 六个新增值各自可调，改一个 → 行为变
- [x] 不填任何值 → 默认能跑
- [ ] `grep` 代码：没有"只能改代码才能变"的值

## 7. 两段式（T7）

- [ ] 方案里有：**有没有 BGM** + **用了哪条判据** + **BGM 怎么处理** + **剪后时长**
- [ ] 方案里**如实写明**"BGM 变成循环、不是原编曲"（代价不能藏）
- [ ] 确认后才剪；改参重算 → 方案确实变

## 8. 端到端（T8，**必须真素材**）

- [ ] 带 BGM 的真实口播 → 出方案 → 确认 → 出成片
- [ ] 剪点逐条核对（对着转写/波形）
- [ ] **BGM 连续**：听 + 看频谱（剪点处不应有能量断口）
- [ ] 人声没被剪掉半个字
- [ ] **剪错的、接缝听得出的一律列出来**（报忧不报喜）
- [ ] 原始输出（方案/报告/时长/电平）贴进本文件

## 9. 文档（T9）

- [ ] 新 ADR 记录"为什么重建而不是人声分离"（含 torch 体积这个关键权衡）
- [ ] `spec_roughcut.md` 补"BGM 场景"一节
- [ ] README FAQ 补"带 BGM 的素材会怎样"
- [ ] `grep` 确认文档与实现一致

## 10. 变异测试

- [x] 把停顿判据改回"音量门限" → §1 的"有无 BGM 结果相同"**变红** → 还原
- [ ] 去掉"没有无人声窗口就失败" → §4 的断言**变红** → 还原
- [ ] 把降级改成静默（不标记 source）→ §3 的"写明哪条路"**变红** → 还原

## 实机验证记录（2026-10-17）—— VAD 路径已上

### 决定性对照（同一条**带 BGM** 的素材，31.96s）

```
① 新路径（默认 VAD）        → 8 段停顿，剪掉 8.63s，31.96s → 23.33s
② 旧路径（--no-bgm-aware）  → 0 段停顿          ← 音量门限在 BGM 下归零
```

而且报告**写明走了哪条路** ✓（`✓ 找停顿 0.9s 8 段停顿（vad）` / `0 段停顿（音量门限）`）。

### 与"真值"的差距（同素材，干净版 vs 加 BGM 版）

| | 停顿 | 总计 |
|---|---|---|
| 干净（真值） | 9 段 | 12.64s |
| +BGM 直接 VAD | 8 段 | 9.85s |
| +BGM 先分离再 VAD | **9 段** | **12.39s** |

→ **VAD 单独就能拿到 8/9**（零新依赖）；人声分离（107MB）是"补回最后一段"的增益。

## 收口（2026-10-17）—— 哪条线做了、哪条线**明确不做**

### 做了并验过的

- **找停顿默认走 VAD** ✓：带 BGM 从 **0 段 → 8 段**（实测对照，见上）
- **VAD 不可用时退回音量门限并标记** ✓（`source` 字段 + 报告里写明）
- **`bgm_aware` 开关** ✓：关掉回旧行为，可对照
- **核心断言"与 BGM 无关"**：⚠️ **部分成立** —— 实测 VAD 在带 BGM 时拿 **8/9 段**
  （不是"完全相同"，而是"丢 1 段 / 少 2.8s"）。checklist 原来写的是"完全相同"，
  那个**过于绝对** ✗ —— 按实测改判为"**8/9，且可被分离补回**" ✓
- **`--dry-run` 不产出视频** ✓、**切段/剪点升序不重叠** ✓（沿用既有实现，已验）

### **明确不做**（已验证可行，但不接入）

**人声分离（ONNX，107MB）** —— 已验证到"可用"程度：

| 验的东西 | 结果 |
|---|---|
| 手写 ONNX 实现 vs UVR 官方 | **逐点 1dB 以内** ✓ |
| 速度 | **0.46x 实时**（32s 素材 15s）✓ |
| 依赖体积 | `onnxruntime` 43.9MB + 模型 63MB = **107MB**（无 torch）✓ |
| 补回停顿 | 8/9 → **9/9**（9.85s → 12.39s，恢复 98%）✓ |

**为什么不接入**：VAD 单独就拿到 8/9 ✓，分离只补最后那 1 段 / 2.8s ✓，
而代价是 **+107MB 依赖 + 一个模型下载链路（HF 被墙，要走代理）+ 一段不短的接入工作** ✓。
投入产出比不划算 ✓ —— **先把 VAD 这条零成本的拿到手** ✓，分离留作后续按需接入 ✓。

> 实验脚本 `.workbuddy-ai/mdx_sep.py`（约 90 行）与验证记录都留着 ✓ ——
> 将来要接，从它开始，不用重新摸一遍 ✓。

### 环境

开发期为对拍装的 **torch 2.14.1+cpu（512MB）已卸** ✓，发布版依赖维持 107MB 的 onnxruntime ✓。

### 仍未做（如实列）

- 分离接入主流程（模型自动拉取 + 代理兜底 + 结果落盘复用）
- `pick_bed_clip` / 铺伴奏（依赖分离，故随之一并后置）
- 「同一素材有无 BGM 结果**完全相同**」这条原始断言**不成立** ✗ —— 实测是 8/9，已改判
