## T1 · 造一份可复现的测试素材

- **做什么**：用本机 TTS 合成一段中文口播（含**故意插入的长停顿**），配上竖屏画面做成 mp4
- **影响文件**：`.workbuddy-ai/roughcut-lab/`（实验目录，不进仓库）→ 定稿后收进 `scripts/` 作为 fixture 生成器
- **依赖**：无
- **参考资料**：
  - 已跑通的做法：`tts3.ps1` + `script.txt`（**中文必须写成 UTF-8 的 txt 再由脚本显式读**）
  - ⚠️ 坑：PowerShell 5.1 按系统代码页（GBK）读 `.ps1` → 脚本里的中文会变乱码并被念出来
  - 本机可用语音：`Microsoft Huihui Desktop`（zh-CN）
  - 可用字体：`C:/Windows/Fonts/msyh.ttc`（微软雅黑）
- **完成判据**：能一条命令重新生成同一个素材；`ffprobe` 显示的时长与预期一致

## T2 · 前置探测与大声失败

- **做什么**：检查输入文件存在、能被 ffprobe 识别、**有音轨**；缺 ffmpeg / 缺 ASR 时明确报错并给一句怎么修
- **影响文件**：新脚本的入口；复用 `python-service/app/pipeline/media.py`（已有 `has_ffmpeg` / `_ffmpeg_bin` / `probe`）
- **依赖**：无
- **参考资料**：`media.py:38-56`（`_ffmpeg_bin` / `has_ffmpeg`）、`media.py:79-87`（ffprobe 解析）
- **完成判据**：对"不存在的文件""纯图片视频（无音轨）""把 ffmpeg 从 PATH 摘掉"三种输入，各自给出**不同**的明确错误

## T3 · 找停顿

- **做什么**：跑 `silencedetect`，把输出解析成"剪掉哪几段"的列表
- **影响文件**：新模块（建议 `python-service/app/pipeline/roughcut.py`）
- **依赖**：T2
- **参考资料**：
  - 实测命令形态：`ffmpeg -i IN -af silencedetect=noise=-30dB:d=<阈值> -f null -`
  - 输出是 stderr 上的 `silence_start:` / `silence_end:` / `silence_duration:` 文本，需要正则解析
  - **实测结论**：噪声门限 -20~-40dB 几乎不影响结果；**真正敏感的是时长阈值**（0.3s→8 段 / 0.8s→4 段 / 1.0s→3 段）
- **完成判据**：给定素材与阈值，输出稳定可复现的剪点列表；阈值调大时剪点**单调减少**

## T4 · 剪掉停顿

- **做什么**：按剪点生成 ffmpeg 的 `select`/`aselect` 表达式并重编码，产出剪后视频
- **影响文件**：同上模块
- **依赖**：T3
- **参考资料**：
  - 实测可用形态（视频与音频用**同一个**条件表达式，否则音画不同步）：
    `-vf "select='not(<条件>)',setpts=N/FRAME_RATE/TB" -af "aselect='not(<条件>)',asetpts=N/SR/TB"`
  - 条件由若干 `between(t,起,止)` 用 `+` 连接
  - 剪点两端各留一点余量，否则切得太生硬（余量值见 checklist）
- **完成判据**：剪后视频时长 = 原时长 − 剪掉的静音时长（误差在帧级）；播放时**音画同步**

## T5 · 转写（补"要时间戳"的入口）

- **做什么**：对**剪后**的视频做本地转写，拿到带起止时间的片段
- **影响文件**：`python-service/app/pipeline/asr.py`（新增入口，**不动**现有 `transcribe()`）
- **依赖**：T4
- **参考资料**：
  - 现有 `asr.py:44-46` 的模型加载（进程内缓存）与 `asr.py:50-57` 的 `transcribe()`
  - `faster_whisper` 的 `segments` 每项带 `.start` / `.end` / `.text`（现有实现把它们拼成纯文本丢掉了时间）
  - ⚠️ **实测坑**：`faster-whisper 1.2.1` 与 `av 19` 不兼容（`av.open()` 已不接受 `metadata_errors`），
    走"传文件路径"会在解码阶段直接抛 `TypeError`。**绕开办法：自己用 ffmpeg 解成 16k 单声道，
    再用标准库读成 float32 数组传进去**（传数组时不会走 PyAV 解码路径）
- **完成判据**：对测试素材转写出的文本与台词一致（人名同音错可接受）；片段带正确起止时间

## T6 · 生成字幕文件

- **做什么**：把带时间戳的片段写成标准字幕文件
- **影响文件**：同上模块
- **依赖**：T5
- **参考资料**：项目已有字幕**解析**能力（`media.py` 的 `srt_to_text`），本任务是它的反向
- **完成判据**：产物能被 ffmpeg 的 `subtitles` 滤镜直接读取；时间戳格式合法

## T7 · 烧字幕

- **做什么**：把字幕渲染进画面
- **影响文件**：同上模块
- **依赖**：T6
- **参考资料**：
  - 实测可用形态：`-vf "subtitles=<srt>:force_style='...'"`（本机 ffmpeg 带 libass）
  - 中文字体必须显式指定，否则可能渲染成方块（本机可用 `Microsoft YaHei`）
  - 实测样式：白字 + 黑描边 + 底部居中，竖屏下渲染正确
- **完成判据**：抽一帧能看到**正确的中文字幕**（不是方块、不是乱码、位置不压边）

## T8 · "剪了什么"摘要

- **做什么**：打印剪点摘要（段数 / 每段起止 / 剪掉总秒数 / 剪后时长），并落一份机器可读的剪点文件
- **影响文件**：同上模块
- **依赖**：T4
- **参考资料**：无
- **完成判据**：摘要里的数字与 `ffprobe` 实测的剪后时长**对得上**

## T9 · 接入主流程（**必须有**）

- **做什么**：一个命令行入口，把 T2→T8 串成一条命令；参数可调（输入/输出/停顿阈值/字幕开关）
- **影响文件**：`scripts/roughcut.py`（新）
- **依赖**：T2–T8
- **参考资料**：项目既有脚本风格 `scripts/probe_llm.py`、`scripts/e2e_fr51.py`
- **完成判据**：一条命令从原始视频跑到成片；调阈值能明显改变输出时长

## T10 · 端到端验证（**必须有**）

- **做什么**：用 T1 的素材跑完整链路，逐条对 `checklist_roughcut.md`
- **影响文件**：`scripts/e2e_roughcut.py`（新）
- **依赖**：T9
- **参考资料**：项目既有 e2e 脚本风格 `scripts/e2e_assets.py`、`scripts/e2e_fr51.py`
- **完成判据**：
  - 剪后时长确实变短，且与摘要自洽
  - 抽帧能看到中文字幕
  - 独立字幕文件存在且非空
  - **变异测试至少 1 次**：故意把剪点表达式改坏 → 确认 e2e 变红 → 还原
