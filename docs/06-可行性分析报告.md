## 2. 技术可行性

### 2.1 评估
| 技术点 | 选型 | 成熟度 | 说明 |
|---|---|---|---|
| 业务后端 | Java 21 + Spring Boot 3.3.5 | 高 | 团队熟悉的栈；长生命周期易维护 |
| LLM 服务 | Python 3.13 + FastAPI | 高 | LLM 生态最成熟的运行时 |
| LLM 接口 | OpenAI 兼容 / SenseNova | 高 | 适配层已建，可切任意兼容服务 |
| 本地存储 | SQLite（sqlite-jdbc） | 高 | 单机单用户零运维；M2 已跑通 |
| 平台规则 | YAML 平台 DNA + 自研引擎 | 中高 | 不依赖第三方运营知识接口 |
| 前端 | React（M3） | 高 | 待开发 |

### 2.2 已实证（M1/M2 交付）
- Python 10 项测试、Java 测试全绿；
- 端到端：素材 → 小红书成稿（qa_passed）→ SQLite 落库 ✅；
- 关键技术坑已排除：Java↔Python 需强制 HTTP/1.1（避免 h2c 握手失败）、
  SQLite 多语句建表需逐条执行。

### 2.3 主要技术风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| LLM 输出不稳定/平台规则覆盖不全 | 稿件质量波动 | brief/draft 分阶段可控；qa 自评+重写；人工终审 |
| 商汤模型个别任务表现波动 | 生成质量 | 模型可切换（DeepSeek/通义/OpenAI 兼容） |
| 5 平台规则维护量大 | 出稿质量不齐 | 平台 DNA 文件化、分批补齐、社区可贡献（开源后） |

### 2.4 AI 剪辑能力补充评估（2026-09-09 决策：A→C→B 分期）
| 能力 | 技术评估 | 依赖 | 可行性 |
|---|---|---|---|
| A 剪辑单（分镜/字幕断句/BGM 建议） | 纯 LLM 文本结构化输出，复用现有管线 | 无新增 | ✅ 高（随 M3 交付） |
| C 视频/音频→文字入料 | 语音转写（Whisper 类/厂商 ASR）本地或 API | 转写引擎 | ✅ 中高（M3.5） |
| B 本地自动成片 | 素材拼合/字幕烧录/TTS 均为成熟开源方案 | ffmpeg（用户机器已装）+ TTS | ✅ 中（M5+ 专项，需排期测试） |
> 合规延续：产物仅本地生成，不自动上传（ADR-010/013）。B 引入 ffmpeg 后需补充长视频稳定性测试。

## 3. 经济可行性

| 成本项 | 评估 |
|---|---|
| 服务器/云 | 0 元——本地运行，无需云端部署（分发走 GitHub Releases） |
| LLM token | 按量付费：单次多平台改写预估数千~2 万 token，单价低（SenseNova/DeepSeek 级别 ≈ 元级/百万 token）；个人周更量级成本可忽略 |
| 开发成本 | 单人 + AI 辅助，核心链路已由 M1/M2 验证，剩余以 UI 为主 |
| 商业化路径（远期） | 开源（MIT）+ 可选 Pro（DNA 库/复盘增值）；本阶段以作品与自用为主 |

> 结论：**个人可承受、无重资产门槛**。唯一持续成本是用户自带的 LLM Key 消耗。

## 4. 市场与需求可行性

### 4.1 需求真实性（竞品快研，详见 docs/02 §1）
- 2025 年起多篇运营测评反复印证痛点：多平台运营"格式错乱、文案同质、被限流"；
- 现有工具两极：分发工具（蚁小二/易媒/融媒宝）不解决"内容质量/调性"；
  AI 文案工具（红抖/笔尖AI 等）无创作者记忆、多为矩阵搬运场景；
- **空位**：平台调性感知 + 创作者记忆 + 本地数据主权 + 合规叙事的个人创作工具。

### 4.2 目标市场规模（定性）
- 自媒体从业者/副业博主基数大且持续增长（各平台创作者激励计划推动）；
- "个人下载即用"工具接受度高（本地工具 + 自带 Key = 无隐私顾虑）。

### 4.3 风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| 同质工具增多 | 中 | 差异化在 DNA 库+复盘记忆+本地化，非一次性生成 |
| 未验证真实付费意愿 | 中 | 先开源获取用户反馈，再决定增值路径 |
| 平台规则快速变化 | 中 | DNA 文件可升级；由效果复盘驱动调参 |

## 6. 法律与合规可行性

| 事项 | 评估 | 内建对策 |
|---|---|---|
| 素材版权 | 只处理用户自有/授权素材 | README 免责声明 + 产品定位"自有素材再利用" |
| AI 内容规范 | 各平台对 AI 内容要求趋严 | 建议稿由用户自查后发布；不做自动发布 |
| 平台条款 | 自动化发布/批量搬运有封号与违约风险 | **红线：不提供自动发布**；只产文本建议稿 |
| 爬虫/数据抓取 | 平台数据抓取合规风险高 | 不内置热点抓取；热点由用户手动输入 |
| 开源许可证 | 需要无争议 | MIT；平台 DNA 全部自研整理，规避内容侵权 |
| 隐私 | 素材含个人/商业信息 | 本地存储 + 自带 Key，数据不经过任何第三方服务器 |

> 结论：**合规边界已写入产品架构**（见 08 ADR-006/ADR-010），可行性高。

---

## 7. 综合结论与前置条件

**结论：项目可行，建议继续按 M3→M4→M5 推进。**

关键前置条件（需用户确认）：
1. **LLM Key**：提供 SenseNova 或其它 OpenAI 兼容 Key（用于真实模式质量验证）；
2. **平台规则源**：认可"平台 DNA 由项目自研整理"的知识生产方式；
3. **目标场景**：优先"个人博主/迁移作者"，而非企业级矩阵运营。

> 若目标包含参赛：本报告 + SRS + 用例验收 + ADR 共同构成完整技术文档包。
