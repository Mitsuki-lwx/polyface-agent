# spec —— 按场景切段：一条长录像 → N 条能各自发的素材

版本：2026-10-17　　对应 tasks：`docs/tasks_scene_split.md`　　验收：`docs/checklist_scene_split.md`

---

## 1. 背景

B2 的另一块缺口（ADR-022）。现有的「素材拆分」是按**选题**拆（LLM 看文本），
但真实素材常常是**一条长录像里拍了好几个场景** —— 不同地点、不同话题、不同机位。

这类素材现在的处理方式是：人把它拖进剪辑软件，自己找切点，导出 N 个文件，再一个个喂进工具。
**这正是该交给程序做的**：切点规则明确（画面变了），错了肉眼可见。

现状：全仓**没有**任何画面切点检测（只有 B1 的"按脚本分镜"，那是另一回事）。

---

## 2. 目标用户

**现阶段只有作者本人**（沿用粗剪/去冗余的定位）。会拍 vlog / 教程 / 多场景长录像的人。

---

## 3. 能力清单（一句话一条）

1. 给一个本机视频，找出**画面切点**（换景/换机位/插入 B-roll）
2. 切点要**吸附到语音边界** —— 画面切了但话没说完时，不许把一句话切成两半
3. 切出来的段**能各自去走完整管线**（→ 去停顿/字幕 → 多平台稿 → 成片）
4. **最短时长可改**，低于它的段**并入前一段**（不丢内容）
5. **两段式**：先给出"打算切成哪 N 段"（每段起止、时长、缩略图），
   **你勾选确认后**才真的切
6. 每一段都要能说出**它从哪来**（原始文件的起止时间），可回溯
7. 检测灵敏度**可改**（不同素材的"画面变了"差别很大：静态口播 vs 快速运动）
8. 语音边界拿不到时（无音轨 / 缺 ASR）→ **降级为纯画面切点并明确告知**，
   不是静默少做一步
9. 缺 PySceneDetect 时**大声失败**（说明怎么装），不静默产出空结果

---

## 4. 非功能要求

- **全程本地**（沿用 ADR-017）
- **确定性**：同一输入 + 同一参数 → 同样的切点（检测器不引入随机性）
- **可单独重跑**：检测结果落盘，调阈值不必重新解码整条视频
- **不重编码源视频**：切段是 ffmpeg 的流复制/单次编码，源文件不动
- **速度**：10 分钟素材的**检测**应在分钟内完成（PySceneDetect 默认用降采样检测）

---

## 5. 设计骨架

```
探测 → 检测画面切点（PySceneDetect）→ 取语音边界（复用 ASR 的转写）
     → 切点吸附到最近语音边界 → 按最短时长合并 → 【给你看：N 段 + 缩略图】
     → 你勾选 → 切出 N 个文件 → 每段登记成素材
```

### 关键决定一：**吸附到语音边界**（用户选）

画面切点落在**说话中间**是常态（镜头切了但话没说完）。直接按画面切，
切出来的段开头会缺半句话 —— 一段素材如果开头就是半句，它**不能发**。

所以：先用 ASR 拿到语音边界，把每个画面切点**吸附到最近的语音边界**。
代价是多一遍 ASR（与去冗余一样，可以复用同一遍转写）。

### 关键决定二：**短段并入前一段，不是丢掉**（用户选）

低于最短时长的段**并进前一段**。理由：丢掉是**有损**的 ——
用户可能正是想要那个 3 秒的空镜。并进去最多让前一段长一点，可逆（还能再切）。

### 关键决定三：**两段式，勾选后才切**（用户选）

检测结果先给人看（每段起止 + 时长 + **缩略图**），人勾了才切。
理由：切点是**审美判断**（"这里算不算新场景"因人而异），程序只负责把候选摆出来。
缩略图是必要的 —— 只有时间戳的话，人根本认不出哪段是哪段。

### 关键决定四：**切出来的是原始段，不是加工过的**

每段是**原封不动的一段**（未去停顿、未加字幕）。用户可以只挑其中几段去跑粗剪。
理由：加工是**另一条管线**（要 ASR、要人确认），把两者捆在一起会让"只想看看切得对不对"
变成"必须等 N 遍加工跑完"。

### 其它骨架决定

- **PySceneDetect 是可选依赖**（沿用 librosa/faster-whisper 同一条路）：没装则明确报错 + 安装指引
- 检测结果**落盘**（切点、参数、检测器版本）—— 可复核、可调参重跑
- 段的时间戳**一律取自程序**（不取检测器或模型的自由文本）
- 源视频**不动**；产出新文件，血缘挂回源资产

---

## 6. Out of Scope（本版不做）

- **不做镜头内容的语义理解**（"这一段在讲什么"）—— 那是理解管线的活
- **不做自动挑选"哪几段值得发"**（人勾，程序不替人决定）
- **不做跨视频的合并**
- **不做画面质量筛选**（模糊/曝光问题不判）
- **不改粗剪/去冗余**，只做"多一个上游入口"

---

## 7. 已知风险

| 风险 | 应对 |
|---|---|
| 快速运动/闪光造成误报（切成碎片） | 最短时长 + 并入前一段 + 灵敏度可调 + 两段式让人拦下 |
| 语音边界本身不准（转写误差） | 吸附时留余量（沿用粗剪的剪点余量思路） |
| 一条长录像切出几十段，看着累 | 报告按时间排列 + 带缩略图 + 时长；勾选支持全选/全不选 |
| 切段后每段都要跑粗剪，耗时 N 倍 | 切与加工**分开**（本版只切）；加工由用户按需触发 |
| 新依赖进发布包 | 写进打包清单 + 缺依赖时的错误要能指导安装 |
