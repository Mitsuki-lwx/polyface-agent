## 1. 默认值表（**每一项都必须能被覆盖**）

| 参数 | 默认值 | 依据 |
|---|---|---|
| 单次调用预算 | **沿用 `polyface.llm.timeout-sec`（240s）** | 拆成按平台后每次调用都落在它之内；不为异步单独发明一个预算 |
| 轮询间隔 | **1s** | 与粗剪任务一致 |
| 任务保留 | **沿用 `polyface.roughcut.keep-jobs`（50）** | 同一张 job 表，不分两套 |
| 卡死判定 | **沿用 `polyface.roughcut.stall-sec`（300s）** | 同上；LLM 单次最长 250s，留足余量 |
| 任务边界 | **一次生成请求 = 一个任务**（可含多平台） | 与既有 API 形状一致 |
| 失败平台重试 | **新建任务**，不改原任务记录 | 否则"上次跑了什么"就查不到了 |

## 本轮的设计取舍（值得记下来）

1. **加了第 6 个状态 `partial`**。原 spec 写的是 5 个状态，但"3 个平台成 2 个"**没法用 5 个状态表达**：
   记 `succeeded` 会把失败藏起来，记 `failed` 又抹掉"已产出 2 篇"。已同步改 `docs/spec_roughcut_jobs.md`。
2. **"理解只跑一次"靠 `ensureFacts` 返回事实，不是靠"复用已确认事实的捷径"** ——
   这是变异测试逼出来的理解：先改捷径抓不住，因为没确认过的素材本来就要先理解一次。
3. **同步端点保留**，但已注明归属：工作台只走任务；端点留给 API 调用方，
   且**与任务共用 `GenerateService`**（组装请求体 + 落库各只有一份）。
