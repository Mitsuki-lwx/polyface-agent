# checklist —— 生成任务异步化：复用任务底座（M8 第二片）

对 `docs/spec_async_generate.md` 的可勾选验收。**一行一条，可独立判定。**

> 状态：**未开工**（本文件先于实现写，验收时逐条勾）

---

## 1. 默认值表（**每一项都必须能被覆盖**）

| 参数 | 默认值 | 依据 |
|---|---|---|
| 单次调用预算 | **沿用 `polyface.llm.timeout-sec`（240s）** | 拆成按平台后每次调用都该落在它之内；不为异步单独发明一个预算 |
| 轮询间隔 | **1s** | 与粗剪任务一致 |
| 任务保留 | **沿用 `polyface.roughcut.keep-jobs`（50）** | 同一张 job 表，不分两套 |
| 卡死判定 | **沿用 `polyface.roughcut.stall-sec`（300s）** | 同上；LLM 单次最长 250s，留足余量 |
| 任务边界 | **一次生成请求 = 一个任务**（可含多平台） | 与既有 API 形状一致 |
| 失败平台重试 | **新建任务**，不改原任务记录 | 否则"上次跑了什么"就查不到了 |

## 2. 阶段事件（Python 侧）

- [ ] 传了事件路径 → 该文件里出现阶段事件（理解 / 每平台 策略→成稿→质检）
- [ ] **不传路径 → 不创建任何文件**（向后兼容既有调用）
- [ ] 事件里**不含素材正文/成稿正文**（沿用脱敏原则）
- [ ] 事件写不进去（目录不可写）→ **生成照常完成**，只告警
- [ ] 事件 schema 与既有底座**同一个 version**（不新造一套格式）

## 3. 编排（Java 侧）

- [ ] 一个 3 平台任务里，**理解阶段只发生一次**
- [ ] 每个平台**各一次** `/generate` 调用
- [ ] 任一平台失败 → **其他平台的成果保留**（不因一个失败丢掉全部）
- [ ] 每次调用都落在既有单次预算内（不再出现"多平台累加成一个超长调用"）
- [ ] 任务终态能区分：全成功 / 部分失败 / 全失败 / 已取消

## 4. 进度

- [ ] 能报出**平台级**进度（"第 n/m 个平台"）
- [ ] 能报出**阶段级**进度（当前平台走到哪一步）
- [ ] 事件文件里 Java 与 Python 两边写的行**都能被解析**
- [ ] 事件文件被写坏（半行/交错）时**不崩**，只是进度缺失
- [ ] 任务结束后进度**不再变化**（不会停在一个假的中间态）

## 5. 失败与重试

- [ ] 失败平台在任务详情里**带可读原因**（哪个平台、哪一步、为什么）
- [ ] **重试只跑失败的平台**，已成功的**不重跑**（用调用次数证明）
- [ ] 重试**新建任务**，原任务的记录与结果**不被改动**
- [ ] 全部成功的任务**没有**重试入口（或点了明确告知"没有失败的平台"）

## 6. 产物与稿件

- [ ] 成功的平台 → 草稿**进既有稿件体系**（能在稿件页看到）
- [ ] 失败的平台 → **不产草稿**，但任务详情里有原因
- [ ] 任务详情能跳到对应稿件（不是只给个 id）
- [ ] 落库逻辑**只有一份**（不是从既有控制器复制出来的第二套）

## 7. 前端

- [ ] 生成按钮改为**发起任务**，不再同步等待
- [ ] 进度显示"第 n/m 个平台 · 当前阶段"
- [ ] 失败平台有**重试**按钮，点了能重跑且进度重新开始
- [ ] 任务结束后**轮询停止**
- [ ] **不使用 `alert()`**
- [ ] 发起后**可以立刻做别的事**（不阻塞界面）

## 8. 端到端（**至少一条**）

- [ ] 3 平台任务：进度可见 → 3 篇稿件落库 → 终态正确（**含截图**）
- [ ] 构造一个平台失败 → 其他平台成果保留 + 任务标为部分失败 + 重试只跑失败那个
- [ ] **事件文件里"理解"只出现一次**（数出来）
- [ ] 旧路径清理：工作台只有一条生成路径（或旧端点有明确归属说明）
- [ ] 全程**不出网**（mock 模式）

## 9. 变异测试（至少 1 次）

- [ ] 故意把"理解只跑一次"改成"每平台都跑一次" → 确认 e2e **变红** → 还原 → 复绿
- [ ] 故意让"重试"变成"重跑全部平台" → 确认"重试只跑失败平台"那条**变红** → 还原
- [ ] 记录变异前后的实际数字
