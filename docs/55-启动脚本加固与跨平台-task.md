# 启动脚本加固与跨平台补齐 — task

日期：2026-09-19 · 前置：`docs/23-25`（M5 打包，已交付）· 关联：`docs/48` §6 残余项、`docs/25` D9、`docs/07` M5 行

---

## 1. 起因

`docs/48` §6 把交付时**最该补的一块**列在最前面：

> `scripts/*.bat` 本身 —— ⚠️ **仍未实机执行**。两处工具都硬性拦截 `cmd.exe`，
> 本环境**不可能**执行批处理。已消除行尾符与中文编码两类隐患，
> 剩余风险收窄为"**批处理语法/取词的个别写法**"。

以及 `docs/25` 的 D9 未勾选：

> [ ] D9 有 `.sh` 版本（macOS/Linux）—— **未完成**。仅有既有的 `start.sh` / `mvn.sh`。

两条合起来是同一件事：**启动脚本是发布包里唯一没有测试覆盖的部分。**

## 2. 为什么必须做（不是"锦上添花"）

1. **`.bat` 无法执行 ≠ 无法验证。** 现在的处境是"只能靠人逐行看"，
   而 `docs/48` §5 第 8 项已经证明过：**逐行复核看不出行尾符问题**。
   人眼对"语法/取词"这类错误的检出率同样低 —— 需要**程序化的静态校验**，
   把能机械判定的东西（行尾符、标签引用、括号配平、引号配对、硬编码路径）交给机器。

2. **`.sh` 在本环境能真跑。** 跨平台这条残余项目前是"写了 POSIX 分支但未实测"
   —— 而 `bash` 就在手边。这是**可以把"未验证"变成"已验证"**的机会，
   不应该继续挂在残余项里。

3. **`start.sh` 已经与 `start.bat` 脱节。** 现状：

   | 项 | `start.bat`（M5 后） | `start.sh`（09-09 旧版） |
   |---|---|---|
   | Java 启动 | `java -jar polyface.jar` | `mvn spring-boot:run`（运行时依赖 Maven） |
   | 数据目录 | 显式 `POLYFACE_DATA_DIR=<包根>/data` | **未设置** → 数据写到 `../data`（包外） |
   | 就绪判断 | 分别轮询 8000 / 8080 | `sleep 8` 固定等待 |
   | 打开页面 | `/`（应用首页） | `/health` |
   | 体检 | 先跑 `doctor.py` | 无 |

   也就是说：**macOS/Linux 用户按 README 走会得到与 Windows 用户不同的行为**，
   而且数据会落到包外。这不是"没做"，是"做错了"。

## 3. 目标

1. 给 `scripts/*.bat` 与 `scripts/*.sh` 建立**可自动执行**的静态校验（进入 CI 级测试）。
2. 补齐 `setup.sh` / `stop.sh`，重写 `start.sh`，使其行为与 `.bat` 版本**逐项对齐**。
3. 在本环境**实机运行** `.sh` 全流程，给跨平台补上真实证据（而不是再写一句"未验证"）。

## 4. 边界

**In**
- 新增 `scripts/check_scripts.py`：静态校验器（纯标准库，可测）
- 新增 `python-service/tests/test_check_scripts.py`
- 新增 `scripts/setup.sh`、`scripts/stop.sh`；重写 `scripts/start.sh`
- 在本环境实机验证 `.sh`：setup（建 venv + 装依赖 + 生成 .env）→ start → 就绪 → 生成一条稿 → stop
- 更新 `docs/25` D9、`docs/48` §6 的对应行

**Out**
- **不试图执行 `.bat`** —— 环境硬性拦截，且这是工具限制而非代码问题。
  静态校验是"降低风险"，不是"等价于实机验证"，交付说明里必须写清这个区别。
- 不改 `.bat` 的功能行为（已按 `docs/23` v1.1 定稿）；仅修校验器**确实检出**的问题
- 不做安装器 / 自动更新 / 跨系统打包（`docs/23` 已明确排除）
- 不引入 shellcheck 等外部依赖（本环境不一定有，且要能离线跑）

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 静态校验器误报，逼着改正确的代码 | 每条规则都要有"正例 + 反例"测试；规则若无法在现有脚本上零误报，**降级为警告而非失败** |
| 校验器自身有 bug，反而给出虚假安全感 | 对校验器本身做**变异测试**（故意改坏脚本 → 确认报错） |
| `.sh` 在本环境跑通 ≠ 在 macOS 跑通 | 交付说明中如实标注：验证环境是 Git Bash（Windows 上的 bash），**不是**真 macOS/Linux；`lsof` 分支仍未实测 |
| 重写 `start.sh` 引入回归 | 保留旧脚本的可用入口语义；以 `start.bat` 为行为基准逐项对照 |

## 6. 验收方式

见 `docs/57`。核心判据：**校验器对现有 4 个脚本零误报**，且**注入 8 类缺陷时全部检出**。
