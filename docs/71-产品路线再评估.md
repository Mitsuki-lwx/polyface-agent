# 产品路线再评估：从「文本改写器」到「AI 轻量剪映」的差距清单

日期：2026-10-06 · 触发：用户问「有这么快吗 / 用户功能够吗 / 素材库 / 多模态 / 编排 / harness 规范 / 粗剪还是细剪」
性质：**评估与建议**，不是已确认决策。涉及排序变更的，需按项目惯例落 ADR 后再动代码。

## 0. 先回答「有这么快吗」——没有

M6-2 的"绿"指的是**一个功能**（在工作台里改封面）端到端证据齐全，**不是产品做完了**。

而且必须把这段历史摆出来：`outputs/项目可行性与现实推进建议-2026-09-14.md` §5 明确写了
**"现在应暂缓：……自动成片等远期多媒体方向"**，§最后一句是
**"下一张开发任务应是'修质检和事实确认闭环'，不是'再加一个功能'"**。

我们在 2026-10-06 做的 M6-1/M6-2，**正是那个被建议暂缓的方向**。这不是违规 ——
是用户当天的定向（ADR-019 有记录），且做得很扎实（有 E2E、变异测试、降级不变量）。
但要说清楚：**"快"是错觉。我们是在重新定向之后，把新方向的第一步做扎实了，
不是把产品做完了。**

## 2. 粗剪 vs 细剪：不是"二选一"，是"人在哪一步进来"

**建议：粗剪为默认交付，细剪为可选；但真正的分野不是精度，而是"人改的是什么"。**

### 2.1 为什么不做细剪为主

| 理由 | 说明 |
|---|---|
| **细剪是剪映/PR 的主场，打不过** | 剪映有十年工程 + 免费 + 移动端。我们在时间线交互上做不出差异，投入产出比极差 |
| **AI 能省的时间在粗剪，不在细剪** | 去停顿、去口癖、自动字幕、分镜、卡点 —— 体力活，规则明确、可自动、错了肉眼可见。"这个转场好不好看"是审美判断，AI 给不出可信答案 |
| **行业现实就是"AI 预剪 + 人工审片"** | `docs/06` 自己写了，`docs/49 §5.2` 又重申过。定位成"零人工全自动出网感"是过度承诺 |

### 2.2 建议的形态：把"剪"变成"改数据"

```
L0 剪辑单（已有）     纯文本，告诉人怎么剪
L1 粗剪（默认交付）   AI 出「初剪 MP4」+「可编辑的时间线 JSON」  ← 关键是后者
L2 细剪（可选）       人在这条时间线上微调，改的是同一份 JSON
L3 渲染              统一由 ffmpeg 按 JSON 渲染
```

**核心主张：时间线是数据，不是视频。** AI 生成时间线 → 人改时间线 → 统一渲染。
这样 AI 的产出是**可编辑、可回退、可复现**的，而不是一段无法回退的 MP4。

这也是"轻量剪映"真正能落地的做法：**我们不做完整时间线 UI，我们做"AI 先剪好 + 一个够用的微调界面"**。
（M6-2 已经把"内嵌编辑器"这条路走通了 —— 同一套骨架可以承载时间线微调。）

### 2.3 顺带一个反直觉建议：**B2 先于 B1**

ADR-018 定的是 B1（图文成片）先。建议**重新评估**，理由三条：

1. **B1 撞两条红线**：它依赖 TTS 选型（ADR-018 的 Q3 至今未决）；而最省事的 B1 形态
   （单图 + 大量文字）**恰好是抖音官方明文打击的低质内容**（`docs/49 §5.1`）。
2. **B2 的痛点更硬**：博主手上本来就有口播视频，"去停顿 + 自动字幕"是纯体力活，
   价值立刻可感知，**且不需要 TTS**。
3. **B2 的地基已经全在了**：ffmpeg（已装且在用）、本地 ASR（`asr.py`）、剪辑单（已产出）。

> 若采纳，需新写 ADR 并同步 `docs/05` FR-52/53 的顺序表述 —— 不静默改。

## 3. 素材库：这不是一个功能，是地基

现状：`material` 只存文本。要变成"AI 轻量剪映"，必须先有**统一资产库**。

### 3.1 建议的资产模型

| 资产类型 | 说明 |
|---|---|
| 文本 | 现在的 material（长文/口播稿/大纲/笔记） |
| 图片 | 用户上传的图、从视频抽的帧、AI 生成的封面 |
| 音频 | 原始音轨、TTS 产物、BGM |
| 视频 | 原始录像、粗剪产物、成片 |
| 时间线 | 粗剪的时间线 JSON（**一等公民**，可再次编辑） |

每个资产带：来源（自有/生成/抽取）、标签、尺寸/时长、**复用次数**、
以及**与效果数据的关联**（`effect_metrics` 已存在，但现在挂在 draft 上，与素材层是断的）。

### 3.2 为什么它排第一

- 没有资产库，多模态无处安放（图片/音频/视频都得有归属）
- 没有资产库，剪辑没有输入（B2 要"用户的原始录像"，现在它不是一个可管理的对象）
- 没有资产库 + 效果关联，**"越用越懂你"就永远只是 prompt 里的一句话**，而不是数据事实
  —— 而这是 `docs/02` 里写的护城河

## 4. 编排：现在是"同步调用"，不是"编排"

| 缺什么 | 为什么现在会痛 |
|---|---|
| **任务/作业模型** | DB 里没有 job/task 表。生成是一次同步 HTTP 调用，靠 240s 预算撑着 |
| **异步 + 进度** | 视频渲染是分钟级甚至十分钟级；同步调用必然超时。**不解决这个，成片一定做不出来** |
| **断点续跑**（FR-42） | 标着 ⬜ 未实现 |
| **阶段可见** | 用户看到的是一句"生成中"，不知道在 understand 还是 qa |

**结论：编排是成片的硬前置。** 不是"锦上添花的工程优化" —— 没有它，L1 粗剪的渲染任务会直接把现有架构撑爆。

## 5. Harness engineering：当前最大的工程缺口

**这是"AI 产品"与"AI demo"的分界线。** 现状是全仓 `docs/` 里"评测/golden/回归集"**零命中**。

建议每个 AI 能力都必须具备（括号 = 现状）：

| # | 项 | 现状 |
|---|---|---|
| 1 | **输入契约**（结构化 in/out） | ✅ 有（pydantic schemas） |
| 2 | **工具集**（能用哪些工具，而非纯 prompt） | ❌ 无（`llm.py` 无 tool calling） |
| 3 | **预算**（token/时延/成本上限 + 超限行为） | ⚠️ 只有时延（LLM_TIMEOUT_SEC / 任务预算），无 token/成本 |
| 4 | **评测集（golden set）**：固定输入 + 期望**性质**，每次改 prompt/模型跑一遍 | ✅ **已补**（2026-10-07，见 `docs/spec_eval.md`） |
| 5 | **失败分类 + 降级** | ✅ 有（FR-70） |
| 6 | **trace + 用量** | ✅ 有（FR-71/72） |
| 7 | **prompt 版本化** | ⚠️ 模板有版本号，prompt 仍无版本号，但**每次跑分记录 prompt 指纹**（`scripts/eval/fingerprint.py`）—— 改了能看出来 |

**为什么 4 最关键**：项目已经有"变异测试"的肌肉（测试有没有效，靠注入证明）。
但那只覆盖**确定性代码**；prompt 与模型的改动目前**没有任何防线** —— 改一句提示词，
唯一能发现退化的方式是人工看几篇稿子。这是当前工程体系里最大的窟窿。

> 可落地的形态：20~30 条固定素材 + 对每条的**性质断言**（如"正文数字必须在事实清单里有依据"、
> "标题非空"、"不出现素材外的年份"），跑真实模型时输出通过率与 diff。**不追求精确匹配**
> （LLM 输出本就非确定），只断言性质。

## 6. 必须说清的一笔账：第三关 vs "先做出来"

`docs/50` 的第三关（真实作者对照试验）**至今没跑**，而 09-14 评估与 ADR-018 都把
"先验证再投入"写成了顺序。现在方向反转成"先做出来"。

**我不反对，但代价要摆在桌面上：**

- 我们正在**没有用户证据**的情况下持续增加工程复杂度；
- 每加一块（M6-1 / M6-2 各约千行代码 + 数十项测试）都在扩大"**万一方向错了要推翻的东西**"；
- 而第三关**不需要等任何功能做完**：1 位作者 + 2 份他的真实素材 + 半天。

**建议：不停止开发，但把第三关变成"并行且廉价"的动作。** 它现在是整个项目里
性价比最高、却一直没做的一件事。

## 7. 建议的路线（M7 起）

| 里程碑 | 内容 | 为什么这个顺序 |
|---|---|---|
| **M7 资产库** | 统一资产表（文本/图片/音频/视频/时间线）+ 迁移现有素材/封面/成片 + 标签/搜索/复用 + 与效果关联 | 地基。多模态与剪辑都要往上放 |
| **M8 编排任务化** | job/task 表 + 异步 + 进度 + 断点续跑 | 成片的硬前置，不做则 L1 一定撑爆 |
| **M9 Harness** | 评测集 + prompt 版本化 + token/成本预算 | 让"改 prompt"这件事第一次有防线 |
| **M10 粗剪（B2 优先）** | ffmpeg 去停顿 + 自动字幕 + 分镜 → **时间线 JSON** + 初剪 MP4 | 地基已在（ffmpeg/ASR/剪辑单）；不碰 TTS 与低质红线 |
| **M11 时间线微调（细剪）** | 复用 M6-2 的内嵌骨架，改时间线 JSON | 人进来改数据，不重剪 |

**并行且不占开发资源的一项：第三关（`docs/50`）立刻找人。**
