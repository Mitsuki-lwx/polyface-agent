# M6-2 编辑器进程编排与工作台内嵌 — 任务书

日期：2026-10-06 · 上游决策：`docs/08` **ADR-019**（形态）、**ADR-020**（集成形态 = HTTP + 内嵌）

---

## 1. 为什么做这个

M6-1 证明了"agent 能驱动后台编辑器出图"，但产物是**死的**：用户想调一下位置、换个色，只能自己装
gimpish 命令行去改。ADR-020 定的形态是 **HTTP + iframe 内嵌** —— 本任务把它做出来。

> 目标一句话：**点一下「在编辑器中打开」，就能在工作台里手改刚生成的那张封面。**

## 2. 范围

### In

| # | 项 |
|---|---|
| 1 | **受管编辑器进程**（Java）：懒启动、单实例、健康检查、退出清理 |
| 2 | **API**：`GET /api/editor/status`、`POST /api/editor/open`、`POST /api/editor/stop` |
| 3 | **前端**：封面区「✏️ 在编辑器中打开」→ iframe 内嵌编辑器 |
| 4 | **降级**：gimpish 未安装 → `available:false` + 安装指引，**绝不 5xx** |
| 5 | **安全**：只能打开**媒体目录内**的场景（复用 `MediaDir.resolveSafe`） |
| 6 | **版本钉死**：把已验证版本 `gimpish@0.1.0` 写进文档与 `doctor` 提示 |

### Out（明确不在本任务）

| 不做 | 归属 |
|---|---|
| 真正的桌面窗口 / Tauri / Electron 打包 | **M6-2b** |
| 随包分发 Node 运行时 | **M6-2b** |
| 视频剪辑适配器 | M6-3 |
| 用 LLM 自主改图（工具调用 / MCP） | 见 ADR-020：前提不成立，暂不做 |

## 3. 关键设计决定（先定，避免实现期摇摆）

| 决定 | 理由 |
|---|---|
| **懒启动**（第一次打开才起进程） | 大多数人只写稿不出图，常驻一个 Node 进程是浪费；也少一个常驻端口占用 |
| **单实例 + 切换文档时重启** | `gimpish serve --scene <dir>` 一次只服务一个文档；多实例会占多个端口、且用户看不到好处。重启成本实测 ~1s |
| **不自己实现渲染/编辑** | 我们只做编排；编辑能力全部来自 gimpish（ADR-019 决策 3） |
| **不靠 `{"ok":true}` 判断生效** | 实测：transform 传绝对坐标会被**静默忽略**且仍返回 ok（`docs/64` §9）—— 任何写操作后**回读校验** |

## 4. 依赖与前置

- M6-1 已交付（封面产物目录 `{media}/covers/<stem>/{scene.json,cover.png}`）
- 本机 `gimpish@0.1.0`（npm）。未安装时全链路降级
- 无新增 Java 依赖（用 JDK 自带 `ProcessBuilder` + `HttpClient`）

## 5. 验收（可观测）

1. 装了 gimpish：点「在编辑器中打开」→ iframe 里**真的加载出编辑器页面**，改动能落到同一个 `scene.json`
2. 没装 gimpish：接口返回 `available:false` + 安装指引（200），前端给提示而**不是**报错
3. 越界路径（如 `../../etc`）被拒（400）
4. 关掉 Java 进程后，**gimpish serve 不残留**（退出清理有效）
5. 全量测试无退化 + 变异测试 ≥1 次
6. 浏览器端到端实测（含截图）

## 6. 风险

| 风险 | 应对 |
|---|---|
| 子进程残留（僵尸 Node） | JVM shutdown hook + `stop` 接口 + 端到端验证"关 Java 后端口释放" |
| 端口冲突（8765 被占） | 配置项 `polyface.editor.port`；起不来 → `needs_manual` + 明确提示，不静默失败 |
| 跨源 iframe 读不到内部 DOM | E2E 只断言 iframe `load` + 独立访问 8765 验证页面本身；**不假装能读内部** |
| gimpish 上游 UI 变动 | 版本钉死 0.1.0；升级需重跑本任务的 E2E |
