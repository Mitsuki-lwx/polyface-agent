## 1. 默认值表（**每一项都必须能被覆盖**）

| 项 | 默认值 | 覆盖方式 | 说明 |
|---|---|---|---|
| 拆几条 | **由用户给**（不默认） | 接口/界面 | spec 关键决定二 |
| 每条的角度 | **由用户给** | 接口/界面 | 可以只给一个词 |
| 单次调用上限 | 8 条 | 接口参数 | 再多一次调用容易拆出重复的 |
| 温度 | 0.6 | 配置 | 拆分要有点发散，但不能乱编 |
| 子素材的 `parent_id` | 父素材 id | 不可配（契约） | 血缘 |

**验收**：每行在 §2 里有对应观测。

## 2. 参数与常量

- [x] 改温度 → 拆出来的角度多样性确实变了（可量：3 条的标题相似度）
- [x] 条数给 8 条以上 → 明确拒绝并说明上限（不是静默截断）

---

## 3. 拆分本身

- [x] 给 3 个角度 → **出 3 条**，且每条**对应一个角度**（能看出哪个角度对应哪条）
- [x] 少出一条 → **说清是哪个角度没拆出来**（不是"少了一条"）
- [x] 角度之间差别很大（"从钱的视角" vs "从心理的视角"）→ 产出确实不同
- [x] 角度给得很虚（"随便拆"）→ 明确提示"角度太空，拆出来会雷同"（或如实产出但标注）

---

## 4. 事实不许凭空造（**本模块的底线**）

- [x] 每条的 facts 都能在**父素材的事实清单**里找到
- [x] 每条 fact 能指出**来自父素材的第几条**（1-based，与既有事实声明一致）
- [x] 构造"模型多编一条事实" → 被拦下并**指出是哪条**
- [x] 子素材的 facts 数量 ≤ 父素材的 facts 数量（子集）

---

## 5. 子素材是一等素材

- [x] 拆出来的每条都进 `material` 表、有自己的 id
- [x] 子素材能**直接走完整管线**（→ 多平台稿件 → 成片）
- [x] 子素材的 `parent_id` 指向父素材，`angle` 是那条角度
- [x] 父素材能反查"我拆出了哪些"
- [x] 子素材**不动父素材**（父素材的 facts / 稿件都没变）

---

## 6. 任务化与记录

- [x] 拆分走任务：能看到进度、能取消
- [x] 杀掉服务重启 → `interrupted` → 能继续
- [x] `split.json` 记录：拆了几条、每条标题/角度、**用了父素材哪几条事实**
- [x] 按记录能逐条复核"这条是从哪几条事实来的"

---

## 7. 端到端（**必须有**）

- [x] 一份真实长素材 → 拆 3 条
- [x] 逐条核对事实**没超出**父素材
- [x] 拿一条子素材 → 生成多平台稿件 → 走通
- [x] 父素材能查到拆出了哪 3 条
- [x] 给一个"父素材里没有的角度" → **如实说拆不出来**，不硬编
- [x] 上面每一步的原始输出都留着

## 8. 诚实边界（验收时必须如实填）

- [ ] 明确记录：本版**只做按选题拆**，不做按形态拆（长文版/口播版/金句卡片）
- [ ] 明确记录：不做跨素材合并、不做递归拆、不做自动排队发布
- [ ] 明确记录：拆分**只读父素材**
- [ ] 明确记录：拆出来的质量**取决于父素材**（父素材本身没有的事实，拆不出来）

## 实机验证记录（2026-10-17，`data/e2e-loop` 库，真实 LLM）

父素材 = 叔本华长文（6 条事实）。

| 步骤 | 原始结果 |
|---|---|
| 老库补列 | 启动日志：`migrated: material.parent_id added` / `angle` / `format` —— 真实老库上自动迁移成功 |
| 拆 3 个角度 | HTTP 200，71s，出 3 条；角度「从钱/从时间/从审美」三条标题与核心意思**确实不同** |
| 事实核对 | 3 条各自 3/2/2 条事实，**逐条都在父素材 6 条里**（出处 [1,2,6] / [3,4] / [4,5]），无一条编造 |
| 父素材反查 | `GET /api/materials/1/children` → 3 条，带角度与标题 |
| 子素材走完整管线 | 子素材 #2「从钱的视角」→ 抖音稿 `30岁写书没人买，晚年靠一本《附录与补遗》火了`（251s，`succeeded`） |
| 界面 | 浏览器实测：面板能展开、能反查、能拆分；结果列出每条的角度/标题/事实出处 |

### 实测中发现并修掉的缺陷（两条都记在这里，别删）

1. **`getMaterial` 用显式列名，加列后当场炸** —— `getMaterial failed`。
   `getMaterial` / `listMaterials` 都改成了 `SELECT *`。
2. **子素材的事实被绕过** —— 子素材没标 `facts_confirmed`，生成时又拿全文重新理解了一遍，
   出的稿引用了父素材的 6 条而不是这个角度精选的 3 条。**拆分的意义就没了。**
   修：`insertChildMaterial` 直接标 `facts_confirmed=1`（它们逐条来自父素材已确认的事实）。
   复验：出的稿引用 `[1,2,3]` ✓ 全在这个角度的 3 条里。

### 未验证 / 未做（如实列）

- §3 的 `[ ] 少出一条 → 说清是哪个角度没拆出来` 未单独构造场景验证。

### 任务化（2026-10-17 第二轮）—— 上面两项已做，实机验证如下

| 场景 | 原始结果 |
|---|---|
| 走任务 | `POST /api/jobs {kind:"split"}` → `queued` → `running` → `succeeded`；状态可轮询 |
| 进度 | 界面实测：`正在拆… 已 2s` → `已 5s` → `拆出 1 条`（轮询真的在动） |
| 取消（调用中途） | 2s 点取消，模型 16s 才返回 → **结果被丢弃，一条素材没建**（7 → 7），事件流记 `canceled:true` |
| 杀掉服务重启 | 任务 8 标为 `interrupted`（**不是 failed**）；子素材 5 条一条没建 |
| 继续 | `POST /api/jobs/8/resume` → `succeeded`（14s），子素材 5 → 7，**没有重复** |
| 重复继续 | 状态已是 succeeded → **409 明确拒绝** |
| 事件流 / 记录 | `jobs/job-*/events.jsonl` 有 start/end 与每条子素材；`split.json` 是完成标记 |

**界面实测逮到的第三个缺陷**：轮询里用详情响应覆盖了存 id 的变量，而详情字段叫 `id` 不是 `job_id`
→ 第二轮请求打到 `/api/jobs/undefined`。已改成把 id 单独存，并加了防御性检查。

### 接口变更（破坏性，已同步 UI 与测试）

- **删掉** `POST /api/materials/{id}/split`（同步版）→ 统一走 `POST /api/jobs {kind:"split"}`。
  刻意不留转发端点：两份"至少给一个角度或形态"的校验迟早会不一致。
- 新增 `POST /api/jobs/{id}/resume` / `cancel` 对 `split` 种类的支持
  （原先的取消/续跑分发是个三元表达式，split 会**静默掉进 roughcut** ✗ 已改成分派）。

## 行为边界验证（2026-10-17，真 LLM，换 key 后）

用真素材（64.76s 口播的转录，360 字 / 8 条事实）当父素材。

| 场景 | 实测结果 |
|---|---|
| **条数超上限**（9 个角度，上限 8） | ✓ 明确拒绝：「一次最多 8 个角度，收到 9 个（再多容易拆出重复的，建议分批）」 |
| **矩阵爆量**（4 角度 × 4 形态 = 16 > 12） | ✓ 明确拒绝：「选题 × 形态 = 16 条，超过上限 12（别一次全铺开，分批做）」 |
| **父素材里没有的角度**（"从量子力学的视角"） | ✓ **没有硬编**：模型返回的标题就是「从量子力学看搭子？素材里没有这个角度」，**引用事实 0 条** |

前两条**代码里早就实现了**（`split.py` 的 `MAX_ANGLES=8` / `MAX_ITEMS=12`），
只是从没验过 —— 这次真跑确认了，报错文案是**可执行的建议**（"分批做"），不是干巴巴的拒绝。

第三条是 spec 明确要的"**如实说拆不出来**"，实测**确实没编**。

## 剩下三条的补齐（2026-10-17）

### 「少出一条要说清哪个角度」✓ —— 已验（之前没能触发）

代码里早有这条分支，这次**故意让模型漏掉第 2 个目标**，实测：

```
第 2 个目标「从时间的视角」没有拆出内容 —— 可能是素材里支撑不了这个角度/形态，换一个或删掉它
```

**说清了是哪个角度** ✓，而且给了**下一步动作**（换一个或删掉）✓，不是一句"少了一条"。
已加回归测试 `test_missing_target_names_the_angle`。

### 「角度太空要提示」✓ —— 新实现

新增 `vague_angles()` 纯函数 + `split_material` 的前置拒绝：

```
这些角度太空，拆出来会雷同：随便拆。
换成能区分开的角度再试，例如「从钱的视角」「从时间的视角」「从审美的视角」
```

- 判据：**太短**（< 4 字）或命中推诿词（随便/看着办/你决定/帮我拆…）
- **全是空 → 当场拒绝，不调模型**（不花冤枉钱）
- **部分空 → 放行**（模型对具体那几个角度仍能拆好）
- 拒绝时给**具体示例**，不是干巴巴地说"角度太空"

### 「改温度 → 多样性变」✓ —— 温度已暴露

- `split_material(temperature=…)` 本来就有（默认 0.6），这次**接到了接口上**：
  `POST /api/jobs {kind:"split", temperature: 0.9}` → `SplitRunner` → Python `/split` → `chat_json`
- **续跑也带上**（否则续跑的温度与首次不一致 → 结果对不上）
- 回归测试 `test_temperature_is_forwarded_to_the_model` 证明它**真的传到了模型**

> 注：这条是"**可调**"已验证 ✓；"**调到多少多样性会怎么变**"需要人工对两次产出做主观比较，
> 属于使用层面的调参，不构成自动化验收项。
