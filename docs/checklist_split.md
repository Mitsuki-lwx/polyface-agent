# checklist —— 素材拆分

上游：`docs/spec_split.md`　　tasks：`docs/tasks_split.md`

> 每项必须**可勾选、可观测**。**至少一条端到端验收**（§7）。

---

## 1. 默认值表（**每一项都必须能被覆盖**）

| 项 | 默认值 | 覆盖方式 | 说明 |
|---|---|---|---|
| 拆几条 | **由用户给**（不默认） | 接口/界面 | spec 关键决定二 |
| 每条的角度 | **由用户给** | 接口/界面 | 可以只给一个词 |
| 单次调用上限 | 8 条 | 接口参数 | 再多一次调用容易拆出重复的 |
| 温度 | 0.6 | 配置 | 拆分要有点发散，但不能乱编 |
| 子素材的 `parent_id` | 父素材 id | 不可配（契约） | 血缘 |

**验收**：每行在 §2 里有对应观测。

---

## 2. 参数与常量

- [ ] 改温度 → 拆出来的角度多样性确实变了（可量：3 条的标题相似度）
- [ ] 条数给 8 条以上 → 明确拒绝并说明上限（不是静默截断）

---

## 3. 拆分本身

- [ ] 给 3 个角度 → **出 3 条**，且每条**对应一个角度**（能看出哪个角度对应哪条）
- [ ] 少出一条 → **说清是哪个角度没拆出来**（不是"少了一条"）
- [ ] 角度之间差别很大（"从钱的视角" vs "从心理的视角"）→ 产出确实不同
- [ ] 角度给得很虚（"随便拆"）→ 明确提示"角度太空，拆出来会雷同"（或如实产出但标注）

---

## 4. 事实不许凭空造（**本模块的底线**）

- [ ] 每条的 facts 都能在**父素材的事实清单**里找到
- [ ] 每条 fact 能指出**来自父素材的第几条**（1-based，与既有事实声明一致）
- [ ] 构造"模型多编一条事实" → 被拦下并**指出是哪条**
- [ ] 子素材的 facts 数量 ≤ 父素材的 facts 数量（子集）

---

## 5. 子素材是一等素材

- [ ] 拆出来的每条都进 `material` 表、有自己的 id
- [ ] 子素材能**直接走完整管线**（→ 多平台稿件 → 成片）
- [ ] 子素材的 `parent_id` 指向父素材，`angle` 是那条角度
- [ ] 父素材能反查"我拆出了哪些"
- [ ] 子素材**不动父素材**（父素材的 facts / 稿件都没变）

---

## 6. 任务化与记录

- [ ] 拆分走任务：能看到进度、能取消
- [ ] 杀掉服务重启 → `interrupted` → 能继续
- [ ] `split.json` 记录：拆了几条、每条标题/角度、**用了父素材哪几条事实**
- [ ] 按记录能逐条复核"这条是从哪几条事实来的"

---

## 7. 端到端（**必须有**）

- [ ] 一份真实长素材 → 拆 3 条
- [ ] 逐条核对事实**没超出**父素材
- [ ] 拿一条子素材 → 生成多平台稿件 → 走通
- [ ] 父素材能查到拆出了哪 3 条
- [ ] 给一个"父素材里没有的角度" → **如实说拆不出来**，不硬编
- [ ] 上面每一步的原始输出都留着

---

## 8. 诚实边界（验收时必须如实填）

- [ ] 明确记录：**不让模型自己决定拆几条**（spec 关键决定二）
- [ ] 明确记录：本版**只做按选题拆**，不做按形态拆（长文版/口播版/金句卡片）
- [ ] 明确记录：不做跨素材合并、不做递归拆、不做自动排队发布
- [ ] 明确记录：拆分**只读父素材**
- [ ] 明确记录：拆出来的质量**取决于父素材**（父素材本身没有的事实，拆不出来）

---

## 9. 变异测试（**必须做**）

- [ ] 把"facts 必须是父素材子集"的校验去掉 → §4 的断言**变红** → 还原
- [ ] 把"少一条要说清是哪个角度"改成只说"少了一条" → §3 的断言**变红** → 还原
- [ ] 把子素材落成"稿件"而不是"素材" → §5 的断言**变红** → 还原
