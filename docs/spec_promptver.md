# spec —— 提示词版本化（M9 的最后一块）

版本：2026-10-17　　对应 tasks：`docs/tasks_promptver.md`　　验收：`docs/checklist_promptver.md`

---

## 1. 背景

M9（harness）的三块里，**评测集**（`docs/spec_eval.md`）与**用量/成本**（`usage.py` +
`data/llm-usage.jsonl`）都已经做了。缺的是最后一块：**提示词版本化**。

现在的问题很具体：`grep -rn "prompt_version" python-service/app/` → **0 命中**。
也就是说，**改了 prompt 之后，历史记录里看不出哪条是旧 prompt 产的** ✗。

后果：改了提示词 → 效果变好或变坏 → 翻 `llm-usage.jsonl` 只能看到 token 与场景，
**对不上是哪一版 prompt**。评测集能告诉你"这次没退步"，但**说不出"跟哪一次比"**。

---

## 2. 目标用户

**现阶段只有作者本人**（沿用前几版定位）：会改提示词、想知道"改了之后到底变没变"的人。

---

## 3. 能力清单（一句话一条）

1. 每次 LLM 调用都记下**当时用的是哪一版提示词**，可事后查
2. 版本号**自动产生**：改了提示词内容，版本号就变 —— **不靠人记得手动递增**
3. 版本号**按提示词分别算**（理解/简报/成稿/QA/剪辑单/拆分/去冗余…各自独立），
   改了一个不该把其它的一起标成新版本
4. 记录里**能反查到当时那份提示词的全文**（不是只有一个不可读的哈希）
5. **对现有调用链零侵入**：不改各管线的业务逻辑，不改提示词的写法
6. 提示词缺失/取不到源码时**降级为空**并说明，**不阻断调用**
7. 版本信息进**已有的**用量记录（`llm-usage.jsonl`）与 trace，不另起一套日志

---

## 4. 非功能要求

- **确定性**：同一份提示词源码 → 同一个版本号（跨进程、跨机器都一致）
- **零维护**：不引入需要人手工维护的版本号
- **零额外调用**：算版本号不许调模型、不许读网络
- **开销可忽略**：算一次哈希 + 缓存，不重复读文件

---

## 5. 设计骨架

```
提示词构造函数（prompts.build_*）
        │
        ├─ 首次调用时：读自己的**源码文本** → 算哈希 → 缓存
        │
        └─ 调用 LLM 时（llm.chat_json(scene="draft")）
                 └─ 记进 usage/trace：{scene, prompt_fp, prompt_chars, …}
```

### 关键决定一：版本号 = **提示词构造函数的源码哈希**（用户选）

为什么不是"手写版本号"：**会忘** ✗ —— 忘了就白做，而这正是要防的事。

为什么不是"整个 `prompts.py` 的文件哈希"：**太粗** ✗ —— 改一处会把所有提示词
都标成新版本，历史记录里全是噪音。

为什么不是"最终拼出来的 prompt 的哈希"：**那是数据哈希** ✗ ——
素材变了哈希就变，跟"提示词改没改"无关，正是要区分开的两件事。

**构造函数源码**正好是那个"模板"：它包含所有静态文案与拼接逻辑，
不含素材内容 ✓。用 `inspect.getsource()` 取，改了内容哈希必变 ✓。

### 关键决定二：**存全文**，不只存哈希

哈希不可读 ✗。记录里除了哈希，还要**把当时的提示词模板存一份** ——
否则半年后看到一个哈希，谁也不知道它对应什么。

存哪：与哈希一起进用量记录目录（`data/` 下），**按哈希命名**、**同哈希只存一次**（内容寻址）。
这样"版本号 → 全文"是**直接可查**的，且不会因为重复调用把磁盘写爆。

### 关键决定三：**对现有调用链零侵入**

不改各管线的业务代码 ✓，不改提示词的写法 ✓。做法：
- 提示词构造函数**注册**到一个表里（名字 → 函数）
- `llm.chat_json(scene=…)` 按 `scene` 查表拿哈希（查不到就留空 ✓）
- 记录写入点在 `chat_json` 内部 —— **一处改动覆盖全部调用**

### 其它骨架决定

- 哈希用 **SHA-256 前 12 位**（够用且短；碰撞概率在这个量级可忽略）
- 源码取不到（打包成 pyc / 动态生成）→ **留空并标注**，不报错
- 与已有 `scene` 字段**并存**，不改它的语义

---

## 6. Out of Scope（本版不做）

- **不做提示词的自动 A/B**（谁比谁好要人来判）
- **不做版本回滚**（git 已经是版本管理，这里只做"记录可追溯"）
- **不改评测集的跑法**（它已经有自己的入口）
- **不做模型版本绑定**（那是另一件事；本版只管提示词）
- **不引入 MCP / 不做工具调用**（ADR-020 已定）

---

## 7. 已知风险

| 风险 | 应对 |
|---|---|
| 源码里含**动态内容**（f-string 里的变量名）→ 哈希随无关改动变 | 可接受：变量名改了确实算"改了提示词构造"，且不会误报"没改" |
| 打包后取不到源码 | 留空并标注，不阻断（spec §3 第 6 条） |
| 存全文占磁盘 | 按哈希去重（内容寻址），同版本只存一份 |
| 有人绕过 `chat_json` 直接调模型 | 记录点只在 `chat_json` —— 绕过的调用**不会**被记（已知边界，写进文档） |
