# 数字依据校验加固（FR-60）— spec

日期：2026-09-17 · 对应 task：`docs/51` · 对应 checklist：`docs/53`
引用：FR-60（质检）· UC-11（成稿质检）· `docs/38`（质检加固）· `docs/31`（DNA v2 结构模板）

---

## 1. 现状（代码事实）

`python-service/app/pipeline/generate.py`：

```python
_NUM_RE = re.compile(r"\d+(?:\.\d+)?(?:[%％万kK亿])?\b|\d{2,}")

# _rule_qa 内
fact_text = " ".join(f.text for f in mat.facts)
nums_in_body = set(_NUM_RE.findall(draft.body))
nums_in_facts = set(_NUM_RE.findall(fact_text))
for n in sorted(nums_in_body):
    if n not in nums_in_facts:
        warnings.append(f"正文含素材中无依据的数字: {n}（请确认或删除）")
```

## 2. 缺陷分析（2026-09-17 实测）

### D1 `\b` 在中文语境下失效 —— 同一数字两边命运不同

Python 的 `\b` 基于 Unicode 词字符，而**汉字属于词字符**。于是：

| 文本 | 提取结果 |
|---|---|
| `月入0做到3万`（素材里的写法） | `['3万']` ← **`0` 被丢掉** |
| `月入0，坚持`（正文里的写法） | `['0']` ← 被保留 |

→ 同一个 `0` 在**素材中隐身**、在**正文中现身** → **必然误报**。这不是"偶尔不准"，
而是"取决于数字后面那个字是不是汉字"，**结果不可预测**。

### D2 分点序号被当作事实数字

`1. 复盘数据…` / `2. 分析反馈…` → 提取出 `1`、`2`、`3`，素材里当然没有 → 误报。
而"分点/分步"是 DNA 推荐的**小红书标准结构**（`structure_template` 第 2 条），
于是**越规范越吵**。

### D3 `3w` 完全漏检 —— 反向缺陷

`[%％万kK亿]` 不含 `w`，且 `\b` 在 `3w` 处同样不成立 → `月入3w` 提取为 `[]`。
`w` 是中文互联网对"万"的通用简写，模型也确实这么写（真实产出中就是 `3w`）。
→ **真·无依据的数字会被静默放过**（这里是 3w 恰好等于素材的 3万，所以无害；
但若模型写 `5w` 而素材只有 3万，也不会被抓）。

### D4 同一缺陷刷出多条同类告警

4 条独立 warning 占满 UI，盖住真正的告警。

## 3. 方案

### 3.1 Token 提取：用数字 lookaround 取代 `\b`

```python
# 关键：不要用 \b —— 汉字是 Unicode 词字符，`0做` 处没有词边界，
# 会导致同一个数字在不同邻接字下时隐时现。改用「前后都不是数字」判定。
_DIGIT_UNIT = r"[%％万wWkK亿]"
_NUM_RE = re.compile(rf"(?<!\d)\d+(?:\.\d+)?{_DIGIT_UNIT}?(?!\d)")
```

- 补 `w/W`（D3）
- 去掉 `\d{2,}` 备用分支：主分支已能覆盖（旧分支的存在正是为绕开 `\b` 的副作用）

### 3.2 单位归一化，让简写与全称可比

```python
_UNIT_ALIAS = {"w": "万", "W": "万"}
def _norm_num(tok: str) -> str:
    """`3w` 与 `3万` 视为同一个数字。"""
    return re.sub(r"[wW]$", "万", tok)
```

比较时用归一化后的集合；**展示时保留原文**（用户看到的是他稿子里的写法）。

### 3.3 剥离分点/序号标记后再提取（D2）

```python
# 行首（允许最多 4 个非词字符做前缀，兼容 📊 / emoji / ·）或空白之后，
# 1~2 位数字 + 序号标点 + 空白/行尾 → 视为序号，不当事实数字。
# 只认 1~2 位，避免把「2023.」这类年份误当序号。
_LIST_MARKER_RE = re.compile(
    r"(?m)(?:^[^\w\s]{0,4}\s*|\s)\d{1,2}\s*[.、)）．]\s*"
)
```

处理：`body_for_numbers = _LIST_MARKER_RE.sub(" ", draft.body)`

> 设计取舍：**宁可漏掉一个真数字，也不要对每篇稿子刷噪声**。序号剥离只影响
> `1.`~`99.` 这种形态，真实金额/年份（≥3 位或多位小数）不受影响。

### 3.4 告警合并（D4）

```python
unsupported = sorted(nums_in_body - nums_in_facts)
if unsupported:
    warnings.append("正文含素材中无依据的数字: "
                    + "、".join(unsupported) + "（请确认或删除）")
```

单数字时输出与原先**逐字一致**（`…: 999万（请确认或删除）`），保证既有测试与
UI 文案不破。

## 4. 接口与数据约定

- **无对外接口变化**：仅 `_rule_qa` 内部的告警文本与数量变化。
- `QaReport.warnings: list[str]` 结构不变；**"无依据数字"仍为 warning，不做阻断**
  （沿用 `docs/36` spec Q1 决策）。
- 前端 `index.html` 已渲染 `warnings`，无需改动（合并后条数变少，展示反而更清楚）。

## 5. 兼容性

| 场景 | 变化 |
|---|---|
| mock 模式 | 无影响（mock 成稿无分点序号，且无中文邻接数字） |
| 真实模式 | 告警由 4 条噪声 → 0 条（本条真实样本）；真无依据数字仍会报 |
| 既有测试 | 单数字告警文本逐字一致；`test_qa_hardening.py` 中涉及该告警的断言应继续通过 |
| 发布包 | 纯 Python 逻辑，随下次打包生效 |

## 6. 测试场景（详见 `docs/53`）

**正向（必须抓到）**
1. 正文 `我月入999万` + 素材无该数字 → warning 含 `999万`
2. 正文 `月入5w` + 素材只有 `3万` → warning 含 `5w`（归一化后与 3万 不等）
3. 正文 `营收 3.5亿` + 素材无 → warning 含 `3.5亿`

**反向（必须不报）**
4. 中文邻接：素材 `从月入0做到3万`、正文 `从月入0做到3万` → **不报**（D1 回归）
5. 分点序号：正文 `1. 甲\n2. 乙\n3. 丙`、素材无 1/2/3 → **不报**（D2 回归）
6. emoji 前缀序号：`📊 1. 复盘数据找爆款基因` → **不报**
7. 单位简写：素材 `从月入0做到3万`、正文 `从0做到月入3w` → **不报**（D3 回归）
8. 年份不被当序号剥离：正文 `2023年刚裸辞` → `2023` 仍参与比对

**边界**
9. 多条无依据数字 → 合并为**一条** warning，且列出全部
10. 真无依据数字与序号并存 → 只报真的那个，序号不出现

## 7. 未决 / 已知局限（诚实记录）

- **不做语义合理性判断**：`3万` 与素材的 `3万` 相同即通过，不管上下文是否被曲解。
  这属 LLM 质检的职责。
- **序号剥离是启发式**：形如 `3. 5亿` 这种奇特写法可能被误剥。已用"1~2 位 + 序号标点"
  收窄范围；若真实遇到再调整。
- **仅处理半角数字**：全角 `１` 不识别（现有实现即如此，本次不扩范围）。
