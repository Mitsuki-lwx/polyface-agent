# 发布包内验证（浏览器 UI + 音视频入料）— spec

日期：2026-09-21 · 对应 task：`docs/59` · checklist：`docs/61`

---

## 1. 为什么"在源码目录跑通"不等于"包内跑通"

发布包与源码目录有三处实质差别，每一处都可能让"开发机上是好的"变成用户那里的故障：

| 差别 | 会放倒什么 |
|---|---|
| 目录位置不同（且可能含中文/空格） | 路径拼接、相对路径解析、`PYTHONPATH` |
| Python 环境不同（包内建 venv，非开发机 venv） | 依赖缺失、可选依赖（ffmpeg/ASR）行为差异 |
| 静态资源来自 `polyface.jar` 内部，不是 `src/main/resources` | 前端改动未重新编译进 jar 时，包内是**旧前端** |

**第 3 条尤其容易骗人**：改了 `index.html` 却只跑 `spring-boot:run`（会读源码目录），
看着是对的；而包里打的是 `target/classes` 里的旧副本。**所以"包内 UI"必须单独验。**

## 2. 验证环境

| 项 | 值 |
|---|---|
| 包 | `dist/polyface-0.4.0.zip`（T1 重新打包后的） |
| 解压位置 | **仓库之外**的隔离目录（避免"其实在读源码目录"） |
| 启动方式 | 包内 `polyface.jar` + 包内 `python-service` 的 venv |
| 模式 | `LLM_MOCK=true`（隔离变量；真实模式证据在 `docs/54`） |
| 浏览器 | Edge + CDP（headless），真实点击并读 DOM |

**端口**：优先 8080/8000；若被第三方占用，用 `POLYFACE_JAVA_PORT` / `POLYFACE_PY_PORT`
覆盖并在结论中**显式标注"非默认端口"**（`docs/58 §7` 记录过本机 8000 被第三方占用）。

## 3. 浏览器 UI 验收流程（对应 FR-34 / FR-42）

逐步断言，每步读 DOM 而非看截图：

| 步 | 操作 | 断言 |
|---|---|---|
| U1 | 打开首页 | `200`，且页面标题/关键元素存在（`#raw`、`#btnAnalyze`） |
| U2 | 填素材文本 → 点解析 | 出现事实编辑器 `#factsEditor`，事实行数 ≥ 1 |
| U3 | 改一条事实 + 点「添加一条」 | 行数 +1 |
| U4 | 点「保存并确认」 | 状态文案含「已确认」 |
| U5 | 点生成（单平台） | `#genStatus` 含「完成」，成稿面板出现 `#edBody` 且正文非空 |
| U6 | 改正文/标题/标签 → 保存 | 状态含「已保存」 |
| U7 | **刷新页面** → 点历史素材 | 正文 = U6 改后的内容（验证落库 + 历史稿不再为空）、事实确认状态与条数恢复 |

**U7 是核心**：它是 `docs/42` 修的"历史稿正文为空"缺陷的**唯一端到端证据**，
而此前只在源码目录验过。

## 4. 音视频入料验收（对应 FR-51）

用**包内**的 `scripts/e2e_fr51.py`（它会用 ffmpeg 现场造样本，无需外部素材）：

| 组 | 断言 |
|---|---|
| 上传 | 返回 `media_id` |
| 探测 | ffprobe 报出时长/轨道；非法文件被拒 |
| 字幕轨优先 | 带字幕样本走**零算力**路径 |
| 无字幕 → ASR | 走转写；**若本机无 faster-whisper 则必须降级为 `needs_manual` + 安装指引**，不得报错中断 |
| 转写文本可编辑 | 符合 UC-12"转录文本可编辑后再解析" |

**降级路径不是缺陷**：`asr.py` 的既定设计是"检测到就用，没有则降级 + 给指引"。
本次若走的是降级路径，须**明确记录"未验证真实转写"**，不得写成"转写通过"。

## 5. 缺陷归属判定

| 归属 | 判据 |
|---|---|
| **代码缺陷** | 源码目录同样能复现 |
| **包组装缺陷** | 源码目录正常、包内异常（如静态资源未重新编译、文件未打进包） |
| **环境差异** | 仅因本机缺可选依赖/端口被占导致，且已按设计降级 |

三类必须分开记 —— 混在一起会把"包的问题"错记成"产品的问题"。

## 6. 兼容性与不变量

- 本次**不改任何代码**。若发现缺陷，只记录 + 定性；修不修、怎么修另立任务
- 不变量：验证前后 Python 260 / Java 43 仍全绿（防止"验证过程顺手改坏了"）
- 包内 `data/` 会写入测试数据 → 用独立数据目录，验证后清理

## 7. 未决 / 已知局限

- **仍不覆盖**：`.bat` 真机执行、真 macOS/Linux、真实 LLM 模式下的包内链路
- **单机单次**：UI 只验 1 个平台（小红书），未逐平台验
- 若本机 8000/8080 被占而走了覆盖端口，"默认端口下跑通"这一次仍未实测
