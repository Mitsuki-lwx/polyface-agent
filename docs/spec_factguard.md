# spec —— 事实约束加固（只约束事实，不约束句式）

版本：2026-10-09　　对应 tasks：`docs/tasks_factguard.md`　　验收：`docs/checklist_factguard.md`
上游依据：`docs/76-幻觉对策-可行性判断.md` · `docs/checklist_eval.md`（基线实测）

---

## 1. 背景

基线实测（5 平台 × 10 条，通过率 52%）里，**15 次 A7 失败全部是"越界推断型"幻觉**：

```
素材：要交下个月的伙食费286块
成稿：连交下个月伙食费286块这种小事，都能漏        ← 「漏交」是加的
素材：去年十月我家老二上幼儿园之后事情就彻底失控了
成稿：标题写「半年真实数据 / 半年真实效果」          ← 素材里没有任何时间跨度
```

**不是知识缺口** —— 素材全文就在 context 里。是模型在"合理推断"与"编造"之间越界。
所以 **RAG / 检索对这一类无效**（判断依据见 `docs/76` §0）。

现在的防线是「理解阶段抽 3~10 条事实 → 生成 → QA 用 LLM 判」。
两道口子：

1. **生成阶段没有任何硬约束** —— 事实清单只是塞进 prompt 的一段文本，模型爱加就加
2. **QA 只拿到 3~10 条事实清单，拿不到素材原文** —— 判定证据比模型手里的还少

> 已排除的假设：原以为"事实清单有损（1334 字只抽 10 条）导致 QA 误判"。
> 用基线数据验证是 **0 处**（`docs/76` §0）。**QA 判得基本是对的，问题在生成端。**

## 2. 目标用户

**现阶段只有作者本人**。这是给"改 prompt / 改校验"的人用的加固，不是给终端用户的开关。

## 3. 能力清单（一句话一条）

1. **生成阶段必须声明用了哪些事实**：成稿除了正文，还要给出"这段正文依据的是哪几条事实"
2. **机械可判的部分一律机械判**：数字、年份、**专有名词**必须能在素材或声明的事实里找到依据 —— 不靠 LLM 判断
3. **QA 要拿到素材原文**：判定证据不能比被检对象还少
4. **按失败类型定向重写**：数字类 / 年份类 / 专名类 / 新增断言类，各自给不同的修复指令，而不是笼统"重写"
5. **违规要能定位**：报告里指明"哪一句、违反哪一类、依据是什么"，不是一句"未通过"
6. **阈值与开关全部可配**：严格程度、重写轮数上限、各类检查的开关都能从配置/命令行到达
7. **判定可复现**：同一产物 → 同一结论（机械部分完全确定；LLM 部分不变则不变）

## 4. 非功能要求

- **不引入新依赖**（本版）：`onnxruntime` + NLI 模型**先做离线实验**，通过决策门才谈引入（见 tasks T5）
- **不牺牲表达自由度**：只约束"事实"，不约束句式、语气、结构 —— 产物仍要读起来像人写的
- **成本可控**：每平台的 LLM 调用次数**不得增加超过 1 次**（现在最多 4 次，已是上游限流下的上限）
- **可单独关闭**：加固失效时能退回当前行为，不至于把产品卡死
- **不改变数据边界**：素材仍然只发给你自配的 LLM 服务商（ADR-017）

## 5. 设计骨架

```
理解（已有）→ 事实清单 f1..fn
     ↓
简报（已有）
     ↓
生成：正文 + 【本次用了哪些事实】          ← 新增：声明
     ↓
机械校验（代码，确定）：数字 / 年份 / 专名 必须能在 素材 ∪ 声明的事实 里找到
     ↓
LLM 质检：拿到【素材原文 + 声明的事实 + 正文】，只判一件事：
          「正文里有没有超出声明事实范围的断言」
     ↓
不过 → 按失败类型**定向**重写 → 再校验（轮数可配）
```

**关键决定一：只约束事实，不约束句式。**

考虑过"全骨架化"（连结构也从闭集组装）。**先不做** —— 那会把产物变成填模板，
与「按平台调性重写」的产品定位直接冲突，而且代价（改写质量下降）没量过。
本版只做"事实不许越界"，句式语气完全自由。**做完用评测集量出差距，再决定要不要加码。**

**关键决定二：能机械判的绝不交给 LLM。**

数字/年份/专名是**可枚举**的，交给代码判：确定、可复现、零成本。
LLM 只留一件它真正不可替代的事：**判断"这句话是不是超出了它声明依据的那些事实"**。
这个问题的范围比"这篇有没有幻觉"小得多，也更容易判准。

**关键决定三：让模型自己声明依据（attribution）。**

把"你有没有幻觉"这个模糊问题，换成"**你写的这句，依据的是哪条事实**"。
两个好处：机械校验有了明确的对照集合；LLM 质检的问题变窄了。
**风险要认**：模型可能**谎报**依据（声明了 f3 但正文其实超出了 f3）。
所以机械校验用「素材 ∪ 声明」的**并集**做白名单，并集只会更宽 —— 谎报不会让机械校验放水，
但会让 LLM 质检更容易发现（它能看到"你声明的是 f3，但你写的超出了 f3"）。

**其它骨架决定：**

- 机械校验**复用现有那套数字口径**（`app/pipeline/numberish.py`），不另造一套
- 专名清单从**素材原文**抽，**抽不到的就不检查** —— 宁可不查，不可误报。
  实际只抽三类：**书名号内**、**含大写字母或数字的拉丁串**、**已知平台/工具词表**。
  ⚠️ **引号内不抽**（实现时改的）：引号里也可能是被强调的普通词（"副业"），误报率高。
  ⚠️ **中文机构名不抽**（需要分词与 NER）。两处都是"放弃覆盖换零噪声"。
- 定向重写的**分类是封闭的**（四类），不做开放式建议，否则没法验收
- 加固整体有个**总开关**，默认开；关掉即退回当前行为

## 6. Out of Scope（本版不做）

- **全骨架化**（连结构也从闭集组装）—— 见关键决定一，先量出差距再说
- **引入 NLI 模型** —— 先做离线实验（tasks T5），通过决策门才另开 spec
- **RAG / 检索** —— 对越界推断无效（`docs/76` §0）
- **微调 / LoRA** —— 不在本项目能力与定位范围内
- **DoLa / contrastive decoding** —— 需要模型内部 logits，走 API 拿不到
- **逐句溯源高亮**（把每句话和素材原文连线给人看）—— 有价值但独立，本版只做校验不做展示
- **跨语言 / 多语素材** —— 中文单语
