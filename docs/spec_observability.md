# spec —— 运行透明化：阶段事件 + 进度可见 + 参数可问

版本：2026-10-06　　对应 tasks：`docs/tasks_observability.md`　　验收：`docs/checklist_observability.md`

---

## 1. 背景

粗剪跑起来之后，暴露了两件事：

**一、执行期是黑盒。** 命令跑起来之后，直到结束前**一个字都不打**。
25 秒素材 7 秒跑完看不出来；但 5 分钟的口播光转写就要约 60 秒，
全程没有任何输出 —— 用户唯一能做的判断是"它是不是卡死了"。

**二、参数只到得了两条路。** 用户能手动改（命令行）、能提前提供（配置文件），
但**没有"agent 问用户"这一条**：现在只有 CLI 在开始前问了停顿阈值一项，
而且是工具在问，不是一个会替你考虑的角色在问。

而项目的 LLM 侧**早就有**这套东西了：trace 贯穿全链路（FR-71）、用量落本地 JSONL（FR-72）。
视频侧完全没有对应物 —— 这是缺口，不是新想法。

## 2. 目标用户

**现阶段是作者本人**（与 `docs/spec_roughcut.md` 一致）。
但本次刻意把**事件格式做成机器可读且稳定**，因为用户明确要求"以后让 agent 自己读"
—— 那时候格式改一次，所有读它的地方都要跟着改。

## 3. 能力清单（一句话一条）

1. 长任务执行时**分阶段上报**：每个阶段的开始、结束、耗时、结果
2. **可选的细粒度进度**：转写与渲染能报百分比，不必等到结束
3. 阶段事件**落成机器可读的文件**，供事后复核与（将来的）agent 读取
4. 输出**分级**：安静 / 正常 / 详细；默认"正常"= 阶段 + 重要行 + 心跳，**不刷屏**
5. 结束后给一份**运行报告**：每步耗时、本次生效参数、剪点、产物在哪
6. **参数可被"问"**：开始前把关键参数摆出来，允许当场改；**问哪些、问不问都可配**
7. 同一套**参数契约**在命令行与将来的工作台之间复用（不各写一份）
8. 事件文件里**不记录素材内容**（沿用既有脱敏原则：只记长度/哈希/计数）

## 4. 非功能要求

- **格式稳定**：事件是给机器读的，字段名不能随手改；要有版本号
- **观测不改变业务**：这是项目踩过的坑（`docs/29` 记过"观测破坏业务语义"）——
  上报失败绝不能影响剪裁/转写本身
- **长任务不能看起来卡死**：任何超过几秒的阶段都要有可见的"还活着"信号
- **默认不刷屏**：详细日志是**主动要求**才有的
- **可完全关闭**：事件文件与进度都能关掉（比如批处理时）
- **不引入新依赖**：终端渲染用标准库；进度靠解析 ffmpeg/whisper 已有的输出

## 5. 设计骨架

**一个"阶段事件"的最小结构**（字段名是实现细节，这里只说该有什么）：

```
谁（本次运行的标识） · 哪个阶段 · 事件类型（开始/进度/结束/失败）
· 时间 · 耗时 · 一句人话 · 机器可读的补充字段
```

**两个消费者，同一份事件流：**

```
业务阶段 ──► 事件流 ──┬──► 终端渲染（给人看：阶段 + 耗时 + 进度 + 重要行）
                      └──► 事件文件（给机器/事后看：JSONL，稳定 schema）
```

**三种输出级别**（默认中间那个）：

| 级别 | 给谁 | 内容 |
|---|---|---|
| 安静 | 脚本/批处理 | 只出最终结果与错误 |
| 正常 | 人（默认） | 阶段 + 耗时 + 进度 + 重要行 + 心跳 |
| 详细 | 调试 | 再叠加底层工具的原样输出 |

**参数问法**：一个"展示 → 接受修改"的小循环。
展示的是**本次生效的全部参数**（含来源：默认/配置/命令行），
问哪些由配置决定 —— 默认只问**最影响结果的那几项**，问一长串会烦人。

**与既有观测的关系**：LLM 侧有 trace 与用量；本次是**视频/本地任务的对应物**。
两者不合并，但用同一套"本地 JSONL、脱敏、可关闭"的姿态。

## 6. Out of Scope（本版不做）

- **job/task 表、异步执行、断点续跑**（那是 M8 编排任务化）
- **工作台的进度条 UI**（接进工作台时再做；但**参数契约与事件格式先定下来**，届时直接复用）
- 多任务并发、分布式、远程观测
- 把粗剪接进 Web 工作台
- 把既有 LLM 观测（trace/用量）改造成同一套底座（**不顺手改**，那是另一件事）
