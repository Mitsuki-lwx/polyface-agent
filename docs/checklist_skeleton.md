## 补记：中文数字解析 bug —— 掉 4 格的直接根因（2026-10-26）

### 症状
上表 4 格 `call_failed` 的理由都是同一句：

```
SkeletonGateError: skeleton_gate: 段5 出现声明依据之外的数字「一千五」
```

而「一千五」**就在素材原文里**（"对方报价一千五一条图文"）✗。

### 根因：解析器把素材读错了
```
num_values('第一次商单对方报价一千五一条图文。', strict=True) → {1100.0: '一千五一'}  ✗
num_values('第一次商单报价一千五。',            strict=True) → {1500.0: '一千五'}   ✓
```
`_CN_RE` 把连续汉字数字字符**整串吃掉** →「一千五**一**」→ 1100 ✗。
素材侧算 1100、稿件侧算 1500 → 数字依据校验判"越界" ✗ →
`skeleton_gate` 把**整个调用**判死（不是"这一格断言失败"，是 `call_failed`）。

### 修法（两处，已在 `cfc273d`）
1. `zhnum.parse`：连续两个数字字符且前一个不是「零」占位 → 不是合法中文数字，返回 None。
   （第一版把条件写成"当前字符不是零"，误伤「一千零五」✗ —— 自己引入的回归，已改）
2. `zhnum._scan`（新）：整串不合法就**逐步缩短**，取最长能解析的前缀 ✓。
   没有回退的话，`parse` 返回 None 会让整个 token 被丢掉，又变成另一类误报。

### 验证：子集真跑（m02/m07，真模型，~48min）+ 离线复算

| cell | 基线 skeleton-v1 | 修复后 zhnum-fix |
|---|---|---|
| m07/bilibili · gzh · xhs | **call_failed** | **assert** ✓ **调用不再被判死** |
| m02/bilibili · xhs · m07/douyin | OK | assert ✗ |
| m02/gzh | call_failed | call_failed（另一处门：`段2 槽位引用 n=8`） |

**关键：`--reassert` 离线复算把变量隔离了** ✓ ——
用**基线那批草稿** + **新断言代码**重判（不调 LLM）：**30.0%（3/10）**，
**与基线逐格一致** ✓ → 所以那三个 OK→assert **是模型波动，不是本次改动** ✗。

### 如实说：**通过率没有提回去** ✗

- 本次修掉的是**"调用失败"** ✓：4 格里 3 格从 `call_failed` 变成有产出（用户不再拿到"生成失败"）；
- 但它们**仍过不了 QA** ✗ —— 卡在 **A7「新增断言」**（"这件事让我意识到…""路径的边界是…"），
  也就是上表归因里的**挤出效应**；
- `m02/gzh` 那格是**另一处门**（模型把 `{{n:8|…}}` 写进只声明了事实 [1,2,3,4] 的段 2）——
  同样属于"模型两轮修不好门"，与数字无关。

**所以「通过率提回去」还需要动 A7 那条**，而那是**产品取舍**（放宽 QA 判定 vs 让模型别写方法论式新断言），
不是纯 bug —— 这条我**不动**，等你拍板。

`variance.py` 的 docstring 记着这仓库实测过：**同一份代码、同一批素材，二值通过率在 38%~78% 之间跳**，
并明确警告「在那之前，我拿**单次采样**报过好几轮'提升/退化'，**全是噪声**」。

所以关键不是"98% 这个数"，而是**改善幅度与噪声带宽的比例**：

| | 二值通过率 |
|---|---|
| 基线 skeleton-v1 | **50%**（25/50） |
| 旧基线 t67 | 62%（31/50） |
| 本次 v1 | **98%** |
| 本次 v2 | **94%** |
| **噪声带宽（两轮跨度）** | **4 点** |
| **改善幅度** | **+44 ~ +48 点** |

**改善幅度 ≈ 噪声带宽的 11 倍** ✓ —— 这不是单次采样的运气 ✓。

### 逐格翻面的 4 格

全部集中在 **gzh**（4 格里 3 格）+ `m10/bilibili`：
- m03/gzh：「那天的事我复盘了很久」—— 素材只说「自责 + 下决心找工具」，

### ⚠️ 我之前一直拿**二值通过率**当头条，这是错的口径 ✗

`variance.py` 自己的结论写得很直白：

> **二值通过率不可用于跨版本比较**（本次跨度 6%）；支持率明显更稳，跨版本请以它为准。

**修正后的正确结论**（用**支持率**这个稳定指标）：

| 指标 | 基线 skeleton-v1 | 本次三轮 | 判定 |
|---|---|---|---|
| 原子支持率 | **0.9481** | **0.9989 ~ 1.0000** | **+5.1 点，跨度仅 0.11 点** ✓✓ |
| 二值通过率 | 25/50 = 50% | 94 ~ 100%（跨度 6 点） | 噪声大，**只作参考** ✗ |

支持率的跨度（0.11 点）比它自身的改善（5.1 点）小**一个数量级** ✓ ——
所以"变好了"这个结论**站得住** ✓；而"98% 还是 94%"这种话**不该说** ✗。
