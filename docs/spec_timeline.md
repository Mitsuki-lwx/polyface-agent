# spec —— 时间线（把「剪」变成「改数据」）

版本：2026-10-11　　对应 tasks：`docs/tasks_timeline.md`　　验收：`docs/checklist_timeline.md`
上游依据：`docs/71` §2.2（「把『剪』变成『改数据』」）· `docs/71` §7 M10（「分镜 → **时间线 JSON** + 初剪 MP4」）
· M11（时间线微调/细剪）· README 路线图 M7-2（「时间线作为一等资产」）

## 1. 背景

粗剪（M10）现在**已经在写** `work/cuts.json`：

```json
{"run_id": "…", "cuts": [[1.08, 1.92], …], "pauses": [...], "params": {...},
 "before": 123.4, "after": 98.7, "segments": [{"start":…, "end":…, "text":"…"}]}
```

也就是说 **数据其实已经在了**。缺的是三件事：

1. 它是**任务的中间件**（躺在 `work/` 里），不是**资产** —— 任务目录被清理，它就没了
2. **改不了** —— 想只删掉中间那一段废话，只能重跑一遍粗剪、把参数调来调去猜
3. **改完没法用** —— 没有"从时间线重新出片"的路径

`docs/71` §2.2 的判断是：剪辑的形态应该是**改数据**，而不是**拖时间轴**。
本模块就做这件事的最小可用版：**剪点 + 字幕**这两样已经有的数据，变成可改、可重渲的一等资产。

## 2. 目标用户

**现阶段只有作者本人**。他自己的口播视频，剪完之后发现"这段留着更好 / 那段其实该删"。

## 3. 能力清单（一句话一条）

1. **时间线落成资产**：粗剪产出规范的时间线（保留区间 + 字幕），登记进素材库，
   **不随任务目录被清理而消失**
2. **看得见**：工作台里按行列出每个保留区间 —— 起止秒、时长、**落在该段里的字幕**
3. **改得动**：能改起止秒、能删一段、能合并相邻段
4. **改得对**：非法编辑（越界 / 重叠 / 倒序 / 空）必须**当场拒绝并说清哪里不对**，
   不许"改了但结果是错的"
5. **看得到效果**：每行给一帧**预览**（该区间起点画面）；改完能看到总时长的变化
6. **重渲染出片**：从**源视频 + 时间线**重新剪一遍并重烧字幕，产出新成片，
   血缘挂回源视频（不是从旧成片再剪一次 —— 那会叠加压缩损失）
7. **字幕跟着剪点走**：删掉一段，落在该段内的字幕也要跟着消失/被截断 ——
   **绝不能让字幕与画面错位**（这是本模块最容易错的地方）
8. **两种入口**：粗剪跑完能直接打开时间线；素材库里也能从时间线资产进

## 4. 非功能要求

- **时间线是数据，不是命令**：文件里存的是"保留哪些区间、字幕是什么"，
  **不存 ffmpeg 参数**。渲染细节是实现，不能渗进数据格式
- **格式要能演进**：带 `version` 字段。以后加"分镜/音轨"时不破坏旧文件
- **重渲染必须可复现**：同一条时间线 + 同一个源 → 同样的成片（除编码抖动）
- **编辑不改变源**：源视频、旧成片都不动。重渲染产出**新**文件
- **时长口径唯一**：区间时长、总时长一律由 `cuts` 推出，不另存一份可能对不上的"总长"
- **不引入新依赖**：ffmpeg 已经有

## 5. 设计骨架

```
粗剪（现有）──► timeline.json ──► 素材库（资产，kind=timeline）
                    │                    │
                    │                    ▼
                    │           工作台：表格 + 预览帧
                    │           （改起止 / 删段 / 合并）
                    │                    │
                    └────────────────────┴──► 重渲染
                                              （源视频 + 时间线 → 新成片）
```

**关键决定一：时间线是资产，不是任务中间件。**

现在的 `cuts.json` 在 `work/` 里，是"这次任务干了什么"的记录。
时间线是"这个视频该怎么剪"的**意图** —— 它得活得比任务久。
所以它进素材库（`kind=timeline`，`.json` 已经归到这一类），有自己的 id、名字、血缘。

**关键决定二：改数据比拖时间轴优先。**

拖拽时间轴体验好，但（a）工作量大几倍，（b）在"单文件无构建 SPA"的约束下更难做好，
（c）**最要紧的是先验证"改数据"这条路好不好用** —— 如果改数据本身不顺手，拖拽也救不了。
所以第一版是**表格 + 预览帧**：一行一个保留区间，改秒数、删行、合并。

**关键决定三：重渲染从源视频重剪，不从旧成片剪。**

从成片再剪一次会**叠加压缩损失**，而且字幕已经烧进去了 —— 改字幕就没意义了。
所以重渲染 = 用源视频 + 新时间线，跑一遍"剪裁 → 烧字幕"。这也让"改字幕"真的生效。

**关键决定四：字幕存「源时间轴」，成片时间轴由 `keep` 现推。**

成片时间轴是 `keep` 的**函数**。如果把字幕也存成片轴，那么**每次改 `keep` 都要把字幕
重映射一遍** —— 而重映射正是最容易出错的环节（边界、跨段、取整），一旦算错就是
"字幕和嘴对不上"。存源轴则相反：改 `keep` **完全不碰字幕**，
"字幕跟着剪点走"不是一条要实现的规则，而是**结构上自动成立**的事实。

代价只有一次：粗剪的 ASR 是在**剪后视频**上跑的（成片轴），
产出时间线时要把它映射回源轴一次 —— 这一处转换必须有测试盯着。

**其它骨架决定：**

- 校验分两层：**结构**（区间在源时长内、有序、不重叠、非空）与**语义**（至少保留一段）
- 预览帧复用现有的 `rc.preview_frame`（它本来就按 srt 定位到某一秒抽帧）
- 重渲染走**任务化**（复用 M8）：它是分钟级的，必须能看进度、能取消、**能断点续跑**

## 6. Out of Scope（本版不做）

- **拖拽时间轴 UI**（见关键决定二）—— 表格够用就先表格
- **导出剪映草稿 / FCPXML / EDL** —— 先做自己闭环，互通是下一期
- **分镜 / 镜头切分 / 音轨编辑** —— 用户明确只选了"剪点 + 字幕"
- **多轨 / 叠加 / 转场 / 变速** —— 那是 NLE，不是本模块
- **从时间线改参数重跑粗剪**（比如"再松一点"）—— 那是粗剪的事，本模块只改结果
- **时间线的版本历史 / 撤销** —— 先不做，改坏了可以从粗剪重来
