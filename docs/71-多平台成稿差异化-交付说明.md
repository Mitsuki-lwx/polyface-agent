## 一、起因与基线（2026-11-01 真实样本）

2026-11-01 进行第一次全流程真实产出（素材：内容复用长文 `2.txt`，约 1900 字，分发至公众号、小红书、知乎），发现三个结构性问题：

1. **高逐字重合**：两两逐字重合达 30%~33.3%，且有 3 句核心金句在三篇中完全一字不差共用：
   - 「你缺的不是灵感，是一条能重复跑的流水线」
   - 「没有母体，后面拆出来的都是碎渣」
   - 「内容复用不是偷懒，是让好内容多活几次」
   更讽刺的是素材原文自述「别原封不动搬运，同一段话发5个平台只会让人觉得你敷衍」，产品却恰恰做了被禁止的事。
2. **篇幅严重倒挂**：公众号长文仅 399 字，少于小红书短图文的 498 字（长文平台字数最少）。
3. **平台格式项缺失**：小红书缺话题标签、公众号缺结构化小标题、知乎缺首句结论先行。

## 二、架构改动与实现

```
                      [输入素材: 1900字]
                             │
                             ▼
                    ┌─────────────────┐
                    │  app/pipeline   │
                    │   generate()    │
                    └────────┬────────┘
                             │
       ┌─────────────────────┼─────────────────────┐
       ▼                     ▼                     ▼
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  ① 微信公众号 │      │   ② 小红书   │      │   ③ 知乎回答  │
│  (长文平台)   │ ───► │(已用句子注入) │ ───► │(全量已用注入) │
└──────┬───────┘      └──────┬───────┘      └──────┬───────┘
       │                     │                     │
       └─────────────────────┼─────────────────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │ app/pipeline    │
                    │ diffcheck.py    │
                    │   evaluate()    │
                    └────────┬────────┘
                             │
                             ▼
              【跨平台】逐字重合 / 篇幅倒挂 / 格式检查
              自动并入各平台 qa.warnings（前端审阅直接呈现）
```

1. **`app/pipeline/diffcheck.py`**：
   - 切句与归一：标点+换行切句，过滤 <12 字碎片，去除空格、标点及阿拉伯数字（避免实词受干扰）。
   - 篇幅窗口与倒挂判定：从 DNA 读取 `body_chars` 窗口；判定长文平台（公众号）不得低于短图文（小红书/抖音）× 1.5 倍。
   - 必备格式规则化：小红书话题标签 ≥5、公众号分段小标题 ≥3、知乎首句结论先行（≤60字且无虚泛铺垫词）。
2. **`app/pipeline/prompts.py`**：
   - 在 `build_draft_skeleton_prompt` 的 `writing_rules` 中注入篇幅窗口要求、平台必备格式规则。
   - 在多平台同发时，将前序成稿提取的句子列表 `already_used_sentences` 显式注入后续 prompt，要求必须变换表达、句式与切入角度，同时严格要求保留事实与数据。
3. **`app/pipeline/generate.py`**：
   - 串行链路中动态累积 `_used_sentences()`，按长度排序截断至 60 句最易被照抄的长句。
   - 生成完成后执行 `diffcheck.evaluate()`，将跨平台差异化问题以 `【跨平台】` 前缀写入每个稿件的 `qa.warnings`，落盘保存，无需侵入修改 Java 侧数据契约，前端「③ 成稿审阅」界面自然直接呈现。
4. **`app/config.py`**：
   - 新增 `diff_max_overlap`（默认 0.10）与 `diff_length_ratio`（默认 1.5），支持通过环境变量灵活调优。

## 四、真实成稿片段对比

### 1. 知乎首句（结论先行）
- **旧产出**：`内容复用不是一稿多投，也不是把同一段话复制到五个平台。真正的复用，是把同一个核心信息...`（多句铺垫）
- **新产出**：`先给结论：内容复用不是把同一段话搬去更多平台，而是让母体内容在不同场景里重新出场。`（直截了当，符合知乎高赞回答体）

### 2. 公众号排版（小标题体系）
- **旧产出**：无任何 markdown 小标题，通篇纯文字堆叠。
- **新产出**：
  - `## 先建母库，再谈拆解`
  - `## 拆成能独立发布的内容`
  - `## 2 小时怎么排：4 个番茄钟`
  - `## 几个容易踩的坑`
  - `## 写在最后`

### 3. 小红书标签
- **旧产出**：仅落在 `draft.tags` 字段，正文完全缺失。
- **新产出**：结构化与正文标签共 6 个垂直/场景标签（`#内容运营` `#内容复用` `#自媒体干货` `#创作者成长` `#小红书运营` `#效率提升`）。

## 五、诚实边界与未达标项说明

根据本次真实生成 `data/e2e-diff-result.json`，系统质检机制如实检出并报告了以下 4 项告警：

1. **`gzh∩xhs = 30%` 仍偏高**：
   - 根因分析：公众号和小红书重合的句子集中在素材中的**硬性实测事实清单**：`拆成 1 篇公众号、3 条小红书图文、2 条短视频口播、1 条知乎回答、1 条社群分享、1 张清单海报、1 封邮件，合计 10 条内容，熟练后 2 小时能完成一轮` 与 `小红书负责收藏，短视频负责钩子，知乎负责搜索长尾，社群负责信任，邮件负责回流`。
   - 权衡（Trade-off）：在设计原则中，**事实与数据必须保留，不得为了降重而编造虚假数字**。后续可引导模型在短图文中用表格/符号压缩表现事实清单，而非长句罗列。
2. **`gzh∩zhihu = 12.5%` 略高于 10% 阈值**：
   - 同样来自于素材中番茄钟时间块与封面尺寸数据（1242×1660）的直接引用，表达层基本已分化。
3. **三篇同时出现的句子剩余 1 句**：
   - `最容易踩的坑，是原封不动搬运`。相比之前的 3 句已经大幅收窄，但这一句属于反例金句，模型容易作为避坑共识引用。
4. **公众号正文 742 字低于窗口下限 800 字**：
   - 虽然从 399 字大幅拉升至 742 字（消除了篇幅倒挂），但离 800 字下限仍有 58 字微小差距。质检器忠实报告，为创作者提供了针对性补足提示。
