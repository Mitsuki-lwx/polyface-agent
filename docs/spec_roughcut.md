# spec —— 口播粗剪：去长停顿 + 烧字幕

版本：2026-10-06　　对应 tasks：`docs/tasks_roughcut.md`　　验收：`docs/checklist_roughcut.md`

---

## 1. 背景

拍口播视频的人有一个共同的体力活：**录像里全是"死气"** —— 想词时的沉默、句子之间过长的停顿、
说错了重来的空白。这些不剪掉，成片节奏就拖。

剪它们不需要审美判断，只需要耐心：听一遍、找到沉默、切掉、再听一遍。
**这正是 AI 该替人做的那类事** —— 规则明确、错了肉眼可见。

而字幕更纯粹是体力活：把说的话一个字一个字打上去，还要对时间轴。

现状：项目已有 `剪辑单`（给抖音/B站成片的文字建议）和 `音视频入料`（视频→文字），
但**没有一步是把视频真的剪出来**。

## 2. 目标用户

**现阶段只有作者本人**：一个会写稿、会拍口播、但不想为剪辑学一套软件的人。

明确不服务陌生人 —— 因此**不做**安装引导、跨平台脚本、降级打磨。
（将来若要给别人用，那是另一个 spec。）

## 3. 能力清单（一句话一条）

1. 给一个本机视频文件，产出一个**剪掉长停顿**的视频
2. "多长的沉默算停顿"**可调**（不同人口播习惯差别很大）
3. 对**剪后**的视频自动转写，产出带时间戳的字幕
4. 把字幕**烧进画面**（中文、适合竖屏口播的样式）
5. 同时导出一份**独立字幕文件**（供后续拿去别的工具精修）
6. 打印一份**"剪了什么"的摘要**：剪了几段、各在哪、剪掉多少秒、剪后时长
7. 前置条件不满足时**大声失败**：文件不存在 / 没有音轨 / 缺 ffmpeg / 缺 ASR —— 明确报错，绝不静默产出一个坏视频

## 4. 非功能要求

- **全程本地**：不上传任何数据；ASR 用本地模型（沿用 ADR-017 的数据边界）
- **不引入云服务**，不引入 Node
- **速度**：一条 1 分钟以内的口播视频，端到端应在几分钟内完成（实测 ASR 约 0.2x 实时）
- **可单独重跑某一步**：中间产物落盘保留，调参时不必从头再来
- **确定性**：同一输入 + 同一参数 → 同样的剪点（不引入随机性）

## 5. 设计骨架

```
探测 → 找停顿 → 剪 → 转写 → 出字幕 → 烧字幕 → 出报告
```

**关键决定：先剪，再转写。**

为什么这条重要：如果先转写再剪，字幕的每个时间戳都必须**重新映射**到剪后的时间轴上
（剪点之前的偏移、之后的累加），这是一整块容易写错的逻辑。
反过来先剪再转写，时间戳**天然就是剪后时间轴上的**，映射逻辑直接消失。

其它骨架决定：

- **剪的动作交给 ffmpeg**（一条表达式搞定所有剪点），不自己解码/编码视频
- **ASR 复用项目已有的本地转写适配层**，只补一个"要时间戳"的入口
- **字幕渲染交给 ffmpeg 的 libass**，不自己画字
- **中间产物保留**（找停顿的结果、剪后视频、字幕文件），因为调参是主要使用场景

## 6. Out of Scope（本版不做）

- **去口癖/重复词**（"呃"、"然后然后"）—— 需要词级时间戳，是另一个能力
- **背景音乐存在时的"伪静音"**：有 BGM 的素材里没有真正静音，本版不处理（会如实报"没找到停顿"）
- BGM 卡点、转场、封面帧、画面美化
- 横屏转竖屏 / 改分辨率 / 改码率（**保持原样，只剪时长**）
- 多轨、多机位、批量处理
- 接进 Web 工作台（先把脚本跑顺）
- 剪点的手动微调界面
- 跨平台验证（只在 Windows 本机验）
