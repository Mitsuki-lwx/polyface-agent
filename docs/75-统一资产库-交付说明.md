```
→ 20/20（连续 3 轮）
```

**三件事因此被证明**：

1. **内容寻址真的去重**：同字节、不同文件名的两份文件 → 库里两条记录、**同一个 sha256**、
   **磁盘只有一份文件**。
2. **删除语义是"安全"的**：删掉被 draft 引用的资产 → 记录没了、**文件留着**；
   同 sha 的最后一条记录被删时，文件才真的消失。**绝不静默删用户文件。**
3. **登记是自动的**：生成封面后素材库里自动出现该图，且 `links` 已指向对应 draft ——
   用户不需要"记得去存"。

## 3. 设计要点

| 决定 | 理由 |
|---|---|
| **内容寻址 `assets/<sha前2>/<sha>.<ext>`** | 去重变成免费副作用；"这份素材库里已有"以后零成本实现 |
| **不搬既有文件** | 移动用户文件是**破坏性操作**，收益只是目录好看。`rel_path` 记相对路径，两种布局并存 |
| **`material` 表不迁移** | 它与 draft/facts/effects 深度耦合、测试充分；搬家高风险低收益（ADR-021 决策 1） |
| **`url` 复用 `/api/media/**`** | M6-1 已交付并测过（含防穿越）；**不新开 raw 端点**，少一份要维护的代码 |
| **sha256 流式计算** | 视频可达数百 MB，整份读进内存是不可接受的 |
| **宽高尽力而为（ImageIO）** | 不引入新依赖；webp/svg 探不到就记 0，不假装能探 |
| **登记失败只 warn** | 登记是**附加价值**，不能因为它挂了导致封面生成/入料失败（有专门的注入失败用例） |

## 5. 覆盖与未覆盖

**本次覆盖**
- 内容寻址落盘与去重（同字节 → 一份文件）
- 上传白名单（白名单外 400、空文件 400、不留残骸）
- 列表：kind 多值、name 模糊、limit 夹紧到 200、offset
- `url` 逐段编码（**含空格路径**的往返：`covers/draft 1/cover.png` → `/api/media/covers/draft%201/cover.png` 且能取回原字节）
- 删除三态 + sha 为空时**永不删文件**（保守）
- 自动登记（封面→image/generated + link draft；入料→video|audio/upload）+ **登记失败不影响主流程**
- 前端：面板、类型筛选、搜索（防抖）、上传、缩略图、非图片资产的图标+体积、删除二次确认、关联数、空态

**未覆盖（显式声明）**

| 项 | 原因 |
|---|---|
| **时间线资产的实际产出** | `kind=timeline` 只占位；M10 粗剪才会写入 |
| `duration_sec` | 恒为 0 —— ffprobe 在 Python 侧，接线属后续任务 |
| **视频/音频缩略图** | 要 ffmpeg 抽帧，本里程碑只给图标 + 体积 |
| webp / svg 的宽高 | `ImageIO` 读不到 → 记 0（不假装能探） |
| 素材库与「素材历史」的**合并视图** | 刻意不合并（ADR-021）；两者语义不同 |
| 大文件（>500MB） | 沿用既有 multipart 上限 |
| 真 macOS / Linux | 本机 Windows |

## 6. 观察（**不是缺陷**）

| 观察 | 判定 | 说明 |
|---|---|---|
| 同一份文件重复上传会生成**多条记录**（指向同一 sha） | ✅ 设计如此 | 名字/来源/标签可以不同；删到最后一条才动文件 |
| 资产的 `name` 是**草稿标题**（不是素材标题） | ✅ 设计如此 | `CoverController.deriveTitle` 的语义；写 E2E 时踩过一次，已记在脚本注释里 |
| 列表按 `id DESC` | ✅ | 新上传的在最上面，符合"我刚传的东西要看得见" |

## 7. 复现方式

```bash
# 1) 起服务（Python 用 mock 隔离变量）
cd python-service
LLM_MOCK=true POLYFACE_GIMPISH=<gimpish 入口> POLYFACE_DATA_DIR=<scratch> \
  .venv/Scripts/python.exe -m uvicorn app.main:app --port 18000

bash scripts/mvn.sh -B -f java-backend/pom.xml package -DskipTests
POLYFACE_DATA_DIR=<scratch> POLYFACE_LLM_BASE_URL=http://127.0.0.1:18000 \
  java -jar java-backend/target/polyface.jar --server.port=18082

# 2) 端到端
BASE=http://127.0.0.1:18082 POLYFACE_DATA_DIR=<scratch> \
  python-service/.venv/Scripts/python.exe scripts/e2e_assets.py

# 3) 老库升级验证（复制既有库，不碰原文件）
mkdir -p /tmp/old && cp data/polyface.db /tmp/old/
POLYFACE_DATA_DIR=/tmp/old POLYFACE_LLM_BASE_URL=http://127.0.0.1:18000 \
  java -jar java-backend/target/polyface.jar --server.port=18083
curl -s http://127.0.0.1:18083/api/assets      # → items 为空（新表已建）
curl -s http://127.0.0.1:18083/api/materials   # → 旧数据完好
```
