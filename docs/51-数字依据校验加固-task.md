# 数字依据校验加固（FR-60）— task

日期：2026-09-17 · 前置：无（纯缺陷修复）· 关联：FR-60（质检）、`docs/38`（质检加固）、`docs/33`（DNA v2）

---

## 1. 起因（真实模式发现，非推测）

本项目**第一次真实 LLM 端到端**（`scripts/e2e_real_llm.py`，2026-09-17）通过 14/14，
但真实产出暴露出规则质检的一处缺陷 —— 一份**完全干净、无虚构数字**的小红书成稿，
刷出 **4 条假告警**：

```
QA warn: 正文含素材中无依据的数字: 0
QA warn: 正文含素材中无依据的数字: 1
QA warn: 正文含素材中无依据的数字: 2
QA warn: 正文含素材中无依据的数字: 3
```

而正文里 `1. / 2. / 3.` 是**分点序号**，`0` 明明在素材里（"从月入0做到3万"）。

**这是 mock 模式永远测不出来的**：mock 的成稿是固定文本，不含分点结构。

## 2. 为什么必须修（不是"小瑕疵"）

1. **分点/分步列表是 DNA 明确推荐的小红书结构**（`docs/31`/`platform-dna/xiaohongshu.yaml`
   `structure_template`）。也就是说：**写得越规范，假告警越多**。
2. **假告警会淹掉真告警**。同一次运行里，规则质检之外的 LLM 质检**真的抓出了实质问题**
   （标题「裸辞1年」的「1年」素材中无依据、标题1 属悬念式表述并引用了社区规范 4.1.3）。
   但用户先看到 4 条噪声，很可能就不再往下读了。
3. **这正是本项目一直在防的失败模式**：`docs/38` 修的是"误报通过"，`docs/48` 修的是
   "误报失败"（假的红灯），这里是第三种同族缺陷 —— **误报告警**。
   `docs/50` 的第三关要量"事实错误数"，噪声会直接污染该指标。

## 3. 目标

让"无依据数字"告警**只在真有依据问题时出现**，且**不放过**真正的无依据数字（含 `3w` 这类简写）。

## 4. 边界

**In**
- 修数字提取的边界判定（中文语境下 `\b` 失效问题）
- 排除"分点/序号"标记，不当作事实数字
- 补上 `w/W` 作为「万」的简写（既有的 `[%％万kK亿]` 漏了它）
- 多条同类告警合并为一条（降噪）

**Out（明确不做）**
- 不改"无依据数字 = warning 而非阻断"的既定决策（`docs/36` spec Q1 已定，本次维持）
- 不做"数字是否合理/是否夸大"的语义判断（那不属规则层能力，交 LLM 质检）
- 不动 LLM 质检（`_llm_qa`）的判定逻辑
- 不引入新依赖

## 5. 任务拆分

| # | 任务 | 产出 |
|---|---|---|
| T1 | 复现：固定一段含分点序号 + 中文邻接数字的文本，确认三类缺陷 | 复现脚本输出 |
| T2 | 修 token 提取：用数字 lookaround 取代 `\b`，并归一化 `w/W`→`万` | `_NUM_RE` + 归一化函数 |
| T3 | 剥离分点标记后再提取 | `_LIST_MARKER_RE` |
| T4 | 告警合并为一条 | `_rule_qa` |
| T5 | 回归测试：正向（真无依据要抓）+ 反向（分点序号/中文邻接/简写不得误报） | `tests/test_num_basis.py` |
| T6 | 真实样本回放：用 2026-09-17 那条真实成稿验证告警由 4 条 → 0 条 | 回放输出 |
| T7 | 重跑真实链路 E2E，确认无回归 | `scripts/e2e_real_llm.py` |

## 6. 依赖与前置

- 无代码依赖。T6/T7 需要**上游额度**（`glm-5.2` 本次可用；`deepseek-v4-flash/pro`、
  `sensenova-6.8-flash-lite` 当时均 429）。
- T7 若因额度失败，按惯例**显式标注未验证**，不得记为功能缺陷。

## 7. 风险

| 风险 | 应对 |
|---|---|
| 剥离序号规则过宽，误删真实数字（如"营收 3. 5亿"被当序号） | 只认 1~2 位数 + 序号标点 + 后接空白/行尾；测试覆盖真实年份/金额不被误删 |
| 归一化 `w`→`万` 引入新误判（如英文单词含 w） | 仅对**紧跟数字**的单个 `w/W` 生效 |
| 合并告警丢失信息 | 合并后仍列出全部数字；单数字时输出与原先一致（保证既有测试不破） |
