# 服务崩溃可观测 —— 交付说明

> 对应 openspec change：`openspec/changes/service-crash-forensics`
> 关联：`docs/68`（人机共创）、ADS-001 / ADR-027（准入闸门，未改动）

## 一、起因（不是假设，是实测）

2026-10-31，Python 服务进程以 `0xC0000409`（`STATUS_STACK_BUFFER_OVERRUN`）退出：

```
INFO:     ... "GET /favicon.ico HTTP/1.1" 404 Not Found
<进程消失，之后什么都没有>
```

日志里**没有 traceback、没有 dump、没有退出码**。勘察后确认这条链路每个环节都在漏：

| 现状 | 后果 |
|---|---|
| 无 `faulthandler` / 信号处理器 / `atexit` | 原生崩溃零证据 |
| `scripts/start.sh` 末尾是裸 `wait` | 一个服务死了，脚本安静地等另一个 |
| 产品侧不记子进程退出码 / pid | 事后只能考古 |
| `doctor.py` 只查环境，不查存活 | 用户看到的是"点了没反应" |

## 二、做了什么

1. **`python-service/app/lifecycle.py`**
   - `enable_crash_log()`：`faulthandler.enable(file=<文件>)`，**追加**模式、行缓冲、幂等；失败只告警（取证不能拖垮服务）。
   - `log_startup()` / `log_shutdown()`：pid、python 版本、端口、argv、退出码。
   - `POLYFACE_CRASH_LOG` 可覆盖路径；默认 `<数据目录同级>/logs/crash-python.log`。
2. **`main.py`** 在 `app = FastAPI(...)` **之前**挂上（导入期就生效）。
3. **`scripts/start.sh`**：裸 `wait` → `wait -n` 逐个等；任一退出**指名道姓**报出并收掉另一个；老 bash 退回轮询。
4. **`scripts/start.bat`**：打印三份日志路径 + 说明"窗口报错/关闭 = 该服务停了"。
5. **`scripts/doctor.py`**：新增「服务存活」两项 —— **真的打一次请求**（非阻塞提示）。

## 三、实测结果（都是真跑出来的）

### 3.1 `faulthandler` 抓得到原生崩溃 ✓

| 崩溃方式 | 退出码 | 崩溃日志 |
|---|---|---|
| `os.abort()`（真 SIGABRT）| 3 | `Fatal Python error: Aborted` + 栈 |
| ctypes 空指针（访问违例）| 1 | `Windows fatal exception: access violation` + 栈 |

**反例（诚实记录）**：`os.kill(pid, SIGABRT)` 在 Windows 上等价 `TerminateProcess` —— **硬杀，谁都接不住** ✗，那种情况只能靠脚本记退出码。

### 3.2 半死状态被看见 ✓

起 `start.sh` → `taskkill /F` 掉 Python → 脚本输出：

```
[已退出] Python LLM 服务（退出码 1）
日志：D:\media works move\polyface\logs\python-service.log
其余服务将被停止。请查看日志定位，再用 start.sh 显式重启。
```

随后 Java 被收掉、两个端口清空、脚本非零退出 ✓。

### 3.3 `doctor` 三态 ✓

服务没起时输出 `[提示] Python LLM 服务（存活）: 未运行 / 不可达（URLError）—— 启动前体检时这是正常的；…`（非阻塞）；
单测覆盖：都活 / 死一个（含日志路径与重启提示）/ 都不活 / **4xx-5xx 算活着**（有响应 ≠ 进程死了）。

## 四、踩到的两个坑（都写进代码注释了）

`start.sh` 开着 `set -euo pipefail`，而 **`wait -n`** 与 **`wait <pid>`** 在子进程异常退出时都返回非零 ——
第一次改完，"已退出"那句话**根本没打印**，脚本直接跳出 ✗。两处都必须显式接住状态码才正确。

## 五、未验证 / 不确定（报忧）

1. **`scripts/start.bat` 未经实机运行验证** —— 本环境拦 `cmd.exe`。已做：逻辑对齐 + CRLF 行尾（115 处 LF 曾导致 `cmd.exe` 解析出错，已修）+ `scripts/check_scripts.py` 零问题。
2. **`0xC0000409` 的根因仍未定位** —— 标记 `needs-validation`。本 change 只保证"下次发生时能留下栈和退出码"。已知线索：崩溃前最后一条请求是 `GET /favicon.ico 404`，进程已运行约 24 分钟，同进程内启用着 Langfuse 后台导出与 httpx 客户端。
3. `faulthandler` 对 `0xC0000409` 这类 **fail-fast** 是否抓得到栈 —— **未验证**（没有复现路径）。已按"不押宝"处理：即使抓不到，退出码与"哪个服务退了"仍由脚本保证。
