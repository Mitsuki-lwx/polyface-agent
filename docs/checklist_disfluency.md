# checklist —— 口播去冗余

spec：`docs/spec_disfluency.md`　　tasks：`docs/tasks_disfluency.md`

每一项都可勾选、可观测。**默认值 ≠ 写死的值**：每条可调参数都要有一条"改了它，行为确实变了"。

---

## 1. 词级转写（T1）

- [x] 返回的 words 非空，且 `start`/`end` 单调递增（无逆序）
- [x] words 覆盖的区间与段级时间戳一致（首尾差 < 0.5s）
- [x] 没有词级时间戳的 ASR 后端 → **明确报错**，不是静默返回空 words

## 2. 规则判定（T2/T3）

- [x] 完全重复的相邻两句 → 标出后一句，`kind=repeat`
- [x] 半句重起（「我们今天要讲的」→「我们今天要讲的是」）→ 标出前一句，`kind=restart`
- [x] 口头语独立成词（「那个」单独出现）→ 标出，`kind=filler`
- [x] **口头语不误伤**：「那个人」「那个年代」里的「那个」**不被标**
- [x] 换措辞的重说 → 标为**低置信**（留给模型复核），不是直接剪
- [x] 两件不同的事（相似度低于阈值）→ **不标**
- [x] 每条判定都带 `evidence`（相似度数值 / 命中的词 / 前后句原文）
- [x] 改相似度阈值 → 标出的条数确实变化

## 3. 模型复核（T4）

- [x] 模型返回"是"→ 该段标为重复且 `source=llm`
- [x] 模型返回"否"→ **不标**（模型可以否决规则的疑点）
- [x] 模型抛异常/超时 → `llm_skipped=true`，**流程继续**（降级到纯规则），报告里标明
- [x] 发给模型的内容**只包含可疑句对**，不含全文（可观测：请求体的长度/句数）
- [x] 模型返回里**没有时间戳**（时间戳一律由程序从原句对取）—— 防模型瞎编时间

## 4. 剪点合并（T5）

- [x] 重叠的冗余/停顿区间 → 合并后**不重复**
- [x] 相邻（间隔小于 1 帧）的区间 → 接上
- [x] 低于最短时长的片段 → 丢弃（可观测：报告里不计入）
- [x] 边界回退后**不侵入语音**（回退到语音边界 + 余量）
- [x] 合并后剪点按时间**升序**排列，无交叠

## 5. 参数（T6）

- [x] 四类**各有独立开关**，关掉某类 → 该类不再出现在方案里
- [x] 口头语词表**在配置文件里**，改它 → 判定结果变
- [x] 命令行参数**覆盖**配置文件
- [x] 不填任何参数 → 用内置默认，能跑通
- [x] `grep` 代码：没有任何一个可调值是**只能改代码才能变**的

## 6. 落盘与可解释（T7）

- [x] 判定结果落盘（区间/类别/依据/来源）
- [x] 同一输入重跑，**不重新转写**（可观测：第二次耗时显著短）
- [x] 报告逐条列出"剪了哪几段 + 为什么 + 来源（规则/模型）"
- [x] 报告汇总：各类剪了几段、共剪多少秒、剪前/剪后时长

## 7. 接入主流程（T8）

- [x] 发起粗剪 → 方案里**同时**含停顿与冗余剪点（一份清单，不是两次剪）
- [x] 方案里每条冗余都能看到**理由**
- [ ] 确认后成片；改参重算 → 方案确实变
- [x] 非交互模式一键跳过确认，能跑通
- [ ] UI：粗剪面板能开关四类，能看理由列表

## 8. 安全底线（**最重要**）

- [x] 冗余判定**只剪连续语音内部**的片段，绝不剪掉整段开头/结尾的独立内容
- [x] 边界回退**宁可少剪**：剪错一句话的代价 > 多留 0.3 秒
- [x] 误剪可复核：报告能定位到"剪掉的那段原文是什么"
- [x] 中间产物保留 → 误剪后能改参重跑，不必重拍

## 9. 端到端（T9，**必须真素材**）

- [ ] 一份真实口播素材（含停顿 + 口误 + 重复 + 口头语）→ 走完整链路出成片
- [ ] 四类各自抓到 ≥1 处（若素材里确实有）
- [ ] **误剪的逐条列出**（报忧不报喜）
- [ ] 剪点边界听感正常（无半个字被剪、无爆音）
- [ ] 原始输出（方案/报告/时长）贴进本文件
- [ ] 全程本地（除模型复核那一步的文本外）

## 实机验证记录（2026-10-17，真实 ASR + 真实 ffmpeg）

### 素材

原始素材找不到（`data/e2e-loop` 里的视频都是粗剪**产物**，已剪干净 → 0 停顿 0 冗余，
没有区分度）。改用 **SAPI 合成一份带已知埋点的素材**（ground truth 比真素材更硬）：

| 埋点 | 内容 | 预期 |
|---|---|---|
| 口头语 | 嗯（两侧 600ms 停顿） | 标出 |
| 口头语 | 那个（两侧 500/400ms） | 标出 |
| 半句重起 | 「今天我要讲的是,」→「今天我要讲的是三个方法。」 | 标前一句 |
| 完全重复 | 「这个方法我用了很久。」×2 | 标后一句 |
| 自我纠正 | 「这个数据是去年的。」→「不对，我是说前年的。」 | 标前一句 |

### 结果（`--dry-run`，32.16s 素材）

```
[   2.90 –    4.26s] 半句废弃 · 来源规则   ✓ 命中
[  11.84 –   13.74s] 重复句   · 来源规则   ✓ 命中
[  15.06 –   16.62s] 自我纠正 · 来源规则   ✓ 命中
[  23.62 –   23.96s] 口头语「那个」· 规则  ✓ 命中
合计 4 段，共 5.16s
停顿 11 段 + 冗余 4 段 → 合并后 12 段（相邻的并成一段，实测 2.90–4.26 与 2.98–4.18 并了）
剪掉共 16.40s：32.16s → 15.76s（省 51.0%）
```

- **命中 4/5，误剪 0 条**（"嗯"那条：ASR 把它听成了"文"，转录里根本没有 → 抓不到，
  这是 ASR 的锅不是规则的锅）
- 合并确实生效（冗余段与停顿段挨着 → 并成一段，不会留一小截画面）

### 实测中发现并修掉的三个缺陷（都只有跑真实 ASR 才会露出来）

1. **规则假设"一段 = 一句话"** ✗ —— ASR 的段是**按停顿切的**，一个段常装着两句话
   （实测 `[1]` = 「这个方法我用了很久。这个方法我用了很久。」）→ 重复句/半句重起
   全在段内部，配对规则一条都抓不到（**首轮 5 类埋点只命中 1 类**）。
   修：新增 `split_sentences`，用词级时间戳里的标点切句。
2. **口头语 token 带标点** ✗ —— 词级时间戳给的是 `那个,`，词表里是 `那个` → 永远匹配不上。
   修：匹配前先归一化。
3. **纠正信号自己被判成"被废弃的句子"** ✗ —— 切句后「不对,」自成一个句子，
   紧接着「我是说前年的。」又命中引导词 → 把"不对"剪掉了。而"不对"是**纠正的标记**，
   剪了它观众就不知道后面在纠正什么。修：上一句本身就是引导词时跳过。

- 长素材耗时：实测 32s 素材的**去冗余**阶段 28~33s（约 1x 实时，比 spec 里写的
  0.2x 慢 —— 因为它要的是**词级**时间戳，比段级贵）。两遍 ASR 让端到端更慢，
  这是 spec §5 里记下的已知代价。
