# checklist —— 口播去冗余

spec：`docs/spec_disfluency.md`　　tasks：`docs/tasks_disfluency.md`

每一项都可勾选、可观测。**默认值 ≠ 写死的值**：每条可调参数都要有一条"改了它，行为确实变了"。

## 1. 词级转写（T1）

- [x] 返回的 words 非空，且 `start`/`end` 单调递增（无逆序）
- [x] words 覆盖的区间与段级时间戳一致（首尾差 < 0.5s）
- [x] 没有词级时间戳的 ASR 后端 → **明确报错**，不是静默返回空 words

## 2. 规则判定（T2/T3）

- [x] 完全重复的相邻两句 → 标出后一句，`kind=repeat`
- [x] 半句重起（「我们今天要讲的」→「我们今天要讲的是」）→ 标出前一句，`kind=restart`
- [x] 口头语独立成词（「那个」单独出现）→ 标出，`kind=filler`
- [x] **口头语不误伤**：「那个人」「那个年代」里的「那个」**不被标**
- [x] 换措辞的重说 → 标为**低置信**（留给模型复核），不是直接剪
- [x] 两件不同的事（相似度低于阈值）→ **不标**
- [x] 每条判定都带 `evidence`（相似度数值 / 命中的词 / 前后句原文）
- [x] 改相似度阈值 → 标出的条数确实变化

## 3. 模型复核（T4）

- [x] 模型返回"是"→ 该段标为重复且 `source=llm`
- [x] 模型返回"否"→ **不标**（模型可以否决规则的疑点）
- [x] 模型抛异常/超时 → `llm_skipped=true`，**流程继续**（降级到纯规则），报告里标明
- [x] 发给模型的内容**只包含可疑句对**，不含全文（可观测：请求体的长度/句数）
- [x] 模型返回里**没有时间戳**（时间戳一律由程序从原句对取）—— 防模型瞎编时间

## 4. 剪点合并（T5）

- [x] 重叠的冗余/停顿区间 → 合并后**不重复**
- [x] 相邻（间隔小于 1 帧）的区间 → 接上
- [x] 低于最短时长的片段 → 丢弃（可观测：报告里不计入）
- [x] 边界回退后**不侵入语音**（回退到语音边界 + 余量）
- [x] 合并后剪点按时间**升序**排列，无交叠

## 5. 参数（T6）

- [x] 四类**各有独立开关**，关掉某类 → 该类不再出现在方案里
- [x] 口头语词表**在配置文件里**，改它 → 判定结果变
- [x] 命令行参数**覆盖**配置文件
- [x] 不填任何参数 → 用内置默认，能跑通
- [x] `grep` 代码：没有任何一个可调值是**只能改代码才能变**的

## 6. 落盘与可解释（T7）

- [x] 判定结果落盘（区间/类别/依据/来源）
- [x] 同一输入重跑，**不重新转写**（可观测：第二次耗时显著短）
- [x] 报告逐条列出"剪了哪几段 + 为什么 + 来源（规则/模型）"
- [x] 报告汇总：各类剪了几段、共剪多少秒、剪前/剪后时长

## 7. 接入主流程（T8）

- [x] 发起粗剪 → 方案里**同时**含停顿与冗余剪点（一份清单，不是两次剪）
- [x] 方案里每条冗余都能看到**理由**
- [x] 确认后成片；改参重算 → 方案确实变
      **实测（2026-10-30，`--ask key` 交互确认，喂回车接受默认）**：
      ```
      确认后 → rc5.mp4 成片 ✓（剪掉 29.53s：49.12s → 19.59s）
      改参（--no-dedup-filler --dedup-similarity 0.95）→ 方案确实变：
        口头语那段**没了**（4 段 → 3 段），剪掉 29.34s（49.12s → 19.78s）
      ```
- [x] 非交互模式一键跳过确认，能跑通
- [x] UI：粗剪面板能开关四类，能看理由列表

## 8. 安全底线（**最重要**）

- [x] 冗余判定**只剪连续语音内部**的片段，绝不剪掉整段开头/结尾的独立内容
- [x] 边界回退**宁可少剪**：剪错一句话的代价 > 多留 0.3 秒
- [x] 误剪可复核：报告能定位到"剪掉的那段原文是什么"
- [x] 中间产物保留 → 误剪后能改参重跑，不必重拍

## 实机验证记录（2026-10-17，真实 ASR + 真实 ffmpeg）

### 素材

原始素材找不到（`data/e2e-loop` 里的视频都是粗剪**产物**，已剪干净 → 0 停顿 0 冗余，
没有区分度）。改用 **SAPI 合成一份带已知埋点的素材**（ground truth 比真素材更硬）：

| 埋点 | 内容 | 预期 |
|---|---|---|
| 口头语 | 嗯（两侧 600ms 停顿） | 标出 |
| 口头语 | 那个（两侧 500/400ms） | 标出 |
| 半句重起 | 「今天我要讲的是,」→「今天我要讲的是三个方法。」 | 标前一句 |
| 完全重复 | 「这个方法我用了很久。」×2 | 标后一句 |
| 自我纠正 | 「这个数据是去年的。」→「不对，我是说前年的。」 | 标前一句 |

### 结果（`--dry-run`，32.16s 素材）

```
[   2.90 –    4.26s] 半句废弃 · 来源规则   ✓ 命中
[  11.84 –   13.74s] 重复句   · 来源规则   ✓ 命中
[  15.06 –   16.62s] 自我纠正 · 来源规则   ✓ 命中
[  23.62 –   23.96s] 口头语「那个」· 规则  ✓ 命中
合计 4 段，共 5.16s
停顿 11 段 + 冗余 4 段 → 合并后 12 段（相邻的并成一段，实测 2.90–4.26 与 2.98–4.18 并了）
剪掉共 16.40s：32.16s → 15.76s（省 51.0%）
```

- **命中 4/5，误剪 0 条**（"嗯"那条：ASR 把它听成了"文"，转录里根本没有 → 抓不到，
  这是 ASR 的锅不是规则的锅）
- 合并确实生效（冗余段与停顿段挨着 → 并成一段，不会留一小截画面）

### 实测中发现并修掉的三个缺陷（都只有跑真实 ASR 才会露出来）

1. **规则假设"一段 = 一句话"** ✗ —— ASR 的段是**按停顿切的**，一个段常装着两句话
   （实测 `[1]` = 「这个方法我用了很久。这个方法我用了很久。」）→ 重复句/半句重起
   全在段内部，配对规则一条都抓不到（**首轮 5 类埋点只命中 1 类**）。
   修：新增 `split_sentences`，用词级时间戳里的标点切句。
2. **口头语 token 带标点** ✗ —— 词级时间戳给的是 `那个,`，词表里是 `那个` → 永远匹配不上。
   修：匹配前先归一化。
3. **纠正信号自己被判成"被废弃的句子"** ✗ —— 切句后「不对,」自成一个句子，
   紧接着「我是说前年的。」又命中引导词 → 把"不对"剪掉了。而"不对"是**纠正的标记**，
   剪了它观众就不知道后面在纠正什么。修：上一句本身就是引导词时跳过。

### 未验证 / 未做（如实列）

- **模型复核那一层没有真跑**（`dedup_review` 默认关）：单测覆盖了它的三条要害
  （只能否决、不给时间戳、挂了要降级），但**没有用真模型跑过一次**。
- ~~**界面未实测**~~ → **已实测（2026-10-17，浏览器）**：粗剪参数弹层里四类开关都在、
  默认值正确（四类开 / 模型复核关）；拦下真实提交看到请求体确实带上了全部开关，
  且值随勾选变化（只留"重复句"时其余三类为 false）。
  理由列表的渲染也**已实测**（第二轮：跑完一个粗剪任务，5 段理由 + 模型那一条都渲染出来了）。
- **Java 侧只到编译通过**：`RoughcutRunner` 的参数透传没有端到端跑过一次。
- 长素材耗时：实测 32s 素材的**去冗余**阶段 28~33s（约 1x 实时，比 spec 里写的
  0.2x 慢 —— 因为它要的是**词级**时间戳，比段级贵）。两遍 ASR 让端到端更慢，
  这是 spec §5 里记下的已知代价。

## 第二轮：把第一轮列的"未验证"逐条跑掉（2026-10-17）

第一轮结尾如实列了 4 条未验证。这一轮逐条验，**又逮到两个缺陷**。

### 缺陷 4（设计层面，最要紧）：**模型那一层够不到它本该抓的东西** ✗

量了真实相似度：

| 句对 | 相似度 |
|---|---|
| 「这件事情的核心是执行。」/「这件事的关键就在于落地。」 | **0.381** |
| 「这个项目做了一年。」/「这个项目我做了整整一年。」 | 0.842 |
| 「这个方法我用了很久。」/「这个方法我用了很长时间。」 | 0.800 |

**完全换措辞的重说只有 0.38** ✗ —— 而"送模型复核"原本是**由规则命中（≥0.72）触发的** ✗，
于是这类句子**规则标不出 → 模型也永远看不到** ✗。可"抓换措辞的重说"正是模型这一层存在的理由。

修：**两个门槛分开** —— 规则门槛 0.72（判为疑似）、复核门槛 **0.30**（值得让模型看一眼）。
0.30~0.72 这一段由模型裁决；模型说不是就不剪。

复验（真 LLM，走 Java 任务）：

```
llm_enabled: True  llm_called: True  llm_skipped: False  候选句对: 3
[30.78-33.30] 重复句 · 模型
  模型复核：这两句是同一件事说两遍 —— "核心"与"关键"、"执行"与"落地"意思对应，
  后一句换说法重复前一句。
```

### 缺陷 5：`.env` 只认 cwd → **模型复核在真链路里永远不可能成功** ✗

`SettingsConfigDict(env_file=".env")` 是相对**当前工作目录**的。而粗剪是由 Java 起 CLI 跑的，
cwd 是仓库根 → 读不到 `python-service/.env` → `LLM_API_KEY` 为空 →
`Missing credentials` → **静默降级成纯规则**（用户以为模型看过了）。

修：`config.py` 按**包的位置**解析 `.env`（`<repo>/python-service/.env`），与从哪启动无关。

### 也顺手修了一个歧义字段

`llm_reviewed` 原先只表示"开关开着"，会让人以为"模型复核跑过了"。
拆成三个：`llm_enabled`（开关）/ `llm_called`（真的调了）/ `llm_skipped`（调了但降级）。

### 界面：把"方案"真的摆到人面前

`dedup_url` 进任务产物 → 界面渲染出**逐条理由**（含来源"规则/模型"）。
浏览器实测：任务跑完后，5 段理由 + 模型那一条都正确渲染。

### 素材
`D:\media works move\data\real\[DLBunny.com][tiktok]未剪辑的口播素材来啦~…自学剪辑.mp4`
（文件名**带空格 + 中文 + 方括号** —— 顺带把 checklist 里"路径含空格/中文未验证"那条也验了）

```
64.76s · 1080×1920 竖屏 · h264 30fps + aac 44.1kHz 立体声 · 14MB · **带背景音乐**
mean_volume -13.6dB（电平正常）
```

### 结果：**0 段停顿 + 0 段冗余** —— 两个 0 的原因**完全不同**

**① 0 段停顿 = 产品限制（不是 bug）** ✗
门限降到 **-50dB 仍然 0 段静音** → 全程有 BGM。工具那句
「若素材里有背景音乐，本版不处理」**正好说中**。

> ⚠️ **这是目前最实际的缺口**：用户的真实口播素材**普遍带 BGM**，
> 而带 BGM 时粗剪**等于什么都不做**（0 剪点）。BGM 感知的停顿检测 = 需要人声分离，
> 不在本版范围内（spec 明确 Out of Scope），但值得单独排期。

**② 0 段冗余 = 正确判定** ✓
把 64.76s **全文转录读完**（35 句）核对：这位博主照着稿子顺读 ——
没有说两遍、没有起头重说、没有"不对我是说…"、没有独立成句的口头语。
所以 0 条是**对的**，不是漏判。

### 顺带排掉一个担心的误判（机制层面的收获）

盯了 `啊@2.72`（"我到底要去哪里找**啊**"）—— 两侧空隙 0.20/0.24 都超过 0.12 阈值，
按规则**本该被抓**。结果没抓，查清原因：

**真实 Whisper 的词级时间戳是连续的**（`找@2.52-2.72`、`啊@2.72-2.96` → 空隙 **0**），
只有**段与段之间**才有空隙。所以：
- 口头语**独立成段**时（真实场景最常见）→ 会抓 ✓
- 句尾语气词（"…找啊"）→ 不会抓 ✓ —— **这正是要的行为**

**合成素材（SAPI 带显式 break）会给词之间造出空隙**，所以那条路径验得过；
真实 ASR 不造空隙 —— 两者的差别就在这里，值得记下来。

## 本轮改动（2026-10-30）：同一段被报了两遍

验收 §9「四类各自抓到 ≥1 处」时发现：一条语音片段可能**同时**"像上一句"（`repeat`，
标在**后**一句）和"是下一句的半句重起"（`restart`，标在**前**一句）——
两者覆盖的是**同一段时间**，于是报告里同一段出现两遍、理由还不一样 ✗：

```
[ 14.01 – 17.97s] 重复句 · 来源规则（low 置信）  与上一句相似度 0.78 …
```
