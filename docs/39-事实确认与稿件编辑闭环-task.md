# 任务书：事实确认与稿件编辑闭环

- 文档类型：task（事前三件套之一）
- 版本：v1.0 · 日期：2026-09-15
- 关联：FR-20（素材理解）、FR-34（防幻觉/ADR-009）、FR-42（成稿）、FR-64（模板）、UC-03/04/05
- 前置：M5c + 质检加固（`docs/38`）已完成 ✅；09-14 独立评估认定**本任务是"修质检和事实确认闭环"的后半段**

---

## 1. 背景（评估报告指出的第 3 类问题）

> 「用户确认事实、编辑稿件的工作流没有闭合」

**具体缺陷（代码已复核确认）**：

| # | 缺陷 | 现状 |
|---|---|---|
| 1 | 事实清单**只能看，不能改** | 前端仅渲染文本；无增删改保存入口 |
| 2 | **生成时重复理解** | Java 只传 `raw_text`，Python `generate()` 再次跑 understand → **重复消耗一次额度**；且"解析时看到的事实"可能 ≠"生成时用的事实" |
| 3 | 稿件**不能编辑/保存** | 成稿面板只能复制；无正文编辑、无保存 |
| 4 | 稿件**不能导出** | 只有模板 JSON 导出，没有成稿 txt/md 导出 |
| 5 | **历史稿正文可能为空** | 列表接口只返回摘要，前端却直接交给需要完整 `draft/qa` 的渲染函数；缺少补读 `/api/drafts/{id}` |

**为什么重要**：这是**防幻觉（ADR-009）的地基**。用户核对过的事实若在生成时被丢弃、重新理解一遍，那么"事实约束"就只是心理安慰。同时它也是**省时**的关键——重复理解既慢又贵。

## 2. 目标

1. **事实可确认**：用户能增删改事实清单并保存；保存后的版本**明确标记为"已确认"**
2. **生成复用已确认事实**：已确认事实作为生成唯一依据，**不再重复理解**（省一次 LLM 调用）
3. **稿件可编辑保存**：正文/标题/标签可改并落库；改过的稿标记"人工编辑"
4. **稿件可导出**：txt / md
5. **历史稿能看全**：点历史稿正确显示完整正文
6. **不破坏既有能力**：未确认事实时行为与现在完全一致（向后兼容）

## 3. 范围

### In

| # | 事项 |
|---|---|
| 1 | DB 迁移：`material` 加 `facts_confirmed` / `facts_confirmed_at`；`draft` 加 `edited_at` |
| 2 | API：`PUT /api/materials/{id}/facts`（保存并确认事实） |
| 3 | API：`PUT /api/drafts/{id}`（保存编辑后的稿件） |
| 4 | API：`GET /api/drafts/{id}/export?format=txt\|md`（导出） |
| 5 | Java → Python：生成时传已确认事实；Python 有则**跳过 understand** |
| 6 | 前端：事实清单可增删改 + 保存确认；稿件正文可编辑 + 保存 + 导出；历史稿补读完整内容 |
| 7 | 测试：单元（Java + Python）+ 端到端（含浏览器实测） |

### Out

| 事项 | 原因 |
|---|---|
| 事实的自动抽取质量提升（证据片段定位） | 属"防幻觉深化"，独立任务 |
| 稿件富文本编辑（仅纯文本/Markdown） | 纯文本够用，避免引入编辑器依赖 |
| 单稿手动重跑 QA | 有价值但非闭环必需；可后续（本次先留接口位） |
| Java 180s 超时 / 内测版交付 / 真实作者验证 | 属评估报告其他条目，独立任务 |
| 事实的版本历史/回滚 | v1 只保留"当前确认版"，不做多版本 |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 破坏既有生成路径 | 回归 | 已确认事实为**可选**参数；无则走原路径；既有测试必须全绿 |
| DB 迁移影响既有数据 | 数据丢失 | 用 `ALTER TABLE ADD COLUMN`（既有惯例 `ensureXxxColumns`），不重建表 |
| 前端改动大 | 引入 bug | 浏览器实测（用户硬性要求）；小步提交 |
| 事实格式不一致 | 生成失败 | 复用既有 `StructuredMaterial` 结构，前端提交同构 JSON |
| 额度限制无法真实验证 | 未验证部分 | mock 全覆盖；真实链路尽力并**显式标注** |
