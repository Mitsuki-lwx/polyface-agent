## 1. 背景与问题

M3 交付的模板能力是"一次性表单"：用户在生成页填 名称/语气/开头/结尾，随请求一次性透传给 Python，**没有落库、没有列表、没有复用**。页面一刷新就丢，无法作为"用户资产"积累。

ADR-014 明确要求"模板存用户数据目录，支持导出/备份/开源共享；随稿记录模板版本号（可追溯）"，本任务补齐这部分。

## 2. 目标

把内容模板从"临时表单"升级为**可管理的本地资产**：

1. 模板落库，可长期保存与复用
2. 完整的增删改查（CRUD）+ 复制
3. 内置预置模板库（新用户零配置可用）
4. 导出/导入 JSON（备份、迁移、开源共享）
5. 生成时从模板库选择，**稿件记录所用模板 id + 版本号**（可追溯）

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| SQLite `ALTER TABLE ADD COLUMN` 非幂等 | 二次启动报 duplicate column | 启动前查 `PRAGMA table_info`，缺列才 ALTER |
| 删除被稿件引用的模板 | 稿件溯源断链 | 软处理：删除后 `template_id` 保留，展示为"模板已删除" |
| 导入文件与本地重名/格式非法 | 数据污染 | 导入时校验 schema；重名自动加后缀或按策略跳过 |
| 预置模板被用户误删 | 新用户体验退化 | `builtin=1` 拒绝删除（409），引导"复制为我的" |
| 旧 `template` 内联字段与新 `template_id` 并存 | 语义歧义 | 明确定义优先级：`template_id` > 内联 `template` |
