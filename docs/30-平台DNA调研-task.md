# 任务书：平台 DNA 调研与重建（可信来源版）

- 文档类型：task（事前三件套之一）
- 版本：v1.0 · 日期：2026-09-12
- 关联：FR-07（平台 DNA 文件化 / ADR-007）、NFR-09（合规红线 / ADR-010）、`docs/05-SRS` §3.2 平台支持
- 前置：M5c（LLM 加固与可观测）已完成 ✅ —— 现在能真实跑 LLM 并观测效果了

---

## 1. 背景（问题来自用户质疑）

用户明确提出：

> 「各个平台这么怎么转真的做到了吗，有好好调研吗」

实测核查后的诚实结论：

| 层面 | 结论 |
|---|---|
| **改写机制** | ✅ **真的做到了** —— 真实 LLM 生成时，DNA 的标题规则、结构模板、标签策略、收藏引导**确实体现在成稿里**（见 `docs/29` 的实测记录） |
| **DNA 依据** | ❌ **未做过调研** —— `platform-dna/*.yaml` 头部自己写着「示例版」「自研整理，依据公开运营方法论」，**实为模型通用常识的整理**：无来源引用、关键数字未核实、缺少算法机制层面 |

**这就是本任务要解决的问题**：把 DNA 从"常识整理"升级为"有来源可查的调研产物"。

## 2. 目标

1. **每个平台的关键规则都有来源可溯**：官方文档 / 公开规范 / 权威行业报告，在 YAML 中以 `sources` 字段列出
2. **关键数字经过核实**：字数上限、标签数、标题长度等，不再凭印象写
3. **补齐机制层面**：流量分发逻辑、冷启动、发布时间等真正影响曝光的因素
4. **保留可维护性**：DNA 仍是 YAML，**新增平台 = 新增 1 个文件**（不破坏 ADR-007）
5. **明确不确定性**：无法核实的条目标注 `verify: todo`，不假装确定

## 3. 范围

### In（本任务做）

| # | 事项 |
|---|---|
| 1 | 定义**调研维度**（内容规格 / 标题机制 / 标签规则 / 分发机制 / 社区红线 / 结构范式） |
| 2 | 为 **5 个平台**（小红书 / 抖音 / 微信公众号 / 知乎 / B站）逐维度调研，**记录来源** |
| 3 | 扩展 DNA schema：新增 `sources`、`distribution`（分发机制）、`specs`（硬规格）、`verify` 字段 |
| 4 | 重建 5 个 YAML（保留原有可用内容，用来源校正数字、补机制） |
| 5 | 产出**调研报告**（`docs/NN-平台DNA调研报告.md`）：逐平台结论 + 来源清单 + 不确定项 |
| 6 | **真实 LLM 对照验证**：同一素材用新旧 DNA 各生成一次，人工比对是否有可观察差异 |
| 7 | 前端/文档同步（如 DNA 展示字段变化） |

### Out（本任务不做）

| 事项 | 原因 |
|---|---|
| **爬取平台数据 / 抓取爆款样本** | **ADR-010 合规红线**：不爬平台数据 |
| 建立"爆款样本库"或训练/微调 | 超出 v1 范围，且涉及数据合规 |
| 各平台 API 对接（发布/数据回传） | 明确不做自动发布 |
| 自动化 DNA 质量评估（LLM-as-Judge） | 需先有可信 DNA 与数据集，属后续阶段 |
| 海外平台（X/IG/FB/YT） | v1 范围外（ADR-011） |

## 4. 调研方法（合规前提）

**只使用公开可查的资料，不做任何数据抓取：**

| 来源类型 | 示例 | 用途 |
|---|---|---|
| 平台官方规则页 | 小红书社区公约、抖音社区自律公约、微信公众平台运营规范、知乎社区规范、B站社区规则 | 红线词、内容规格、禁限领域 |
| 平台官方帮助中心 | 各平台创作者学院 / 帮助文档 | 字数上限、标签规则、发布规格 |
| 权威行业报告 | 公开的创作者生态报告、行业分析 | 分发机制、内容趋势 |
| 公开运营方法论 | 广泛传播的通用做法 | 结构范式（**须标注为经验性而非官方**） |

**强制要求**：
- 每条调研结论必须能回答"**这个数字/规则从哪来**"
- 无法核实的一律标 `verify: todo`，**禁止编造来源**
- 区分「官方规则」与「经验性做法」，不得混为一谈

## 5. 任务拆分

| 序号 | 任务 | 产出 | 预估 |
|---|---|---|---|

| T6 | 交付说明 + 文档同步 | `docs/34` | 小 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **搜集不到官方精确数字** | 结论无法落地 | 保留原值但标 `verify: todo` + 标注"经验值"；**不编造** |
| 平台规则变动频繁 | DNA 快速过时 | YAML 加 `updated_at` + `version`；报告注明核查日期 |
| 联网搜索质量参差 | 采信了不可靠内容 | 优先官方域名；非官方来源须**交叉验证 ≥2 处**才写入 |
| 调研内容被误解为"承诺效果" | 产品过度承诺 | 报告中明确"DNA 是改写**输入约束**，不保证流量结果" |
| 新旧 DNA 差异不可观测 | 无法验证价值 | T5 做真实对照，**如无显著差异需诚实说明** |

## 7. 完成定义（DoD）

- [ ] 三件套文档齐备且已确认
- [ ] 5 个平台 × 6 维度全部有调研结论
- [ ] 每条**数字类**结论都有来源标注（或明确标为经验值 + `verify: todo`）
- [ ] 5 个 YAML 重建完成，schema 统一，**`sources` 字段非空**
- [ ] 调研报告产出（含来源清单 + 不确定项清单）
- [ ] **真实 LLM 对照验证**：新旧 DNA 各生成一次并比对（有差异则说明，无差异则诚实记录）
- [ ] mock 模式与新 DNA 兼容（回归测试通过）
- [ ] 交付说明产出并提交

## 8. 待确认项

| # | 问题 | 建议默认 |
|---|---|---|
| Q1 | 是否允许联网检索？ | **是**（只查公开资料，不爬平台数据） |
| Q2 | YAML 是否兼容旧格式（加字段而非改结构）？ | **是**，新增字段可选，旧 DNA 不报错 |
| Q3 | 无法核实的数字怎么处理？ | 保留但标 `verify: todo` + 注明"经验值，待核实" |
| Q4 | 是否做新旧 DNA 的真实 LLM 对照？ | **是**（否则无法回答"调研有没有用"） |
| Q5 | 调研报告是否含各平台违禁词示例？ | 只列**类别**（如"医疗功效断言"），不复制具体词表（避免误导与版权问题） |
