# tasks —— 时间线（把「剪」变成「改数据」）

上游规格：`docs/spec_timeline.md`　　验收：`docs/checklist_timeline.md`

> 10 个任务，每个能在一次专注会话内完成。
> **最后两个（T9 接入主流程 / T10 端到端验证）是硬要求。**
> **T10 必须真的改一次时间线、真的重渲染出片**，不是只调接口。

## T1 · 时间线数据契约（先定契约）

**影响文件**：`docs/spec_timeline.md`（补一节）· `python-service/app/pipeline/timeline.py`（新建）

**依赖**：无

**做什么**：定死时间线的文件格式与校验规则。**这是 Python 与 Java 的共同接口**，
先定死，后面才能并行。

要定死的：

| 项 | 约定 |
|---|---|
| 顶层 | `{"version": 1, "source": {...}, "keep": [[start, end], …], "segments": [...]}` |
| `keep` | **保留**区间的升序列表（不是"剪掉"的区间 —— 语义只能有一种，写错方向后果严重） |
| `segments` | 字幕分段 `{"start","end","text"}`，**时间轴是源视频的时间轴**（见下） |
| `version` | 必须存在；不认识的高版本要**明确报错**，不猜 |
| 不存什么 | **不存 ffmpeg 参数**（见 spec §4） |

**字幕为什么存"源时间轴"而不是"成片时间轴"（关键）**：

成片时间轴是 `keep` 的**函数**。如果把字幕也存成片时间轴，那么**每次改 `keep` 都要
把字幕重映射一遍** —— 而重映射正是最容易出错的环节（边界、跨段、取整），
一旦算错就是"字幕和嘴对不上"。

存源时间轴则相反：改 `keep` **完全不碰 `segments`**，
成片时间轴在**渲染时**由 `keep` 现推。"字幕跟着剪点走"于是不是一条要实现的规则，
而是**结构上自动成立**的事实。

代价只有一次：粗剪的 ASR 输出是在**剪后的视频**上跑的（成片轴），
产出时间线时要把它映射回源轴一次。这一处转换有测试盯着。

**校验规则**（写成纯函数，两边都调它）：

| 规则 | 违反时 |
|---|---|
| `keep` 非空 | "至少要保留一段" |
| 升序且不重叠 | 指出是哪两段重叠 |
| 每段 `start < end` | 指出是哪一段 |
| 落在源时长内 | 指出越界的那一段与实际时长 |

**验收**：单元测试覆盖上表每一行，错误信息里**带得上具体是哪一段**。

## T2 · Python：粗剪产出规范时间线

**影响文件**：`scripts/roughcut.py` · `python-service/app/pipeline/timeline.py`

**依赖**：T1

**做什么**：粗剪跑完时，除现有 `cuts.json` 外产出**规范时间线**（走 T1 的契约）。
`cuts` 是"剪掉"的区间，时间线要的是"保留"的区间 —— **必须做这个转换，且要有测试**。

**同时定死字幕规则**（spec 关键决定四）：与保留区间无交叠的字幕段**整条丢掉**；
跨边界的**截断**；时间轴换算到成片时间。

**验收**：跑一次粗剪 → 时间线文件里 `keep` 是"保留"而非"剪掉"；
删掉一段后字幕不会错位（T10 会真验）。

## T3 · Python：从时间线重渲染

**影响文件**：`python-service/app/pipeline/timeline.py` · `scripts/render_timeline.py`（新建）

**依赖**：T1、T2

**做什么**：`源视频 + 时间线 → 新成片`。**从源视频重剪**，不是从旧成片剪
（spec 关键决定三：从成片剪会叠加压缩损失，且字幕已经烧进去了）。

复用现有 `rc.cut_video` / `rc.burn_subtitles` ✓。字幕用时间线里的 `segments`
（而不是旧 srt）—— 这样"改字幕"才真的生效。

**验收**：给定时间线与源，产出成片；**时长与 `keep` 推出的总长一致**（允许极小误差）。

**影响文件**：`job/RoughcutRunner.java` · `asset/AssetService.java`（如需要）

**依赖**：T2

**做什么**：粗剪跑完时把时间线登记进素材库，`kind=timeline`（`.json` 已经归到这一类），
血缘挂到**源视频**上。

**要点**：现在的 `cuts.json` 在 `work/` 里，会随任务目录清理而消失 ——
时间线要放到**不会被任务清理碰到**的地方（资产目录），这是本任务的核心。

**验收**：跑完粗剪 → 素材库里出现时间线资产；删掉任务目录后它**还在**。

## T5 · Java：时间线读写端点（校验走 Python）

**影响文件**：`web/` 新增控制器 · `client/PythonClient.java`

**依赖**：T1、T4

**做什么**：
- `GET /api/timelines/{id}` —— 读（含源信息、时长）
- `PUT /api/timelines/{id}` —— 存（**先校验**）
- `POST /api/timelines/validate` —— 只校验不存（前端编辑时用）

**校验只有一份实现**：在 Python（T1 的纯函数），Java 调它 ——
两边各写一遍必然分叉（仓库里已有"数字口径统一在 numberish，避免两处实现分叉"的先例）。
校验不通过时返回**具体是哪一段不对**，不是一句"格式错误"。

**验收**：非法时间线 → 4xx + 可读理由（指出段号）；合法 → 200 且落盘。

## T10 · 端到端验证（**必须有**）

**影响文件**：无（验证任务）

**依赖**：T9

**做什么**：**真的改一次、真的重渲染出片**。

步骤：

1. 用一个真实视频跑一次粗剪 → 得到时间线与成片
2. 打开时间线，**删掉中间一段**（并记下删的是哪段、原时长、预计新时长）
3. 保存 → 确认总时长变化**与预计一致**
4. 重渲染 → 看进度 → 完成
5. **打开新成片核对**：
   - 时长与预计一致
   - **被删那段的内容确实没了**
   - **字幕没有错位**（逐段抽查）
6. 再改一次（比如只改一段的结尾）→ 再渲染 → 确认改一处不影响别处

**验收**：上面 6 步的原始输出都留着；**哪一步没做到就如实写没做到**。
