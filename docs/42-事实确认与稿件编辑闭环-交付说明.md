## 2. 修复的四个缺陷

| # | 缺陷（评估报告指出） | 修复 |
|---|---|---|
| 1 | 事实清单**只能看不能改** | 可增/改/删 + 暂存 + **保存并确认**；确认后显示 ✅ 与时间 |
| 2 | 生成时**重复理解**（浪费一次调用，且事实可能不一致） | 已确认事实作为唯一依据，**跳过 understand** |

**浏览器实测**（Edge/CDP，逐步真实操作）：
```

5. 改正文/标题/标签 → 点「保存修改」→ 「✅ 已保存（00:13:54）」
6. **刷新页面 → 点历史稿** → 正文长度 18，内容 = `这是浏览器实测人工编辑后的正文内容。`
   → 编辑持久化 ✓  事实确认状态恢复 ✓  3 条事实恢复 ✓
```

## 4. 关键设计决策

| 决策 | 理由 |
|---|---|
| **跳过 understand 而非并行调用** | 既省一次 LLM 调用（额度紧张下很实际），又保证"解析时看到的事实"==="生成时用的事实"（防幻觉地基） |
| **`facts_json` 存数组**，非 `{facts:[...]}` | 沿用既有格式（`out.set("facts", readTree(factsJson))` 已是数组）；生成时在 Java 侧包装成 `StructuredMaterial` |
| **编辑接口白名单**（只改 titles/body/tags/interaction_line/cover_suggestion） | **防止绕过质检**：`qa`/`brief`/`clip_sheet` 不经此路径，有测试断言不可注入伪造 qa |
| **编辑后不自动重跑 QA** | 避免用户等待 + 额外额度消耗；改为 UI 明确提示"改动后请自行核对（尤其数字与事实）" |
| **DB 增量迁移**（`ALTER TABLE ADD COLUMN`，幂等） | 不重建表、不丢既有数据；沿用项目既有 `ensureXxxColumns` 惯例 |

## 5. 过程中发现并修复的问题（测试驱动）

| # | 问题 | 怎么发现的 | 影响 |
|---|---|---|---|
| 1 | `getMaterial`/`listMaterials` 的 **SQL 是显式列名**，不含新列 → `getMaterial failed` | Java 单测（4 项 ERROR） | 若漏掉，新列永远读不到 |
| 2 | 前端事实类型给的是 `fact/quote/experience`，而 Python `FactType` 只允许 `data/story/opinion` → **422** | 端到端（生成 502） | 用户一保存事实就会失败 |
| 3 | 创建素材响应缺 `facts_confirmed` → 前端判断"已确认"失效 | 端到端断言 | UI 状态错误 |
| 4 | 素材详情响应缺 `facts_confirmed` + `structured` → 历史稿无法恢复事实清单 | 端到端第 7 项 | 编辑区无法回填 |

**第 2 项特别值得记**：跨语言契约（Java 自由字符串 → Python `Literal`）没有共享定义，靠端到端才暴露。已在 **Java 侧补同源校验**（`data|story|opinion`），避免把非法值传到下游才 422。
