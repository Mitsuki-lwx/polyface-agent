## 1. 检测（T1）

- [x] 三段纯色的合成视频 → 检出 ≥2 个切点，位置与真实边界差 < 0.5s
- [x] 静态单场景视频 → 检出 0 个切点（不硬凑）
- [x] PySceneDetect 没装 → **明确报错 + 安装指引**，不是返回空列表
- [x] 阈值可改：调高 → 切点变少；调低 → 变多
- [x] 同一输入 + 同一参数 → 两次结果完全相同（确定性）

## 2. 语音吸附（T2）

- [x] 画面切点落在句子中间 → 吸附后与**语音边界**重合
- [x] 吸附偏移超过上限 → **不吸**（宁可留原样，也不挪到另一句话里）
- [x] 没有音轨 / 缺 ASR → 原样返回画面切点 + 标记 `speech_aligned=false`（**不静默**）
- [x] 吸附只做**就近平移**：不会把边界挪到相反方向、不会产生重叠

## 3. 合并（T3）

- [x] 低于最短时长的段 → **并入前一段**（不是丢掉）
- [x] 第一段过短 → 并入**后一段**
- [x] 合并后：升序、无重叠、**总长等于源时长**（守恒）
- [x] 改最短时长 → 段数确实变化

## 4. 方案与勾选（T4/T6）

- [x] `--dry-run` → **不产出任何视频文件**
- [x] 方案里每段有：起止、时长、缩略图
- [x] N 段 → N 张缩略图，且都非空
- [x] `--pick 2` → 只切第 2 段
- [ ] 检测结果落盘；改阈值重跑时**不重新解码整条视频**（可观测：第二次更快）
- [x] 落盘里含检测器版本与参数（可复核"当时用的是什么"）

## 5. 切段（T5）

- [x] 切出的段数 = 勾选数
- [x] 每段时长与方案一致（±0.2s）
- [x] **源文件不动**（mtime 不变）
- [x] 段的时间戳来自程序（不取检测器的自由文本）

## 6. 接入主流程（T7）

- [x] 新任务种类可发起，进度可看、能取消
- [x] 切出的每段**登记成素材**（出现在素材库）
- [ ] 每段血缘挂回源视频（能反查"这条是从哪个视频的哪一段来的"）
- [x] 界面：能看方案（缩略图 + 时长）、能勾选、能切
- [ ] 缺 PySceneDetect 时，界面能看到"怎么装"（不是空白）

## 7. 端到端（T8，**必须真素材**）

- [x] 真实多场景素材 → 出方案 → 勾选 → 切 → 拿一段跑粗剪
- [x] 切点位置**逐条核对**（对着源视频看）
- [ ] 没有把一句话切断（听切点前后 1 秒）
- [x] **切错的逐条列出**（报忧不报喜）
- [x] 原始输出（方案、时长、缩略图）贴进本文件

## 8. 文档（T9）

- [x] 新 ADR 记录"引入 PySceneDetect"与代价（发布包带上它）
- [x] SRS 的 FR-53 缺口表去掉"分镜"
- [x] README 补新依赖安装说明
- [x] `grep` 确认 SRS/README 与实现一致

## 9. 变异测试

- [x] 把"短段并入前一段"改成"丢掉" → §3 的守恒断言**变红** → 还原
- [x] 去掉吸附的偏移上限 → §2 的"不挪到另一句话"**变红** → 还原
- [x] 让缺依赖时返回空列表（而不是报错）→ §1 的"明确报错"**变红** → 还原
- [x] 让 `--dry-run` 也真的切 → §4 的"不产出任何视频"**变红** → 还原

## 实机验证记录（2026-10-17）

### 素材
`data/` 里没有合适的多场景素材（都是粗剪产物），所以**合成**：

```
ffmpeg -f lavfi -i color=red:640x360:d=8 -f lavfi -i color=blue:...:d=8 -f lavfi -i color=green:...:d=8
       -i <一段带语音的 wav> -filter_complex "[0:v][1:v][2:v]concat=n=3:v=1:a=0"
```
→ 24 秒，三段纯色（真实边界 8.0 / 16.0），并带语音（用来验吸附）。

### 结果

```
▶ 探测  long.mp4  24.00s
切成 3 段（检测器：PySceneDetect 0.7.2 ContentDetector，阈值 27.0，最短 3.0s，吸附 1 处）：
    1.     0.00 →     8.00s  (  8.00s)
    2.     8.00 →    15.00s  (  7.00s)   ← 画面边界 16.0 被吸附到语音边界 15.0
    3.    15.00 →    24.00s  (  9.00s)
缩略图 3 张 ✓
切出：scene-001.mp4 8.08s / scene-002.mp4 7.08s / scene-003.mp4 9.00s（±0.2s 内 ✓）
源文件 mtime 未变 ✓
```

### 实测逮到三个缺陷（都只有真跑 ffmpeg 才会露出来）

1. **`-to` 的参考点不对** ✗ —— `-ss 15 -to 24` 切出来 16.1 秒（应 9 秒）。
   改用 `-t <时长>`（无歧义）。
2. **`-avoid_negative_ts make_zero` 让容器时长算错** ✗ —— 同一个切点，
   加了它 16.105 秒，去掉它 9.000 秒。那是为拼接准备的参数，这里用不上。
3. **dry-run 时 `plan.json` 里没有 `thumb`** ✗ —— 缩略图**产出了**，但方案文件写在它之前，
   于是"哪段对应哪张图"没落盘。落盘的意义是"调参重跑不必重新解码"，它得是**完整**的方案。

三条都加了回归测试。

### 未做 / 未验证（如实列）

- **接入主流程（T7）与浏览器实测**：本次由子代理并行完成，结果见其报告。
- 端到端用的是**合成素材**，不是真实多场景录像。
- 吸附用的语音边界来自合成语音；真实素材上"切点附近有没有合适的语音边界"未验。

### 接入主流程 + 界面实测（2026-10-17）

走 **Java 任务**跑完整两段式（真服务、真 ffmpeg、真 ASR）：

```
① 方案阶段：POST /api/jobs {kind:"scene_split", asset_id:1, params:{min_sec:3}}
   → running（阶段：语音边界）→ succeeded（27s）
   outputs.plan_url = /api/media/scenes/job-…/work/scene-plan.json
   段数 3，吸附 1，语音对齐 True；每段带 thumb

② 切段阶段：POST /api/jobs {kind:"scene_split", asset_id:1, plan_job_id:1, pick:[1,3]}
   → succeeded（27s）
   素材表新增：
     (2, 'video', 'long.mp4 第1段（0.00–8.00s）', 'scenes/job-…/scene-001.mp4')
     (3, 'video', 'long.mp4 第3段（15.00–24.00s）', 'scenes/job-…/scene-003.mp4')
   plan.cut = [1, 3]；第1段 方案 8.00s 实际 8.08s ✓；第3段 9.00s 实际 9.00s ✓
```

**浏览器实测**（headless，真服务）：素材行有「✂️ 切场景」按钮 → 面板（阈值/最短段长/吸附开关）
→ ① 出方案 → **缩略图网格**（3 格，红/蓝/绿，与合成素材一致 ✓，每格带段号/起止/时长/勾选框）
→ 勾 1、3 → ② 切选中的段 → `✅ 切段完成` + `✂️ 切出 2 段，已入素材库`。

### 实测逮到第四个缺陷（界面）

**状态文字在任务结束时从不更新** ✗ —— 只写了"进行中…"，任务早就成功了界面还停在"进行中"，
用户会一直等下去。修：结束分支里更新状态并恢复按钮。

### 未验证

- 端到端用的是**合成素材**（三段纯色 + 合成语音），不是真实多场景录像。
- 切段阶段会**重跑一遍语音边界**（27s）—— 方案阶段的 ASR 结果没有复用。这是已知代价
  （CLI 每次独立跑），要省这一步得把转写结果跨阶段落盘。

## 真素材验证（2026-10-17，影视飓风素材库）

### 素材
`D:\media works move\data\real\20260712_A1M2-5503_1159.mov`
= 素材库里的 **Bo-Kaap-02**（样片日记-南非 / 城市 / 广角 / Sony / 59.94 / S-Log3）。

```
ProRes · 3840×2160（真 4K）· yuv422p10le（10bit 灰片）· 60fps · 2.72s · 363MB · **无音轨**
```

### 结果

| 验的东西 | 结果 |
|---|---|
| 解 ProRes 10bit 4K | ✓ 检测耗时 3.4s |
| 切点检测 | ✓ 1 段（单镜头 —— 正确，这条素材本来就是一镜到底） |
| 缩略图 | ✓ 1 张 |
| **无音轨跑粗剪** | ✓ **大声失败**：「这个视频没有音轨，无法判断停顿」—— 正是该有的行为 |
| 切段（修复后） | ✓ `scene-001.mov`，**ProRes 3840×2160 完整保留**，时长 2.719s（精确） |

### 实测逮到第五个缺陷（**只有真素材才会露出来**）

**源是 ProRes 时切成 .mp4 直接失败** ✗：

```
Could not find tag for codec prores in stream #0, codec not currently supported in container
```

MP4 容器装不下 ProRes。而**影视飓风素材库里大量是 ProRes 灰片** —— 把 `.mp4` 写死
等于这类素材一进来就切不动。

修：按**源编码**选容器（ProRes/DNxHD → `.mov`，其余 → `.mp4`），
并把真实文件名写进方案（`file_name`），Java 侧据此登记素材而不是猜扩展名。
加了 4 条回归测试（含"真的切一刀，编码不被改掉"）。

### 仍未验

- 这条素材**只有 2.72 秒、单镜头、无音轨** → **验不了**多场景切分、语音吸附、去冗余。
  需要**多段不同场景**的素材拼起来才能验（这是下一步）。
- 4K ProRes 的**长素材**耗时未测（这条只有 2.7s）。

## 真素材多场景验证（2026-10-17，影视飓风素材库，4 条不同场景）

### 素材（用户从素材库下载，全部 ProRes 4K 灰片）
| 文件 | 时长 | 来源（据封面内嵌原片名比对） |
|---|---|---|
| `20260712_A1M2-5503_1152.mov` | 3.120s | Bo-Kaap 街景（另一条） |
| `20260712_A1M2-5503_1159.mov` | 2.719s | Bo-Kaap-02 街景 |
| `DJI_20260713233125_0121_D.mov` | 2.052s | 航拍（长颈鹿草原） |
| `DSC_2109.mov` | 2.427s | 织布鸟巢 |

### 做法
4 条都是 3840×2160 ProRes（共 1.6GB），先转 1080p h264 代理（共 6MB）再拼接成
一条 **10.267s 的四场景片** —— 这样**切点真值是已知的**（就是四条接缝），
比随便找一条长录像更能判"切得准不准"。

> 注：直接 `-c copy` 拼 ProRes 会**翻倍**（20.64s vs 10.32s）—— concat 解复用器遇到
> 不同时基的 ProRes 会这样。这是**工具用法**问题，不是产品缺陷，记在这里免得重踩。

### 结果：**4 段，边界误差 < 0.01s**

| 检出 | 真值 | 误差 |
|---|---|---|
| `0.00 → 3.10` | 3.100 | < 0.01s ✓ |
| `3.10 → 5.80` | 5.800 | < 0.01s ✓ |
| `5.80 → 7.83` | 7.833 | < 0.01s ✓ |
| `7.83 → 10.27` | 10.267 | < 0.01s ✓ |

**切错 0 条** ✓。缩略图 4 张，肉眼核对确为**四个不同场景**
（窗边墙面 / 街景有人 / 草原长颈鹿 / 织布鸟巢），md5 各不相同。

### 顺带观察（不是缺陷，但值得记）
素材库里这些都是**灰片**（S-Log3 / D-Log）—— 画面发灰是**素材本身**如此，
本工具**不做色彩还原**（不在 B2 范围内）。要做的话是另一件事。

### 仍未验
- **语音吸附**：这 4 条都**没有音轨** → 吸附路径仍未在真素材上验过（合成素材验过）。
- **去冗余**：需要**带人声**的真实素材。
