# 素材关键词与检索 —— 交付说明

> 对应 openspec change：`openspec/changes/material-keywords-and-search`
> 关联：`docs/69`（崩溃可观测）、ADR-017（数据边界）

## 一、起因

`material` 表**没有任何索引字段** ✗ —— 素材一多只能靠翻列表和记忆找。对照之下 `asset`
（图片/音频/视频）反而有 `tags_json` ✓。而"复用"正是这个产品的核心动作：找不到就复用不了。

## 二、做了什么

| 层 | 改动 |
|---|---|
| 存储 | `material.tags_json TEXT DEFAULT '[]'`（建表 + `ALTER` 幂等迁移）|
| 解析 | `StructuredMaterial.keywords`；`UNDERSTAND_SYSTEM` 同批产出 3~8 个候选（**不新增调用**）|
| 检索 | `GET /api/materials?q=&tags=` —— `q` 全文子串、`tags` 交集，两档可叠加 |
| 写入 | `PUT /api/materials/{id}/tags`；`POST /api/materials` 接受可选 `tags` 与 `structured` |
| 前端 | ① 素材：**解析(不保存) → 改事实/删改关键词 → 确认并保存**；素材历史加搜索框与关键词显示 |

## 三、关键结论：**FTS5 不能用** ✗（实测）

`SqliteFts5CapabilityTest`（sqlite-jdbc 3.46.1.0）：

| 检查 | 结果 |
|---|---|
| `CREATE VIRTUAL TABLE ... USING fts5(...)` | ✓ 可用 |
| 默认分词器搜「复用」（2 字）| ✗ 整句被当成一个 token |
| `tokenize='trigram'` 搜「一稿多」（3 字）| ✓ 命中 |
| `tokenize='trigram'` 搜「复用」（2 字）| ✗ trigram 最小 3 字 |

中文最常搜的恰恰是**两字词**（复用/周报/选题）→ 走 **`LIKE`** ✓。功能正确、一万条量级
全表扫描仅几 MB。这条结论由测试钉住：驱动哪天支持更好分词，测试会先红。

## 四、实测（真模型 / 真库 / 真 HTTP）

### 4.1 自动关键词

`2.txt`（1900 字）解析 → 8 个候选：

```
内容复用 / 内容母库 / 一稿多拆 / AI写周报 / 小红书图文 / 短视频口播 / 自媒体运营 / 番茄钟
```

覆盖了**主题 + 场景**两个维度 ✓（prompt 里就是这么要求的）。

### 4.2 确认前不落库（核心验收，**在真实界面上验的**）

用 headless Chromium 驱动真实页面：

```
① 粘贴 2.txt → 点「解析素材」
   状态栏：已解析（8 个候选关键词，确认后保存）
   GET /api/materials → 0 条          ✓ 未确认没落库
② 点关键词上的 × 删掉「内容复用」→ 剩 7 个
③ 点「确认并保存为素材」
   GET /api/materials → 1 条，tags = 7 个，被删的不在里面   ✓
   状态栏：✅ 已保存（#1，7 个关键词）
④ 搜索框输入「剪映」→ 素材历史出现该条，关键词标签正常渲染   ✓
   页面 JS 错误：无 ✓
```

### 4.3 同一流程的 HTTP 侧（上面那节的早期验证）

```
① POST /api/analyze → 8 个候选
② GET  /api/materials → 0 条   ✓ 未确认就没写库
③ 删掉「内容复用」→ POST /api/materials（带 structured + tags）
④ GET  /api/materials → 1 条，tags = 7 个，被删的那个不在里面 ✓
```

### 4.3 检索

| 用法 | 结果 |
|---|---|
| `tags=母体内容` | 1 条 ✓ |
| `tags=绝无此词` | 0 条 ✓ |
| 删掉的关键词再搜 | 0 条 ✓ |
| `q=剪映` / `q=Canva` / `q=番茄钟` | 各自命中 ✓ |
| `q=…&tags=…` | 叠加命中 ✓ |
| 列表项 / 详情 | 都带 `tags` 数组 ✓ |
