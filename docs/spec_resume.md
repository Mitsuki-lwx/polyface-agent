# spec —— 任务断点续跑（生成 + 粗剪）

版本：2026-10-09　　对应 tasks：`docs/tasks_resume.md`　　验收：`docs/checklist_resume.md`
上游依据：`docs/71` §7（M8「编排任务化」里「**断点续跑**」那一半）· `docs/spec_roughcut_jobs.md` §4

---

## 1. 背景

`docs/spec_roughcut_jobs.md` §4 写过一句判断：

> 分钟级任务里「**重启一下进度就没了**」是不可接受的。

任务表（`job`）与异步/进度/取消都做了，但**续跑没做**。现在的
`recoverInterrupted()` 只是把未结束的任务**标为失败**：

```java
/** 与粗剪同样的启动清理：上次没跑完的标为失败，否则工作台会永远转圈。 */
store.finishJob(j.id(), Store.JOB_FAILED, "服务重启时任务尚未结束", ...);
```

**是"清理"，不是"续跑"。** 后果：

- 生成一条素材要**几分钟**（每平台最多 4 次 LLM 调用），服务重启 = 白跑，用户重来
- 粗剪更贵（转写是分钟级），中断损失更大
- 而**已花掉的 LLM 额度**不可恢复 —— 这不是"重来一次"那么便宜

更麻烦的是：**跑到一半时，产物一个都没落盘**。workdir 里只有 `events.jsonl`（阶段事件），
阶段报告的是「成稿完成」这种**摘要，不是稿子本身** —— 稿子要等 `generate()` 整批返回才到 Java 侧。
所以续跑**必须先解决中途落盘**。

## 2. 目标用户

**现阶段只有作者本人**（以及将来的使用者）。这是他自己的长任务，中断了要能接着跑。

## 3. 能力清单（一句话一条）

1. **中途落盘**：每个平台/阶段一完成，产物立刻写进该任务的 workdir —— 不等整批返回
2. **中断可辨**：服务重启时，未结束的任务标为 `interrupted`，**不再标为失败**
3. **一键继续**：工作台对 `interrupted` 的任务给出「继续」，点了才真的接着跑
4. **只跑缺的**：继续时**跳过已完成的平台/阶段**，不重跑、不重复花额度
5. **产物不重复**：继续完成后，产物与"一次跑完"**完全等价**（不是两份、不是拼接错位）
6. **可放弃**：`interrupted` 的任务也能被取消/删除，不留垃圾
7. **不自动开跑**：**绝不在服务启动时自动发起 LLM 调用**（那会在刚启动时一次性打出一批请求，
   既花钱又可能撞限流；用户也可能已经不想跑了）
8. **两种任务都支持**：生成（平台级）与粗剪（阶段级）—— 两者的"已完成单位"不同

## 4. 非功能要求

- **失败与中断必须分开**：`failed`（跑过、确实错了）与 `interrupted`（没跑完、可继续）
  是两种状态。把它们混成一个，用户就分不清"该重试"还是"该修问题"
- **落盘要原子**：写一半崩掉不能留下半个 JSON —— 宁可当成"没完成"，也不要读出一个坏产物
- **不改变对外契约的形状**：`/api/jobs` 的既有字段不动，只加状态与一个新端点
- **续跑要能看出"接着跑了多少"**：日志/事件里能看出跳过了哪些、跑了哪些
- **不引入新依赖**

## 5. 设计骨架

```
任务执行中
   │
   ├─ 每完成一个单位（平台 / 阶段）→ 立刻写 workdir/done/<单位>.json（**原子写**）
   │
   └─ 服务重启
        ↓
   recoverInterrupted() 把未结束的标为 **interrupted**（不是 failed）
        ↓
   工作台显示「已中断 · 可继续」  ← 用户点「继续」才动
        ↓
   续跑：读 workdir/done/ 里已有的单位 → **只跑缺的**
        ↓
   合并产物 → 与"一次跑完"等价
```

**关键决定一：落盘单位就是"续跑单位"，两者必须是同一个东西。**

如果落盘按平台、续跑按素材，就会出现"存了 3 个平台但续跑时整条重来"——
存了等于没存。所以：**落盘粒度 = 续跑粒度**，这是本设计的第一条不变量。

**关键决定二：中断是独立状态，不是失败的一种。**

`failed` 的语义是"跑过了，结果是错的"——用户该去看错误、改素材、改参数。
`interrupted` 的语义是"没跑完，接着跑就行"——用户该点「继续」。
两者混用会让用户对着一个"失败"的任务不知道该修什么（其实没什么可修）。

**关键决定三：绝不自动续跑。**

服务启动时自动续跑看起来"贴心"，实际有三个问题：刚启动就打出一批 LLM 请求（可能同时好几个任务）、
额度与限流风险集中爆发、而用户可能早就不想跑那个任务了。
**改成显式的一次点击** —— 代价是用户要点一下，收益是不会花冤枉钱。

**其它骨架决定：**

- 生成的"单位" = **平台**（`generate()` 本来就接受 `platforms` 子集，续跑只需传缺的那些）
- 粗剪的"单位" = **阶段**（探测 / 找停顿 / 剪 / 抽音轨 / 转写 / 烧字幕）——
  它本来就"中间产物落盘保留"（`docs/spec_roughcut.md`），续跑复用它已有的落盘
- 落盘用**临时文件 + 改名**（原子），不用"直接写目标文件"
- 「继续」复用现有的 `retry` 语义，但**带跳过**：读 `done/` 决定跑哪些

## 6. Out of Scope（本版不做）

- **自动续跑**（见关键决定三）
- **跨机器 / 跨版本的续跑** —— 只保证同一份数据目录、同一个版本内
- **续跑时的参数变更**（比如中断后换平台集合）—— 本版按原参数继续；
  换参数属于"新任务"
- **任务队列的并发控制 / 优先级** —— 与续跑无关
- **自动成片（B1/B2）** —— 那是另一条线
- **把 `done/` 里的中间产物当资产登记** —— 中间产物不是资产，不进素材库
