# 剪辑用画面 —— 交付说明

> 承接 `video-frame-understanding`（能看懂画面 ✓）。这一轮解决的是：
> **粗剪看得懂画面之后，剪辑本身还看不见** ✗。

## 一、问题

粗剪按**静音与句读**切 ✓ —— 这对手口播是对的（切点本来就该由换气决定 ✓）。
但它**不知道切出来的是什么画面** ✗：

- 保留的 8 段里可能有一段是空镜 / 桌面特写 / 走神 ✓
- 你只能导出来以后一段段看 ✗
- 想配文、想挑封面，也没有画面依据 ✗

## 二、做了什么

| 改动 | 说明 |
|---|---|
| `roughcut.kept_segments(cuts, total)` | 剪掉区间 → **保留**区间（粗剪真正出片的那几段）✓ |
| `roughcut.segment_midpoints(segs)` | 每段取中间点（抽帧位置）|
| `frames.extract_at(video, dir, times)` | **在指定时刻**各抽一帧（区别于"找代表性画面"）|
| `POST /frames` + `times` | 给了 `times` 就不做场景检测，只抽这些时刻 ✓ |
| Java 代理 | `/api/frames` 透传 `times` ✓ |

**为什么取中间点**：切点两侧有气口（静音留白 ✓），中间点最不容易切到转场糊帧 ✓。

## 三、实测（`拒绝背刺！.mp4`，65.7s）

## 六、画面质量评分（纯本地，2026-11-09）

`frames.frame_quality(frame)` 用 ffmpeg 在**静态帧**上算三个数，**不调模型** ✓：

| 指标 | 含义 | 阈值（故意保守） |
|---|---|---|
| `blur` | **模糊度**（越大越糊）| `> 20` → blurry |
| `yavg` | 亮度均值（0~255）| `< 25` → dark；`> 235` → overexposed |
| `ymin/ymax` | 亮度极值 | 只记录，不判定 |

### 踩到的两个坑

1. **方向搞反了** ✗ —— ffmpeg 的 `blurdetect` 输出是**模糊度**，不是清晰度。
   实测：清晰口播帧 `7.98`，高斯模糊后 `27.48`。第一版写成了 `< 3 判糊`，永远不触发 ✓。
   现在 `< 20` 才判糊，并有测试钉住"模糊后数值必须**变大**"。
2. **指标写在 stdout 不是 stderr** ✗ —— `metadata=print:file=-` 把结果打到标准输出，
   而 ffmpeg 自己的日志在标准错误。只读 stderr 会全部拿到 `None` ✓。

### 实测

```
不能用模型的成本：3 张 0.6 秒（含抽帧）

[  1.0s] ok  blur=7.78 yavg=126.9
[ 12.0s] ok  blur=7.59 yavg=129.2
[ 44.4s] ok  blur=7.65 yavg=128.6
```

界面里每帧右侧直接显示 `质量 ok`（异常时变朱红并写原因）✓。
