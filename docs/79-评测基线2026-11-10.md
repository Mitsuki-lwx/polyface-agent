# 评测基线（2026-11-10）与提速实验的第一轮结论

> 目的：给"骨架那步 p95 210 秒"找一条**可证明**的提速路。
> 工具：`scripts/eval/run_eval.py`（素材 × 平台矩阵，机械断言，不请模型当裁判）

## 一、基线（改动前，当前配置）

| 项 | 值 |
|---|---|
| 素材 | v1 · **10 条** |
| 平台 | xhs / douyin / gzh / zhihu / bilibili（共 50 格）|
| 模型 | `cline-pass/deepseek-v4.1-flash-1017` |
| 耗时 | 2716s（约 45 分钟，`--jobs 2`）|
| **通过率** | **92.0%（46/50）** |
| 断言失败 | 4 |
| **调用失败** | **0** |
| 原子支持率 | **99.3%** |

分平台：xhs 100% · douyin 100% · gzh 90% · bilibili 90% · zhihu 80%。

> 和上一份报告（2026-10-26，2 条素材、10 格）对比：通过率 30% → **92%**，
> 调用失败 4 → **0**。后者的提升主要来自这轮的重试/退避/兜底加固 —— 也就是说
> **"评测分数低"当时有一半是调用不稳，不是内容差**。

### 4 个断言失败长什么样

都是"语义质检判新增了素材没有的断言"，例如：

```
m02 · gzh：QA 未通过：正文「最贵的一课」一节新增了素材没有的行为断言：
「课也听完了」—— 素材只写「后来发现，教学内容全是网上能免费搜到的」，
并未说明课程已学完。
```

这说明质检那一层在按设计工作（模型不许加素材里没有的事实），不是管线坏了。

## 二、变体 A：换非推理模型 —— **当前不可行**

先确认"关思考"的参数确实无效（同一个问题四种写法）：

| 参数 | 延迟 | 推理 token |
|---|---:|---:|
| 基线 | 2.8s | 77 |
| `chat_template_kwargs.thinking=false` | 1.0s | 70 |
| `reasoning_effort=none` | 1.1s | 60 |
| `enable_thinking=false` | 2.9s | 93 |
| `thinking_budget=0` | 1.0s | 62 |

再枚举免费通道实际能用的模型（`/models` 有 448 个名字，但 `cline-pass/` 只服务少数几个）：

| 模型 | 结果 |
|---|---|
| `cline-pass/deepseek-v4.1-flash-1017` | 可用，推理 52/81 token |
| `cline-pass/minimax-m3.1-flash` | 可用（预算太小时返回空正文），推理仍在 |
| `cline-pass/kimi-k3` | 可用，但一句话要 **39 秒** |
| `cline-pass/glm-5.3` | 预算小时空正文；推理仍在 |
| 其余 20 个候选（gemini / qwen / claude / deepseek-pro…）| **404 model not found** |

付费路（`deepseek/...`）需要余额，当前 **$0.0099** —— 不敢拿来跑 50 格。

**结论：免费通道里没有非推理模型，"换模型"这条路现在走不通。** 不是没试，是试完了没得选。

## 三、变体 B：骨架拆步（下一步）

思路：把"一次让模型写完整篇多段正文"拆成

1. **提纲**：只输出"每段用哪几条事实、这段要说什么"（小输出，思考量小）
2. **逐段写**：每段一次调用，可并行；每段只带自己的事实与上下文

预期：单次调用的思考量下降 + 段间并行 → p95 下降。
判定标准（预先写死，避免事后找理由）：

- **通过率不低于基线 92%**（允许 ±2 个百分点内的噪声）
- **原子支持率不低于 99.3%**
- **p95 下降 ≥ 40%**（210s → ≤126s）

任一条不满足就不采纳。

### 实现状态（2026-11-10）

已落地，**默认关闭**（<code>llm_draft_split=false</code>），线上行为不变：

| 件 | 内容 |
|---|---|
| `prompts.build_draft_outline_prompt` | 只出提纲：标题/标签/每段用哪几条事实/这段要说什么 |
| `prompts.build_draft_section_prompt` | 只写这一段；只把**这一段声明的事实**原文摆出来 |
| `prompts._draft_payload` | 三种提示词共用的材料与平台规则（避免两套规则慢慢分叉） |
| `generate._split_draft` | 提纲 → 段间并行（默认 2 路）→ 拼回**同形状**骨架 JSON |
| 开关 | `LLM_DRAFT_SPLIT=1` / `LLM_DRAFT_SECTION_WORKERS=2` |

形状不变是刻意的：下游闸门、装配、质检一行没改 —— 拆步只影响"怎么问模型"。

单测 `tests/test_draft_split.py`（5 条）：同形状、乱序完成仍按段号排序、
空提纲不抛、提纲提示词不要求 body、单段提示词只带自己声明的事实。

## 四、这轮顺带确认的事

- `--jobs 2` 跑 10 条素材约 45 分钟；单条最慢 845s（m09）、平均约 540s
- 单条素材的 token 量很可观：m01 **116,840 输入 + 192,605 输出**（含推理 token）
- 一次 JSON 解析失败自动重试后恢复（m08），没有变成整条失败
- 全程 1 次连接错误，重试后成功 —— 加固生效

## 五、拆步第一轮：失败，但失败在实现而不是想法

第一次子集跑（2 素材 × 5 平台，`split-20261110`）：

| 指标 | 基线 | 拆步第一版 |
|---|---|---|
| 通过率 | 92% | **0%（0/10）** |
| 原子支持率 | 99.3% | **73.0%** |
| m01 耗时 | 414.6s | **1010.4s** |
| m02 耗时 | 742.0s | **1301.8s** |
| 调用次数（m01）| 48 | **325** |

失败原因（逐条抄自报告）：

1. `SkeletonGateError: 段5 残留未回填的槽位写法（{{n:序号/表层}}）`
   —— 单段提示词没把"序号/表层要替换"这两行抄过来，模型照抄了示例。
2. `SkeletonGateError: 骨架没有任何非空段落` —— 段调用返回空，`parse_skeleton` 丢空段后全军覆没。
3. 长度失控：bilibili 正文 2396 字（上限 1000）—— 单段没有字数预算，模型按"写满"写。
4. 语义质检抓到的都是编辑残留：括号里重复整句、素材没有的情节（"房东那天发来消息"）。

**根因判断**：这是实现缺陷（缺槽位说明、缺分段预算、修复轮重跑全部段），
不是"拆步不可行"的证据。已修：

- 单段系统提示补上槽位规则（与骨架版同文），删掉没有实现的 `other_sections` 承诺
- 单段给出字数预算（平台窗口上界 ÷ 段数），并要求"只写自己这段"
- `section.fact_texts` 修正（之前被预算覆盖掉了一次）
- 修复轮只重写**被点名**的段（硬违规里带「段N」），不再全量重跑

第二轮（`split2-20261110`）：

| 指标 | 基线 | 拆步第二轮 | 判定 |
|---|---|---|---|
| 通过率 | 92% | **10%（1/10）** | ✗ 远低于要求 |
| 原子支持率 | 99.3% | **89.1%** | ✗ 低于要求 |
| m01 耗时 | 414.6s | 750.6s | ✗ 更慢 |
| m02 耗时 | 742.0s | 764.2s | ≈ 持平 |
| 调用次数（m01）| 48 | 244 | ✗ 5 倍 |

失败模式与第一轮不同、但更说明问题：

1. **新增断言成为主要失败模式**（8 格断言失败里绝大多数是它）：
   「每天刷岗位刷到麻木」「不追爆款」「报名时被课程页的收益截图打动」——
   素材里都没有。分段写时模型更容易"补细节"。
2. **篇幅失控**：1442 / 1837 / 2133 字，上限 1000。分段预算用的是平台 DNA 的窗口，
   而断言用的是评测规则里的阈值，两个来源不一致 —— 拆步把这个既有不一致放大了。
3. **空骨架 / 坏 JSON** 仍有：`Invalid control character`、`Expecting ',' delimiter`
   （长段中文里的控制字符），单段失败就整篇失败。

## 六、结论：**否决**（按预先写死标准）

三条验收标准（通过率 ≥92%、支持率 ≥99.3%、p95 降 ≥40%）**一条都没达到**，
其中两条（质量、耗时）都是反向。因此：

- `llm_draft_split` **保持默认关闭**，代码保留（已单测、可回退），不删 —— 
  它证明了"这条路的实现成本比预期高"，留着免得以后有人重做一遍
- 真正的收获不是"变快了"，而是：**"分而治之"在生成任务上会同时放大幻觉与长度漂移**，
  因为每一段都缺少全文视角，模型就自己脑补上下文

## 七、下一步（按性价比）

| 方向 | 依据 | 代价 |
|---|---|---|
| **接受长尾，改交互**：先出已完成平台、显示阶段进度 | draft p95 210s 是单次调用的物理下限，拆步证明了改结构会更差 | 小 |
| 买额度后试 `gemini-3.8-flash` / `glm-5.3-flash`（付费路） | 免费通道只有 4 个会思考的模型 | 需要充值 |
| 骨架**输入瘦身**：只给"本平台简报引用到的事实" | 现在每次带全部事实清单（m01 输入 11.7 万 token / 48 次） | 中，要重跑评测 |
| 前缀缓存对齐：system + 平台 DNA 固定在最前 | 观测里有 1536/2350 命中，说明网关有缓存 | 小 |

**不建议**继续在"拆步"上加码：两轮实现、两套失败模式，都没有改善任何指标。
