**三件事因此被证明**：

1. **内嵌是真的**：iframe 指向 `127.0.0.1:18765`，且该页面在**真实浏览器**里渲染出编辑器
   （截图里能看到它的图层面板 `title1`/`title2`/`bg`）。冷启动 **0.9s**。
2. **改动真的落回同一个 `scene.json`**：脚本用编辑器自己的 HTTP API 把文字层平移 30px，

3. **生命周期是干净的**：`stop` 后端口立刻释放、幂等；**停掉 Java 进程后子进程不残留**（实测）。

## 3. 设计要点

| 决定 | 理由 |
|---|---|
| **懒启动**（第一次打开才起进程） | 大多数人只写稿不出图；常驻一个 Node 进程是纯浪费，还白占一个端口 |
| **单实例 + 换文档时重启** | `gimpish serve` 一次只服务一个场景目录；多实例要占多端口，用户看不到好处 |
| **复用同目录时不重启** | 重启会让用户正开着的编辑页面白屏 |
| **健康检查打 `/api/scene` 而非 `/`** | 后者只能证明 HTTP 起来了；前者能证明**场景已加载** |
| **进程归 Java 管，Python 不碰** | Python 只做一次性渲染（M6-1）；编排与生命周期归编排者 |
| **`MediaDir` 作为唯一媒体根** | M6-1 已抽；本任务复用，越界一律 400，不新开第二套路径解析 |
| **版本从 `package.json` 读，不跑 `--version`** | 实测 gimpish 0.1.0 **没有**该选项（打印 unknown option）→ 子进程探测永远拿到空串。已修，现在 `status.version = "0.1.0"` |

## 4. 变异测试：2 次注入均被检出（并顺带纠正了一次误判）

| # | 注入 | 结果 |
|---|---|---|
| M1 | `open` 绕过 `MediaDir.resolveSafe`（改用原始路径） | ✅ 检出（`EditorControllerTest` 1 failed） |
| M2 | 健康探测恒真 | ⚠️ **第一次没检出 → 实为等价变异**；改成"方法入口短路"后 ✅ 检出 |

> **M2 的教训值得留档**：第一版注入是 `return client.send(...).statusCode()==200` →
> `send(...); return true`。它**没被抓住**，但查下来**不是测试漏洞** —— 超时场景下 `send` 会抛异常，
> 根本走不到那个 `return`，所以对超时路径是**等价变异**。
> 把注入改成"方法入口直接 `return true`"才真正骗过超时路径，随即被检出。
> **纪律：变异没被抓住时，先判断它是不是等价变异，再怀疑测试。**

### 5.1 补验证：首轮 4 项未验证已全部补上，并**顺带修掉一个真实缺陷**

| 原未验证项 | 补法 | 结果 |
|---|---|---|
| 端口被占时 serve 自行退出的分支 | 单测（真实 bind 探测）+ E2E 用真占端口复现 | ✅ `200 + needs_manual`，**降级 0.0s** |
| `open` 并发被互斥锁串行化 | 4 线程同时 open，launcher 慢 300ms | ✅ 只 spawn **1** 次，4 个结果都 ok |
| 前端「再次点击收起」 | E2E `D2` | ✅ iframe 移除 + 文案还原 |
| 前端"未装 gimpish 时按钮仍在" | E2E 降级模式 `H2/H3/H4` | ✅ 入口仍在 + 给安装指引 |

**顺带发现并修掉的真实缺陷**：`gimpish serve` 在端口被占时**不会退出**（实测它照样活着），
所以"进程死了就快速降级"这条救不了端口冲突 —— 实测 `open` 要**白等满 15s** 健康预算。
已加**端口前置探测**（spawn 之前先自己 `bind` 一次，判据与 `scripts/doctor.py::port_in_use` 一致，
且**刻意不设** `SO_REUSEADDR` —— Windows 上它允许绑到别人已监听的端口，等于没测）。
**15.3s → 0.0s**。

**顺带修掉的前端问题**：编辑器入口原先只在"封面成功"分支渲染，缺工具时表现为**功能凭空消失**；
`docs/68` §4 本来就要求入口常在。已改为与封面成败无关，失败时点了把原因讲清楚。

## 6. 观察（**不是缺陷**）

| 观察 | 判定 | 说明 |
|---|---|---|
| iframe 与工作台**不同源**（:8080 vs :8765） | ⚠️ 固有限制 | 只能展示与操作，**读不到它内部 DOM**。E2E 因此把"编辑器渲染"放在**另一次导航**里验证，不假装能从 iframe 内部断言 |
| gimpish 编辑器是**给人用的窗口**，不是库 | ⚠️ 已知代价 | ADR-020 已接受：要承担它的 UI 稳定性；升版本必须重跑 `scripts/e2e_editor.py` |
| `scene` 指向封面目录而非稿件 | ✅ 设计如此 | 一个封面一个文档目录，互不干扰 |

## 8. 复现方式

```bash
# 1) Python（mock 隔离变量）
cd python-service
LLM_MOCK=true POLYFACE_GIMPISH=<gimpish 入口> POLYFACE_DATA_DIR=<scratch> \
  .venv/Scripts/python.exe -m uvicorn app.main:app --port 18000

# 2) Java（改了 index.html 必须重新 package，否则读的是 jar 里的旧副本）
bash scripts/mvn.sh -B -f java-backend/pom.xml package -DskipTests
POLYFACE_DATA_DIR=<scratch> POLYFACE_LLM_BASE_URL=http://127.0.0.1:18000 \
POLYFACE_EDITOR_PORT=18765 POLYFACE_GIMPISH=<gimpish 入口> \
  java -jar java-backend/target/polyface.jar --server.port=18080

# 3) 端到端
BASE=http://127.0.0.1:18080 POLYFACE_DATA_DIR=<scratch> POLYFACE_EDITOR_PORT=18765 \
  python-service/.venv/Scripts/python.exe scripts/e2e_editor.py
```
