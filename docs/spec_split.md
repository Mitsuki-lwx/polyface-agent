# spec —— 素材拆分（一个素材 → 多个素材源）

版本：2026-10-15　　对应 tasks：`docs/tasks_split.md`　　验收：`docs/checklist_split.md`
上游：`docs/01` §目标用户（"素材复用 + 风格重铸"）· Creative Minds Jam 选题
**Content repurposing across platforms**

---

## 1. 背景

**黑客松那个选题里的"复用"指的是「内容」的复用**（`docs/01` 开头写着），不是形式的复用。
现在这条链只走了一半：

```
一份素材 ──► 多平台稿件          ✓ 已做（实测 5 平台，261~1415 字）
一份素材 ──► 多个**素材**         ✗ 没做 ← 本版补这个
```

**差在哪**：现在一份素材只能"出一次稿"。但博主真正想要的是**一次创作、多次使用** ——
一篇文章能拆成几条口播、一条长视频能拆出几个选题。**拆出来的每一条，本身应该是一个
可以再走一遍完整管线的素材**（有自己的事实清单、能出多平台稿、能出成片）。

## 2. 目标用户

**现阶段只有作者本人**：他写完一篇长文，想知道"这篇能拆成哪几条短视频"。

## 3. 能力清单

1. **指定条数与角度**：用户说"拆成 3 条，分别从钱的视角、心理的视角、方法的视角"，
   就按这个拆 —— 不让模型自己决定拆几条（那多半拆出一堆相似的）
2. **派生为**子素材**（一等公民）**：拆出来的每一条都是一个**真正的素材** ——
   有自己的 id、自己的事实清单、能再走一遍完整管线（→ 多平台稿 → 成片）
3. **血缘可查**：子素材知道自己从哪个父素材、哪一条角度来的；父素材能看到自己拆出了哪些
4. **事实继承、且只用父素材的事实**：子素材的事实清单是父素材事实的**子集** ——
   拆分不能凭空造出父素材里没有的事实（这是防幻觉的底线）
5. **可复核**：每次拆分留下记录（拆了几条、每条的标题/角度/用了父素材的哪几条事实）
6. **拆分结果可改**：不满意可以只保留其中几条，其余的删掉 —— 不是一次性的
7. **不动父素材**：拆分只读父素材，不改它

## 4. 非功能要求

- **复用现有管线**：子素材进的是同一个素材表，不需要新的"稿件类型"
- **一次 LLM 调用**（不是每条一次）—— 拆分本身要快
- **失败要说清是哪一条**：某条角度没拆出来，要能说出是哪个角度
- **数据边界不变**：拆分走的就是现有的 LLM 配置，不引入新服务商

## 5. 设计骨架

```
父素材（已有事实清单）
   │
   ├─ 用户给：条数 + 每条的角度（"从钱的视角" / "从心理的视角"）
   ▼
  一次 LLM 调用（带父素材全文 + 事实清单 + 用户给的角度）
   │
   ▼
  子素材 ×N  ← 每个都是**一等素材**：自己的 id、自己的事实清单（父事实的子集）
   │           血缘：child.parent_id / child.angle
   ▼
  各自可以：→ 多平台稿件 → 成片 → 效果回填 → 复盘
```

**关键决定一：子素材是「一等素材」，不是"派生稿"。**

如果拆出来的只是几条稿件，那它们**只能发一次**（稿件的生命周期止于发布）。
而素材可以**反复走管线**：换平台、换模板、换配音、再出成片。
"一次创作多次使用"要成立，拆出来的东西就必须是素材。

**关键决定二：条数与角度由用户给，不让模型自己决定。**

模型自己拆的结果通常是"5 条都差不多" —— 因为它没有你的发布节奏、不知道你想强调什么。
用户给角度（哪怕只给一个词）能把结果钉在他要的方向上。

**关键决定三：事实清单是父素材的子集，一条都不能多。**

拆分是最容易**凭空造事实**的一步（"再编一个角度"的诱惑很大）。
所以子素材的事实必须**逐条来自父素材**，而且要能指出**来自父素材的第几条** ——
与既有的"事实依据声明"（`docs/spec_factguard.md`）同一条思路。

**关键决定四：一次调用拆完，不是每条一次。**

拆 5 条就是一次 LLM 调用（带上全部角度）。分开调会有两个问题：
互相不知道对方写了什么（容易重复）、以及 5 倍的等待与成本。

**其它骨架决定：**

- 复用 `material` 表，加 `parent_id` / `angle` 两列（老库自动补列）
- 走既有的异步任务化（`docs/spec_resume.md`）—— 拆分是分钟级，要能看进度、能断点续跑
- 拆分记录落盘（`split.json`）—— 哪条从哪个角度来、用了父素材哪几条事实

## 6. Out of Scope（本版不做）

- **模型自己决定拆几条**（见关键决定二）
- **跨素材合并**（几条素材合成一条）—— 那是另一个方向
- **拆出来的东西自动排队发**（沿用 ADR-010：不自动发布）
- **递归拆**（子素材再拆）—— 技术上可以，但先看一层够不够用
- **按形态拆**（长文版/口播版/金句卡片）—— 用户明确先做"按选题"
