# 关联本地素材库 —— 交付说明

> openspec change: `library-context-generation`
> 前置：`material-keywords-and-search`（关键词与检索 ✓）

## 一、形态（为什么不是"把库传给模型"）

| 字面做法 | 后果 | 实际做法 |
|---|---|---|
| 勾选 = 传整个库 | 库无限长、token 爆、无关素材污染 | **检索 top-3** ✓ |
| 只给"参考一下"的软指令 | 模型把**别人的事实**搬进来 ✗ | prompt 写死**事实只能来自本次素材** ✓ |
| 无声引用 | 两次产出差异无法解释 | **成稿里列出参考了哪几条** ✓ |

## 二、实现

| 层 | 改动 |
|---|---|
| `Store` | `relatedMaterials(excludeId, tags, limit)`：按命中关键词数排序，**排除自身与子素材** ✓ |
| `GenerateService` | `buildBody(..., useLibrary)`：勾选时带 `library_context[{id,title,snippet,keywords}]`，snippet ≤200 字、最多 3 条 ✓ |
| `GenerateRunner` / `JobController` | `params.use_library`（**只在其为 true 时写入** ✗ 未勾选时请求体与改动前一致 ✓）|
| Python | `GenerateRequest.library_context`；prompt 增 `reference_materials` + **事实隔离**规则；参考素材句子进 `avoid`（跨时间去重）✓ |
| 前端 | ② 选择平台 加复选框「关联本地素材库（只传 3 条，仅借鉴角度）」**默认不勾** ✓ |

## 三、实测（mock 模式，验管线）

同一素材 B（tags `AI/周报`），库里有 A（tags `AI/周报/复盘`）：

```
① 不勾选 → 稿 #1：参考警告 = 无 ✓
② 勾选   → 稿 #2：参考警告 =
   【参考素材】#1 周报三段式（仅借鉴角度；事实仍来自本次素材）✓
Java 日志：material 2 关联素材库：引用 1 条   （只在勾选那次出现 ✓）
```

## 四、未验证（如实）

1. **相关性好不好** ✗ —— mock 不比检索质量。要判断"取到的 3 条真的相关吗"必须真模型 + 真素材。
2. **会不会串题** ✗ —— 同上。prompt 里写死了事实隔离，且 factguard 会抓"本次素材里没有的数字/专名"，
   但语义级断言（把参考里的观点当成本次素材的观点）本来就抓不全 ✗。

这两条建议在**下一轮真实出片**时顺带看 ✓。

## 五、测试

- Python **1052 passed / 3 skipped**（新增 3 条：未传时 prompt 不变、注入含事实隔离、上限 3 条）
- Java **160 passed**（新增 3 条：按命中数排序并排除自身、limit、空关键词）

## 六、配置

- 引用条数上限：`GenerateService.MAX_LIBRARY_REFS = 3`（spec 要求"少数几条"）
- snippet 截断：200 字（价值在角度，不在全文）
