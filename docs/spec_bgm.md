# spec —— 带 BGM 的口播也能剪：VAD 找停顿 + 重建伴奏

版本：2026-10-17　　对应 tasks：`docs/tasks_bgm.md`　　验收：`docs/checklist_bgm.md`

---

## 1. 背景

**这是真素材一上来就撞到的缺口**（2026-10-17 实测）。

「口播粗剪」靠 `ffmpeg silencedetect`（**音量门限**）找停顿。但真实口播素材**普遍带背景音乐** ——
实测一条 64.76s 的社区口播素材：

```
mean_volume -13.6dB（电平正常）
门限 -30dB → 0 段静音
门限 -40dB → 0 段静音
门限 -50dB → 0 段静音      ← 降到 -50 仍然 0
```

BGM 把人声之间的空隙**填满了**，于是**一段停顿都找不到** → 剪点 0 → **粗剪等于什么都没做**。
工具当时如实说了「若素材里有背景音乐，本版不处理」—— 但**说得对 ≠ 能用**：
带 BGM 是默认情况，不是边角情况。

---

## 2. 目标用户

**现阶段只有作者本人**（沿用前几版定位）。拍口播、**会配 BGM**、不想为剪辑学一套软件的人。

---

## 3. 能力清单（一句话一条）

1. **带 BGM 的素材也能找到停顿** —— 判据是"人在不在说话"，不是"音量够不够大"
2. 停顿判定**不依赖 BGM 有无**：同一条素材，有无 BGM 应给出**同样的剪点**
3. **能识别素材里有没有 BGM**，并把结论告诉用户（而不是让他猜为什么剪点这么少）
4. 剪点处 **BGM 不跳**：人声按剪点剪，BGM **连续铺底**
5. 重建的伴奏**循环接缝听不出来**（"能用就行"级：不追求工作室音质，但不能有明显断点）
6. **降级路径**：VAD 不可用时退回"降噪 + 音量门限"，并**明确说明用了哪条路**
7. **两段式**：先给出剪点 + "BGM 会怎么处理 + 循环几次"，确认后才动手
8. 所有可调值**外露**（循环段最小长度、接缝交叉淡化、VAD 静音阈值……），三层优先级不变
9. 前置条件不满足时**大声失败**（没有音轨 / 找不到任何无人声窗口 → 说清为什么）

---

## 4. 非功能要求

- **全程本地**、不引入云服务（沿用 ADR-017）
- **不引入重依赖**：不拖 torch（这是本版与"人声分离"路线的分水岭，见 §5 关键决定二）
- **确定性**：同一输入 + 同一参数 → 同样的剪点与同样的伴奏重建
- **可单独重跑**：VAD 边界、伴奏片段都落盘，调参不必重新解码
- **速度**：停顿判定不应比现在的 `silencedetect` 慢一个数量级

---

## 5. 设计骨架

```
探测 → 【VAD 找语音边界】→ 边界之间的空隙 = 停顿
     → 【BGM 检测】有 BGM 吗？（有则走重建）
     → 【抽伴奏片段】从"无人声窗口"里截一段干净的伴奏
     → 【给你看：剪点 + 剪后时长 + BGM 怎么处理】→ 你确认/改参
     → 剪（人声轨按剪点）→ 铺伴奏（循环 + 交叉淡化）→ 混音 → 字幕 → 报告
```

### 关键决定一：**停顿的判据是"语音边界"，不是"音量门限"**（用户选）

`faster-whisper` 的 `vad_filter=True` **本来就在跑**（Silero VAD，开源）——
也就是说**转写这一步已经知道"人在哪儿说话"**，而且**与 BGM 无关**。
把它当作停顿判据，等于**零新依赖**地解决 BGM 问题。

而且去冗余阶段**已经在原文上转写过一遍**（`docs/spec_disfluency.md` 关键决定一）——
那一遍的段边界可以直接复用，**不用为找停顿再转写一次**。

**降噪兜底**（用户选"两者结合"）：VAD 不可用（缺 ASR / 模型加载失败）时，
退回 `ffmpeg arnndn/afftdn` 降噪 + `silencedetect`。两条路**都要在报告里说明用了哪条**。

### 关键决定二：**伴奏重建，不做人声分离**（用户选）

源文件是**混合轨**（人声 + BGM 录在一起），所以"剪掉停顿"必然让 BGM 跳。
要做到 BGM 连续只有三条路：

| 路线 | 代价 |
|---|---|
| 人声分离（Demucs，开源） | 真分离、音质最好；但**拖 torch（约 2GB）**、CPU 上约 1x 实时、发布包暴涨 |
| **重建伴奏（本版）** | 从"无人声窗口"截一段伴奏循环铺底；**零重依赖**；代价是 BGM 变成**循环**，不再是原编曲 |
| 接受跳变 | 最省事，但不满足"BGM 要连续" |

选**重建**：用户对音质的要求是"能用就行"，而拖 torch 会直接违背"本地一键启动"这个核心卖点。

**要如实告诉用户代价**：BGM 会变成循环（不是原编曲），接缝处可能听得出重复。
这一条必须写进方案里，不能藏在产物里。

### 关键决定三：**BGM 检测要主动做，并把结论说出来**

"有没有 BGM"不是靠猜：**VAD 说"没人说话"的窗口里，音量仍然不低** → 有 BGM。
检测结果要出现在方案里 —— 否则用户看到"0 段停顿"只会以为工具坏了（这正是本 spec 的由来）。

### 关键决定四：**两段式照旧**（用户选）

剪点 + "BGM 怎么处理 + 循环几次 + 循环段从哪来" 一起给人看，确认后才动手。
BGM 场景的不确定性比纯口播大（VAD 边界有偏差、循环接缝有风险），更需要人拦一道。

### 其它骨架决定

- 人声/伴奏的**混音电平可调**（重建的伴奏不该压过人声）
- 循环段的**最小长度**可调（太短的循环听得出周期）
- 接缝**交叉淡化**（淡化长度可调）—— 生硬拼接会有"咔"声
- 找不到任何"无人声窗口"（整条都在说话）→ **明确失败**，不硬凑一段伴奏

---

## 6. Out of Scope（本版不做）

- **不做人声分离**（不引入 Demucs/torch，见关键决定二）
- **不做色彩/音频美化**（降噪只为找停顿，不是为出片音质）
- **不做多轨素材**（只处理单条混合轨）
- **不做音乐识别**（不判断是什么 BGM、不做版权检测）
- **不改去冗余/字幕逻辑**，只在"找停顿"这一步换判据 + 加"铺伴奏"这一步

---

## 7. 已知风险

| 风险 | 应对 |
|---|---|
| VAD 边界不准 → 剪点偏 | 两段式让人确认；边界落盘可复核 |
| 循环接缝听得出重复 | 交叉淡化 + 循环段最小长度可调 + 报告里说明循环了几次 |
| 重建的伴奏与原 BGM 相位/调性不合 | 只用**同一素材**的无人声段（不是另找音乐）→ 音色天然一致 |
| 整条都在说话 → 没有干净伴奏 | 明确失败并说明；不硬凑 |
| 混音后总音量变化 | 混音电平可调 + 报告里给出混音前后电平 |

## ⚠️ 实现时的实测结果：**本 spec 的核心假设被推翻了**（2026-10-17）

### 测出来的事实

| 做法 | 结果 |
|---|---|
| 旧路径 `silencedetect`（-30/-40/-50dB） | 0 段停顿 |
| **复用转写段边界**算语音窗口 | **1 个**窗口 → 0 段停顿 ✗ |
| **直接调 Silero VAD**（faster-whisper 自带，`min_silence_duration_ms=800`） | **1 个**窗口 → 0 段停顿 ✗ |
| VAD + `afftdn=nf=-25` / `-40` / `anlmdn` / `highpass+afftdn` 降噪 | **全部** 1 个窗口 ✗ |
| **对照：干净音频（无 BGM）** | **10 个窗口 / 9 段停顿** ✓ |

### 结论

**VAD 本身没问题** ✓ —— 干净音频上工作得很好（9 段停顿）。
**是 BGM 击败了它** ✗：Silero 在带 BGM 的轨道上认为**全程都是语音**。

而 **ffmpeg 内置降噪救不回来** ✗ —— `afftdn`/`anlmdn` 针对的是**稳态噪声**，
**音乐不是噪声** ✓，四条链路全部无效。

### 因此本 spec 的两条关键决定**站不住**

- 关键决定一「**复用 ASR 的段边界**」✗：实测只算出 1 个窗口（`vad_filter` 是为切段调的，
  调得很粗，会把停顿并进语音段）。
- 关键决定二「**重建伴奏**」✗：它需要先找到"无人声窗口"——
  而 BGM 恰恰让这个窗口**找不到**（VAD 认为全程有人声）。**鸡生蛋**。

### 还成立的部分

- **`vad_speech_windows` / `pauses_vad`（`pipeline/bgm.py`）**：对**无 BGM** 素材
  是真能用的（对照实验 9 段停顿 ✓），比 `silencedetect` 更贴近"人在不在说话"。
- **`detect_bgm` / `pick_bed_clip` / `denoise_wav`**：逻辑成立，但**在带 BGM 素材上
  拿不到输入**（`has_bgm` 检测需要"无人声窗口"，同样拿不到）。

### 真正的岔路（需要重新决策）

要支持带 BGM 的素材，只剩**人声分离**这一条 —— 而当前 spec 明确排除了它（拖 torch）。
轻量替代是 **ONNX 路线**（`onnxruntime` 约 50MB + 一个 MDX/Demucat ONNX 模型），
比 torch 轻得多，但仍是**新依赖 + 新模型**。这需要用户重新拍板。
