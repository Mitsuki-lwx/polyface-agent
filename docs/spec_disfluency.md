# spec —— 口播去冗余：去口误 / 重复句 / 口头语 / 半句废弃

版本：2026-10-17　　对应 tasks：`docs/tasks_disfluency.md`　　验收：`docs/checklist_disfluency.md`

---

## 1. 背景

「口播粗剪」已经能把**停顿**剪掉（`docs/spec_roughcut.md`）。但停顿只是"死气"的一部分。

真实口播素材里更常见的是**说错了话**：

- 同一句说了两遍（想换个说法，结果前一遍没删）
- 说错了当场纠正（「不对，我是说……」「抱歉重来」）
- 半句废弃（「我们今天要讲的……我们今天要讲的是……」）
- 满嘴填充词（嗯、啊、那个、就是）

这些**剪不掉**，成片就还是毛坯。而它们和停顿一样：**规则明确、错了肉眼可见**——
正是该交给程序做的那类事。

现状：粗剪只处理静音段。**用户得自己在剪辑软件里听一遍找这些**，一次 10 分钟的素材要花半小时。

---

## 2. 目标用户

**现阶段只有作者本人**（沿用粗剪的定位）：会写稿、会拍口播、但不想为剪辑学一套软件的人。

明确不服务陌生人 —— 不做安装引导、不做跨平台打磨。

---

## 3. 能力清单（一句话一条）

1. 给一个本机视频文件，找出**四类冗余**：重复句 / 自我纠正 / 口头语 / 半句废弃
2. 每一段都要能说出**为什么判它是冗余**（哪一类、依据是什么）——
   不能只给一个"这里剪掉"，人要能复核
3. **四类各自可开关**（有人不在意口头语，有人只想去重复句）
4. 判定的**尺度必须可改**（多像才算重复、口头语词表、最短片段多长才值得剪）——
   没有普适值，不同人语速/口癖差别很大
5. **两段式**（沿用粗剪）：先把"打算剪哪几段 + 为什么 + 剪完多长"给你看，
   你确认或改参后才真的动手
6. 冗余剪点与**停顿剪点合并**成一份剪点清单 —— 用户看到的是一次剪，不是两次
7. 判定分两层：**规则打底**（快、确定、零成本）→ **模型复核**（抓换措辞的重说）
8. **模型只做"判定"，不做"决定"**：它标出可疑段与理由，剪点由程序合并，最终由人确认
9. 模型不可用时**降级到纯规则**并明确告知（不静默少剪一类，也不假装跑过模型）
10. 冗余判定**绝不越界**：只剪**连续语音**内部的片段，绝不剪掉整段开头/结尾的独立内容
11. 前置条件不满足时**大声失败**（没有音轨 / 缺 ASR / 缺 ffmpeg）—— 沿用粗剪的错误风格

---

## 4. 非功能要求

- **全程本地**：音频/文本不出本机（**例外**：若用户显式开启模型复核，转写文本会发给用户自配的 LLM —— 见 ADR-017 的数据边界，UI 要标明）
- **确定性**：同一输入 + 同一参数 + 同一模型版本 → 同样的判定（规则层必须确定；模型层可复跑但要有温度=0 的默认）
- **可解释**：每条判定都要能打印"依据"（相似度多少 / 命中哪个词 / 模型的原话）
- **可单独重跑**：转写结果、判定结果都落盘保留 —— 调参不必重新转写
- **不引入新依赖**（复用现有 ffmpeg / 本地 ASR / LLM 客户端）
- **速度**：10 分钟素材的**判定**（不含转写）应在秒级完成；转写是主要成本

## 5. 设计骨架

```
粗剪现有：  探测 → 找停顿 ─────────────────────┐
                                              ↓
新增：              转写原文 → 规则判定 → 模型复核 → 合并剪点
                                              ↓
粗剪现有：        【给你看：剪点 + 每段理由 + 剪完多长】 → 你确认/改参
                                              ↓
                              剪 → 转写（剪后）→ 字幕 → 烧字幕 → 报告
```

### 关键决定一：**先转写原文，再剪**（与粗剪相反）

粗剪的骨架是「先剪再转写」，理由是字幕时间戳天然落在剪后时间轴上，省掉重映射。

**冗余判定必须先有文本**，所以这一环只能反着来：在**原始**视频上转写一次，拿它做判定，
剪完再转写一次出字幕。

代价是**两遍 ASR**（实测约 0.2x 实时：10 分钟素材约 2 分钟）。接受这个代价，因为：
- 重映射时间戳是"一整块容易写错的逻辑"（粗剪 spec 原话），而它省下的只是一遍 ASR
- 判定需要的是**原文时间轴**，剪后轴上的文本已经被剪得七零八落，判不准

### 关键决定二：**模型只判定，不决定**

模型返回的是"这段疑似重复，因为它和前一段说的是同一件事"，**不是**"剪掉第 12.4–15.1 秒"。
剪点由程序按统一规则合并（重叠、最短长度、边界回退），最后交人确认。

理由：模型给时间戳不可靠（它看不到音频），给"判断"才是它的强项。

### 关键决定三：**规则打底，模型只复核规则标出的可疑段**

不是把全文丢给模型（贵、慢、还容易整体跑偏），而是：
规则先找出高置信的（完全重复、命中口头语词表、明显的半句重起），
**只把规则拿不准的相邻句子对**交给模型判断"这两句是不是在说同一件事"。

这样模型的输入是**受控的小集合**，成本可预测，且模型挂了也不影响主体能力。

### 关键决定四：**边界回退，宁少剪不多剪**

剪点的边界要**向两侧回退**（回退到最近的语音边界 + 一点余量）。
宁可少剪半秒留一点拖沓，也不要剪掉半个字 —— 剪错一句话的代价远大于多留 0.3 秒。

### 其它骨架决定

- 判定结果**落盘**（每条含：区间、类别、依据、来源=规则/模型）—— 这是"可解释"和"可复核"的载体
- 与停顿剪点**合并后再给人看**：用户只面对一份剪点清单
- 参数沿用粗剪的三层优先级：`内置默认 < 配置文件 < 命令行`
- 口头语词表**外露成可改的配置**，不写死在代码里

## 6. Out of Scope（本版不做）

- **不做语义级的"废话"删除**（比如"这段讲得不够好"）—— 那是重写稿子，不是剪视频
- **不做语气词的美化**（把"嗯"变成停顿而不是剪掉）—— 只做删除
- **不做跨句的语序调整**（把后面的话挪到前面）
- **不做多人对话的分角色处理**
- **不做自动配 BGM / 卡点**（那是 B2 的另一块）
- **不引入云端 ASR**（沿用 ADR-017）
- **不改粗剪已实现的停顿/字幕能力**，只做"在剪点里多加一类来源"

---

## 7. 与现有能力的关系

| 现有 | 关系 |
|---|---|
| 口播粗剪（停顿 + 字幕） | **宿主**：冗余判定是给它多加一类剪点来源 |
| 本地 ASR 适配层 | **复用**：新增"要词级时间戳"的入口 |
| LLM 客户端 | **复用**：只用于"这两句是不是同一件事" |
| 数据边界（ADR-017） | **受影响**：开启模型复核时，转写文本会发出本机 —— 必须让用户知道 |

---

## 8. 已知风险

| 风险 | 应对 |
|---|---|
| **误剪正话**（最严重） | 两段式 + 逐段给理由 + 边界回退；宁可少剪 |
| 模型把"排比句"当成重复 | 规则层先做高置信判定，模型只看可疑对；报告里标来源 |
| 转写错字导致判定失败 | 判定用**相似度**而非精确匹配；转写错误对相似度影响有限 |
| 两遍 ASR 让端到端变慢 | 中间产物落盘：调参不重跑 ASR；报告里给出各阶段耗时 |
| 口头语剪太干净反而失真 | 词表可改 + 可关闭该类；报告里说明剪了多少个 |
