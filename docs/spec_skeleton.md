# spec —— 骨架式改写（Extract-then-select：段落级骨架 + 事实槽位回填）

版本：2026-10-25　　对应 tasks：`docs/tasks_skeleton.md`　　验收：`docs/checklist_skeleton.md`
上游：`docs/76-幻觉对策-可行性判断.md`（方案 A+D 合并版，骨架硬度取**段落级**——用户 2026-10-25 拍板）　　决策：`docs/08` **ADR-025**

---

## 1. 背景与要治的病

`docs/76` 的基线结论：评测失败的大头不是"数字抄错"（A1，5 次），而是
**越界推断型新增断言**（A7，15 次）——素材说「要交286块」，成稿写「漏交了286块」；
凭空加「半年数据」。这类问题 **prompt 禁令治不了**（`DRAFT_SYSTEM` 早已写"禁止编造"），
QA 也只能**事后发现**（factguard 那轮已把 QA 喂了素材原文，判得更准了，但产物没变好）。

本任务把 draft 阶段从「自由重写正文」改成「**先产骨架，代码装配**」：

> 模型不再直接写正文，而是写**段落级骨架**：每段声明依据哪几条事实 + 段内文本；
> 段内每个数字/年份/专名必须写成**槽位** `{{n:序号|表层}}`，由代码验证依据后原样回填。
> 正文 = 各段文本拼接，**事实值由代码钉死，表述由模型自由**。

机制上达成：
- **A1/A2（数字/年份）清零**：裸数字过不了机械门，槽位表层验证数值等价后才回填。
- **A7（新增断言）大幅收窄**：新增断言只能藏在"段内非数字文本"里，且
  QA 的「超出 facts_used 声明」检查从**形同虚设**（模型曾全量声明）变成**真核对**
  （facts_used 改由代码从段声明计算）。

## 2. 目标用户

作者本人（生成质量的第一责任人）。不是新 UI 功能：不接界面、不加安装引导。

## 3. 契约（新 draft 产物形状）

模型（真实模式）只输出一个 JSON —— **骨架**：

```
{
  "titles": ["主标题", "备选2", "备选3"],        // 标题里的数字/年份也必须走槽位
  "paras": [
    {"facts": [1, 3], "role": "hook",            // facts: 本段依据的事实序号(1-based)
     "text": "上月我被迫交了{{n:3|286块}}，{{n:1|收益}}直接腰斩——你敢信？"}
    , {"facts": [2], "role": "body", "text": "后来摸清了三步，第{{n:2|一步}}最关键……"}
  ],
  "tags": ["…"],
  "cover_suggestion": "…",
  "interaction_line": "…",
  "rationale": "…"
}
```

- **槽位语法**：`{{n:<事实序号>|<表层写法>}}`。一律带表层 —— 模型写句子时本来就
  决定了用哪个词；写下来让验证有明确对象。回填 = 表层**原样**替换槽位
  （模型控制表述，代码只验证依据）。
- **role** 取 `hook|body|evidence|close`，仅 advisory（顺序 = 数组顺序，代码不重排）。
- **段落事实声明 `facts`**：本段全部事实性内容的依据集合。槽位引用必须 ⊆ 该集合。
- **titles**：数字/年份同样走槽位；标题的证据集合 = **全部事实清单**（标题是全篇层面，
  不绑定段）。
- tags / cover_suggestion / interaction_line：自由文本（A1 类机械断言仍会兜底扫）。

## 4. 机械门（装配时，QA 之前）

装配器 `assemble_skeleton(skeleton, facts) -> (DraftPayload, violations)`：

| # | 检查 | 级别 |
|---|---|---|
| G1 | 槽位序号合法（1..len(facts)）且 ⊆ 所在段（或标题：全部事实）的声明集合 | 硬 |
| G2 | 槽位**表层有依据**：表层是 `facts[n].text` 子串；或表层数值 ∈ `num_values(facts[n].text)`（zhnum 归一，两侧口径同 `_rule_qa`：素材侧宽松）；或表层为 `proper.extract` 在 `facts[n].text` 命中的专名 | 硬 |
| G3 | **裸数字/年份拦截**：回填后的每段文本里，数字 token 的数值必须 ∈ 该段声明事实的数值 ∪ 已验证槽位表层的数值；年份同口径（A2）。数字/年份违规 = 硬；疑似未声明专名 = 软（warning，交 QA） | 硬（数字/年份）/ 软（专名） |
| G4 | 结构：≥1 段、每段非空、titles 非空（沿用既有"可交付性必须由规则守住"） | 硬 |

**口径只有一份**：数字/年份/专名判定全部复用 `numberish` / `zhnum` / `proper`
（`_rule_qa` 同源）——评测集 A1/A2/A3 测的就是这条链路。

**facts_used 由代码计算** = 所有段 `facts` 声明的并集。模型不再自报
（实测它会把 [1..10] 全声明了，让 attribution 形同虚设）。
三态语义保留：facts 恒非 None（代码产物），`[]` = 全文没用任何事实（合法但罕见）。

**违规处理（fail-closed，对齐 FR-70 精神）**：
1. 首次装配违规 → 带**违规清单**定向修复一轮（重调 draft，同 scene）；
2. 修复后仍硬违规 → 该平台**显式失败**（error 注明 `skeleton_gate` + 违规明细），
   不静默带病产出；
3. 软违规 → 进 DraftPayload 后续 QA 的 warnings。

## 5. 流程变化

```
旧：draft(自由正文) → qa → (不过→定向重写)
新：draft(骨架) → assemble+gate → (硬违规→骨架修复×1) → qa → (不过→定向重写，仍走骨架)
```

- **不新增 LLM 调用**（修复轮仅在违规时发生）；scene 名仍是 `draft`
  （trace/usage 观测面零改动）；提示词版本号按 ADR-024 自动更新
  （`SCENE_BUILDERS["draft"]` 指向新构造函数）。
- **mock 模式走同一条装配路径**：`_mock_draft` 改为构造骨架
  （text = 事实原句、facts = [i]，天然过门），不再手拼 body ——
  "逻辑只有一份"，mock e2e 也能暴露装配器的 bug。
- **Java / API / 存储零改动**：`DraftPayload` 形状不变，body 是装配出的字符串。
- QA（含两阶段、verifier、`--reassert`）不动 —— 它核对的证据（素材原文、
  facts_used）都还在，且 facts_used 从此可信。

## 6. 非功能要求

- 装配器是**纯函数**（骨架+事实 → 产物+违规），可单测、可被评测复用。
- 槽位解析宽容：`{{n:3|286块}}` 之外的常见变形（`{{3|286块}}`、全角 `｛｛｝｝`）
  尽量识别；识别不出按裸文本处理 → 会被 G3 拦下（宁拦不漏）。
- 回填后正文里**不留任何 `{{`**（有残留 = 装配失败，硬违规）。
- 性能可忽略（纯正则 + 既有口径函数）。

## 7. Out of Scope（本版不做）

- 句级/从句级骨架（更硬的约束）—— 若段落级实测 A7 仍高，再评估
- 标题的段落绑定 —— 标题证据集合取全部事实（见 §3）
- tags/cover_suggestion/interaction_line 的槽位化
- NLI 校验（`docs/76` 方案 B，仍搁置）
- understand/brief/clip 阶段的骨架化（draft 是幻觉源头，只动它）
- 旧自由正文路径的保留开关 —— 不留双路径，回退靠 git 与评测对比（ADR-025）
