# 任务书：音视频转文字入料（FR-51 / M3.5）

## 1. 背景与问题

目前素材入口**只有"粘贴文本"**。但创作者的真实素材大量躺在本地视频/音频里：

> 口播视频、访谈录音、直播回放、已经剪好的成片 —— 想二次利用，得先手打成文字。

手打成本极高（10 分钟口播 ≈ 1 小时打字），导致"已有内容资产"无法进入本工具的改写链路。

## 2. 目标

**本地文件 → 转录/提取出文字 → 用户校订 → 转成素材 → 走现有 understand 管线。**

1. 支持指定本机视频/音频文件
2. 探测媒体信息（时长、音轨、字幕轨）
3. **优先免算力路径**：若视频内嵌字幕轨 → 直接提取文字
4. 无字幕时：可选本地 ASR 转写（若环境具备）
5. 转录文本**必须先给用户审阅/编辑**，确认后才创建素材
6. 全流程本地完成，**不上传任何数据**

## 5. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 媒体探测/提取 | **ffmpeg + ffprobe**（已具备） | 零新依赖，成熟稳定 |
| 字幕提取 | `ffmpeg -map 0:s:0` 提取字幕轨 → 去时间轴 | 免算力，秒级，覆盖率不低（口播类常带字幕） |
| ASR 转写 | **可选**：faster-whisper（CTranslate2，无需 torch） | 本地推理、无外部上传；作为"环境具备则增强"，不作硬依赖 |
| 转写兜底 | 提示安装指引 + 允许手动粘贴 | 保证无 ASR 环境下功能不废 |

> **关键决策**：ASR 做成**可选增强**而非硬依赖——否则"本地一键启动"会被拖入 torch/模型下载（数百 MB ~ 数 GB）的泥潭。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Python 3.13 无 ctranslate2 wheel | faster-whisper 装不上 | ASR 为可选；装不上则仅走字幕提取 + 指引，不阻塞主流程 |
| 大文件（>1GB 视频）处理慢 | 请求超时 | 只提取音频（不做视频转码）；ffprobe 先探时长并提示；避免整文件读入内存 |
| 无字幕且无 ASR 的文件 | 用户以为功能坏了 | 明确区分三种状态：`subtitle_extracted` / `transcribed` / `needs_manual`，各自给可执行指引 |
| 路径访问越权（任意路径读取） | 本地工具风险有限但需收敛 | 仅接受本机存在的媒体文件；校验扩展名与 ffprobe 可识别性；不提供目录遍历 |
| ffmpeg 未安装 | 全功能不可用 | 启动/调用时探测，给出明确安装提示（含已装路径示例） |
| 版权 | 用户导入他人作品 | UI 提示"请仅处理自有或已获授权的内容" |
