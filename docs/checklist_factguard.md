# checklist —— 事实约束加固（只约束事实，不约束句式）

上游：`docs/spec_factguard.md`　　tasks：`docs/tasks_factguard.md`

> 每一项都必须**可勾选、可观测**。不许出现「实现完整」「质量良好」这类无法判定的项。
> **至少一条端到端验收**（§7）。验收完必须如实填 §8 与「未做」。

---

## 1. 默认值表（**每一项都必须能被覆盖**）

| 项 | 默认值 | 覆盖方式 | 说明 |
|---|---|---|---|
| 加固总开关 | 开 | `.env` / 环境变量 | 关掉即退回加固前的行为 |
| 数字检查 | 开 | 同上 | 复用 `numberish` 那套口径，不另造 |
| 年份检查 | 开 | 同上 | |
| 专名检查 | 开 | 同上 | 白名单抽不到时不检查（宁可不查，不可误报） |
| 新增断言检查 | 开 | 同上 | 靠 LLM QA，问题已收窄成"有没有超出声明范围" |
| 重写轮数上限 | 1 | 同上 | 沿用现状；调大要有可观测的多一轮 |
| 专名补充词表 | 空 | 同上 | 用户补自己的行业词 |
| 严格程度 | `standard` | 同上 | `loose`=只报不拦 / `standard`=不过则重写 / `strict`=不过即判失败 |

**验收**：上表每一行都要在 §2 里有对应的「改了它，行为确实变了」的观测。

---

## 2. 参数可改（**本轮的核心验收**）

- [ ] 关掉**总开关** → 一个原本被拦的产物**通过了**（行为确实退回）
- [ ] 关掉**数字检查** → A1 类问题不再被拦，其余三类照旧
- [ ] **重写轮数上限 = 2** → 日志里能看到第二轮重写（原本只有一轮）
- [ ] **严格程度 = loose** → 同样的问题只出现在 warnings 里，`passed` 仍为 true
- [ ] **严格程度 = strict** → 同样的问题直接判失败，不进入重写
- [ ] 往**专名补充词表**里加一个词 → 该词不再被报（原本会报）
- [ ] 任一可调值改了而行为没变 → 该项**不通过**

---

## 3. 机械校验（数字 / 年份 / 专名）

**正例（不许误报）**：

- [ ] 正文数字来自**素材原文**但**不在 3~10 条事实清单里** → **不报**
      （这是本次的核心修复：证据集合从"事实清单"扩到"素材原文 ∪ 声明的事实"）
- [ ] 「我跑了 3 公里」「12 个月」这类句中数字 → 不报
- [ ] 正常中文里的「迈出这一步」→ 不报

**反例（必须报）**：

- [ ] 正文出现素材里没有的数字 → 报，且**指出是哪个数**
- [ ] 正文出现素材里没有的年份 → 报
- [ ] 正文出现素材里没有的**专名**（如凭空写「飞书」而素材只有「Notion」）→ 报
- [ ] 三类报错能**分别开关**（关掉专名检查后专名不再报，数字照报）

**边界**：

- [ ] 素材里一个专名都抽不出 → 专名检查**静默跳过**，不报"检查失败"
- [ ] 专名白名单里**不出现普通词**（人工过一眼 10 条素材的抽取结果）

---

## 4. 声明契约（attribution）

- [ ] 产物里**能看出**本次用了哪些事实
- [ ] **没声明**与**声明了空**在行为上不同（前者应视为违规，后者是合法的"没用到事实"）
- [ ] 字段是**可选**的 —— 既有调用方与测试不被一次性打红
- [ ] 模型**谎报**依据时（声明 f1 但正文超出 f1）：机械校验用**并集**做白名单，
      所以不会因此放水；且 QA 能看到"声明与正文不符" → 报

---

## 5. QA 与定向重写

- [ ] QA 的输入里**有素材原文**（不再是只有 3~10 条事实）
- [ ] QA 的问题**已收窄**成"有没有超出声明范围"（不是笼统的"有没有幻觉"）
- [ ] 喂一个已知超出声明的产物 → 指出**具体句子**与**类别**
- [ ] 四类（数字/年份/专名/新增断言）各构造一个失败产物 → 重写指令里出现**对应类别与定位**
- [ ] 重写指令**不出现**开放式建议（分类是封闭的四类）
- [ ] 单平台 LLM 调用次数**不增加超过 1 次**（现在最多 4 次）

---

## 6. 评测集对齐（测不了就等于没做）

- [ ] 新增断言 **A9 事实有依据（专名）**，与 A1（数字）、A2（年份）并列
- [ ] 变异测试：把 A9 的实现注释掉 → 对应测试**变红** → 还原
- [ ] 变异测试：把 A1 的实现注释掉 → **变红** → 还原
- [ ] `--reassert` 能在**不调 LLM** 的前提下复算（改断言不必重跑 5 小时）

## 7. 端到端（**至少一条**）

- [ ] **全平台跑一轮**（5 平台 × 10 条），拿到报告
- [ ] 与基线对比（`--baseline eval/reports/20261008-205056/report.json`）：
      **A7 从 15 降到 ____**、A1 从 5 到 ____、A2/A9 各 ____（验收时如实填）
- [ ] 通过率与基线 52% 对比：____（**降了也是结果，不许调阈值把它调上去**）
- [ ] **改写质量人看一眼**：随机抽 3 条通过格，确认没有变成"填模板"的腔调
      —— spec 关键决定一的代价就在这，必须实际检查
- [ ] 失败归因仍分得清：调用失败 / 机械校验失败 / QA 失败 三类在报告里分列

---

## 8. 诚实边界（验收时必须如实填）

- [ ] 明确记录：本版**只约束事实、不约束句式** —— 全骨架化**没做**，
      所以"模型把两个事实连成一个新断言"这类仍可能漏网
- [ ] 明确记录：NLI 实验的结论是**方向性**的（23 条正样本 + 同等负样本），不是精确指标
- [ ] 明确记录：专名抽取**只覆盖可靠形态**，中文机构名不抽 —— 宁可不查，不可误报
- [ ] 明确记录：LLM 非确定性 → 同一素材两次跑分结果不会完全一致，
      **不能**把 ±1~2 格的波动当退化
- [ ] 明确记录：单模型（`cline-pass/deepseek-v4.1-flash`），未做多模型对比

## 9. T5 决策门（**先定死，避免事后找理由**）

| 结果 | 结论 |
|---|---|
| 幻觉召回 ≥ 80% **且** 正常句误报 ≤ 10% | **通过** —— 另开 spec 谈引入 |
| 召回 < 80% | **不通过** —— 漏判的幻觉比不查更糟 |
| 误报 > 10% | **不通过** —— 会变成新一类噪声，且更难排查 |

- [ ] 实验记录里**明确写了**「通过」或「不通过」（不许写"效果还可以"）
- [ ] 若通过：结论里带上"样本量小、方向性"的限制
- [ ] 若**不通过**：**不做** NLI，如实记录原因，不要"先做一半再说"

## 实测（进行中，2026-10-09）

**单格验证**（`m01` × `xhs`，加固前 vs 加固后）：

| | 基线 | 加固后 |
|---|---|---|
| `facts_used` | `None`（未声明） | `[1..10]` ✓ 接线生效 |
| A7 通过质量门 | FAIL（QA 拦下幻觉） | **OK** |
| A3 标题合法 | FAIL | FAIL（超 20 字上限，真问题） |

### ⚠️ 已发现一个设计弱点（如实记）

**模型会把全部事实都声明了**（实测 `facts_used = [1,2,...,10]`）。
这样一来「有没有超出声明范围」就永远问不出问题 —— **attribution 形同虚设**。

好在本版真正起作用的改动不是 attribution，而是**给 QA 素材原文**（T4）+
**证据集合扩到素材原文**（T3）。attribution 目前只是个弱信号。

**可能的改法**（未做，留待量完差距再定）：把声明做成**逐段**而不是整篇，
或对"声明了全部事实"这种退化声明单独告警。

### 遇到的坑（都已修）

1. **`run_draft` 漏传 `facts_used`** —— 逐字段构造时漏了一行，
   不报错、测试全绿，功能永远 None。补了接线守卫测试
2. **A9 在 19/50 格上误报，全是同一个词 `AI`** —— 平台 DNA 要求「AI 辅助创作需标明」，
   草稿合法地写了「AI」，素材里当然没有。补两轮通用缩写词表后误报归零，
   **但 A9 的失败数也是 0** —— 新增断言 ≠ 新增覆盖
3. **专名抽取放宽成「≥4 字母的全小写词」** 会把 `brain`/`second`/`collaborator`
   这些普通词抽进来 → 收紧成「必须含大写字母或数字」
