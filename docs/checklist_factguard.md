### ⚠️ 必须说清的两点

**1. 每轮都是单次采样，模型有随机性。**

`A7` 在 factguard 那两轮是 8 与 9（同一份代码、只差标题修复，而标题修复不该影响 A7）——
这就是**单次采样的噪声**。所以：
- **52% → 78% 这个量级是可信的**（+26 点远超噪声）
- 但**±1~2 格的变化不能当结论**（checklist §8 已写明这条）

**2. `A3 9→0` 是"归零"，不是"减少"。**

修的是**根因**（上限没传给模型），不是"让模型更听话"。修后 xhs 标题长度：

```
修前: [20,18,22] [29,25,25] [21,23,20]   超限 5 个
修后: [13,11,11] [14,14,14] [18,18,19]   超限 0 个
```

标题短了但**质量没降**（「裸辞一年，月入8千到1万2」）。

```
DNA:      specs.title_chars_max: 20            ← 调研出来的真值
传给模型: title_rules: ["多用数字+结果", ...]   ← 只有散文，**没有长度**
         limits: {body_chars_max: 1000, ...}   ← 没有标题上限
```

**模型不知道小红书标题要 ≤20 字**。而产品自己的 `_rule_qa` 又写死 `>24 字才警告` ——
21~24 字的标题**连产品自己都不报**。

修法（三处）：`dna.title_chars_max()` 暴露真值 → `build_draft_prompt` 显式传给模型 +
`DRAFT_SYSTEM` 明确要求 → `_rule_qa` 改用平台上限（不再写死 24）。

**修后实测**（xhs 前 3 条，修前 → 修后）：

| 素材 | 修前标题长度 | 修后标题长度 |
|---|---|---|
| m01 | `[20,18,22]` 超限 1 | **`[13,11,11]` 超限 0** |
| m02 | `[29,25,25]` 超限 3 | **`[14,14,14]` 超限 0** |
| m03 | `[21,23,20]` 超限 2 | **`[18,18,19]` 超限 0** |

标题短了但**质量没降**（「裸辞一年，月入8千到1万2」）。
剩下 2 处失败都是 A7 的真问题（小标题与素材冲突、新增断言），不是标题。
