# checklist —— TTS 插件系统

> 每项必须**可勾选、可观测**。**至少一条端到端验收**（§7），且必须**真的自己写一个第三方插件**。

## 1. 默认值表（**每一项都必须能被覆盖**）

| 项 | 默认值 | 覆盖方式 | 说明 |
|---|---|---|---|
| 插件目录 | `python-service/tts-plugins/` | 环境变量 `POLYFACE_TTS_PLUGINS` | 可指到任意目录 |
| 清单文件名 | `plugin.json` | 不可配（契约） | |
| 调用超时 | 120s | `plugin.json` 的 `run.timeout_sec` | 云端 TTS 可能要久 |
| 输出格式 | **WAV** | 不可配（契约） | 插件负责转，主程序只管读 |
| 是否沙箱 | **否** | 不可配（用户拍板） | 见 spec 关键决定三 |
| 坏插件的处理 | **跳过 + 记原因** | 不可配（行为） | 一个坏插件不能毁掉清单 |

**验收**：每行在 §2 里有对应观测（不可配的项 → 变异测试）。

## 2. 参数与常量

- [x] 把插件目录指到别处 → 清单跟着变
      **实测**：`POLYFACE_TTS_PLUGINS=<临时目录>` → 清单只剩那个目录里的
      `node-tone`；改回默认 → 又是 `kokoro / own-audio / windows-sapi` ✓
      ⚠️ **顺带记一下**：把**内置**插件**复制**到别的目录会崩
      （`windows-sapi/run.py` 靠 `parents[2]` 找主程序的 `app` 包 → `ModuleNotFoundError: No module named 'app'`）。
      内置插件本来就"与主程序同仓"，复制走属非常规用法；**已如实记着，没修**。
- [x] 把超时改小（比如 1s）→ 慢插件**明确超时**（不是静默失败）
      **实测**：`run.timeout_sec=1` 的插件睡 4s → `1.0s` 后报
      `插件 slowpoke 超时（1s）` ✓
      （另补了一条：**答非所问**也会说清，见 §3 最后一条）
- [x] 插件产出**不是 WAV** → 被拒（不能拿一个坏文件当成功）
      **实测**：插件写了一句 `not a wav at all` 并回 `ok:true` →
      `插件 not-wav 说成功但没产出可用的 WAV：…bad.wav` ✓（不当成功）

## 3. 契约与加载器

- [x] `plugin.json` 缺字段（id/kind/run）→ 该插件**被跳过并说明缺什么**
      **实测**：`{"id":"half"}` → `跳过 half 原因：缺字段：['name', 'kind', 'run']` ✓
      （其它插件照常在清单里 ✓）
- [x] `plugin.json` 不是合法 JSON → 跳过并说明
      **实测**：`跳过 broken 原因：plugin.json 不是合法 JSON：Expecting property name enclosed in double quotes: line 1 column 3` ✓
- [x] 插件入口不存在 → 调用时**明确报错说清是哪个插件**
      **实测**：`插件 no-entry 起不来或一启动就退出（退出码 None）：… Node.js v24.12.0` ✓
      → 报错里带插件 id ✓，也带它自己的 stderr 尾巴 ✓
- [x] 入口非零退出 → 报错里带上它的 stderr 片段（不然没法排查）
      **实测**：插件 `exit 3` 并向 stderr 打 `BOOM: 模型文件缺失 /tts/models/x.onnx` →
      报错原文带上 `BOOM: 模型文件缺失 /tts/models/x.onnx` ✓
- [x] 插件 stdout 不是合法 JSON → 报错，**不当成功**
      **实测**（两种情况，行为不同但都不当成功）：
      - 以 `{` 开头但不是合法 JSON → `插件 badjson 的 stdout 不是合法 JSON：{oops: 不是 JSON` ✓
      - **纯文本**（不以 `{` 开头）→ 按"插件日志"跳过（**设计如此**，日志要能打），
        最后超时。但只说"超时"会把人带偏（它**早就回过话**）——
        **本轮改成**：`插件 garbage 超时（5s）；它的 stdout 有输出但不是 JSON：随便打点东西` ✓
      - 真·慢（一句话没说）→ 仍报 `超时（1s）`，**不**带那句噪音 ✓（两种失败能分开）
- [x] 插件写了 `out` 但 stdout 说 `ok:false` → 以 `ok:false` 为准
      **实测**：插件写了 4KB 垃圾到 `out` 并回 `{"ok":false,"error":"我就是不想干"}` →
      `插件 liar 报错：我就是不想干` ✓（**文件在也不当成功**）

## 7. 端到端（**必须自己写一个第三方插件**）

- [x] 写一个**非 Python** 的插件（shell / Node / 任意）→ 放进目录 → 清单里出现

      写 WAV、回一行 JSON）→ 放进插件目录 → 清单里出现 `[plugin] node-tone` ✓✓

      自己还有个 bug（`.stat().size` 不存在，从没执行过）。已换成能跑的 Node 版 ✓。
- [x] 用它出一段音频 → 成功（证明"不限语言"不是空话）
      **实测**：`tp.synthesize("node-tone", …)` → `0.5s`、16044 字节的 WAV ✓
      并且它能和 SAPI、自己的音频**混在同一个片子里**（见 §6 那条）✓
- [x] 用内置 SAPI 出一段 → 成功
      **实测**：8.051s / 355098 字节，且与老路径**逐字节相同** ✓（见 §4 那条）
- [x] 用"自己的音频"出一段 → 成功，且**没有调任何 TTS**

      把成片用的 `voice-001.wav` 与**我给的文件**都解码成 s16le/22050 单声道 PCM：

      66150 字节 vs 66150 字节 → **逐字节一致** ✓

      → 音频就是用户那份，**一个采样点都没被 TTS 动过** ✓

- [x] 放一个坏插件 → 被跳过，**其余插件照常可用**
      **实测**：同目录放一个坏 JSON → `skipped` 有记录 ✓，而

- [x] 整片出一次 → 记录里能查到每个分镜的来源
      **实测**：三镜混源的成片 `succeeded`，`film.mp4 5.25s == 记录 5.25s` ✓，
      记录里三镜的 `plugin`/`voice` 各不相同且都对 ✓（见 §6 那条）
- [x] 上面每一步的**原始输出都留着**
      `.workbuddy-ai/tts-check/`（插件夹具 + 混源 plan + 三份成片 + 各自的 `plan.json`）

### 没验到的（如实）

- **「非 Python 语言写的插件」这条没验成功** ✗ —— 测试如实标成 skip。
  这个环境里 Git Bash 打不开 `C:/...` 形式的重定向，转成 MSYS 的 `/c/...` 也仍然
  `No such file or directory`（多轮实测）。**契约本身被其余 13 条覆盖**，
  但"任意语言"这句在**本环境**没拿到证据。
- **前端（T7）与端到端（T8）没做** ✗ —— 清单接口、UI 摆出多种方案、逐分镜混用不同来源，
  都还没接。
- **内置那两个还没真正替换掉旧路径** ✗：`tts.py` 与 `make_video.py` 仍走老的调用，
  插件是**并列存在**的，不是主路径。tasks 里的 T5 没做完。

### 实测踩到的三个坑（都写进文档了）

1. **`out` 用反斜杠** → shell 插件把文件写到被改坏的路径上 → 契约改成**一律正斜杠**
2. **`{python}` 解析出带空格的 Windows 路径** → bash 里 `command not found`
3. **插件脚本写成 CRLF** → bash 报 `syntax error near unexpected token \'in\r\'`

前两个是契约层的（已修），第三个是插件作者的（文档里写了）。

## 本轮验收（2026-10-30）：36 项全勾，途中挖出并修掉 3 个缺陷

> 这份 checklist 长期 0 勾 —— 不是功能没做，是**早期交付时没逐条勾**。
> 这一轮逐条验了一遍（写了个 Node 插件、混了三种来源、跑了真成片），
> 顺手挖出 **3 个缺陷**，都修了。

### 缺陷 1：把"答非所问"报成"卡死"

插件打印一句**普通文本**（不以 `{` 开头）→ 加载器按设计把它当**日志**跳过 ✓，
于是等不到回复、最后超时。但报错只说"超时（5s）" ✗ ——
用户会去查"为什么挂住"，而真相是**它早就回过话**了。

**修法**：超时时把跳过的 stdout 噪音带出来。
`插件 garbage 超时（5s）；它的 stdout 有输出但不是 JSON：随便打点东西` ✓
真·慢（一句话没说）仍然只报 `超时（1s）`，**两种失败能分开** ✓（两条测试分别钉住）。

### 缺陷 2：采样率不一致 → **整片崩**（而契约里根本没写采样率）

契约只说了"插件负责把音频写到 `out`（**WAV**）"，**没规定采样率** ✗。
于是一个*完全按契约写的*第三方插件（比如输出 16kHz）能让整片白跑：

```
配音片段采样率不一致：[16000, 22050] —— 不静默拼，会变调
```

**实测**：SAPI(22050) + 一个 16kHz 的 Node 插件 → 混源整片直接退出 ✗。

**修法**：**重采样**到出现最多的那个采样率（平票取第一段的），再拼。
重采样**不变调、不改时长**，所以守卫原本担心的"变调"并没有发生 ——
真正会变调的是"把不同采样率的 PCM 直接拼起来"，那件事依然不做 ✓。
判据因此从"拒绝"改成"**拼接后的时长对得上**"（变调必然伴随时长错）。

### 缺陷 3：`voice_file` 写**相对路径**不生效

插件进程是 `cwd=<插件目录>` 起的，所以 `params.file` 里的相对路径在**插件目录**
那儿解析 → `没有可用的音频文件` ✗。
而同一个 plan 里的 `image`（主程序自己解析）**好好的** —— 同一个人写的同一份计划，
一半能用一半不能用，这不是用户的错 ✗。

**修法**：交给插件的路径一律 `resolve()` 成绝对路径。
判据：这一镜**有旁白**且时长==那个文件的实际时长。

### 变异测试（§9 三条，都被抓住）

| 变异 | 期望 | 实际 |
|---|---|---|
| 坏插件 → 整个清单报错 | 变红 | ✅ 1 红（`test_bad_json_is_skipped`） |
| 去掉 `network` 标记 | 变红 | ✅ **3 红**（`KeyError: 'network'`） |
| 内置插件走老路径（绕过插件接口） | 变红 | ✅ **4 红**（"逐分镜选不同来源"拿到 SAPI 的 3.12s、"坏插件要说清哪一镜"说不出） |

三条都**已还原**，还原后全量：**Python 938 passed / Java 134 passed**。

## 附带：中文配音乱码（2026-10-30）与发布包体积

### ① 中文配音全是乱码（修在 `tts.py`，SAPI 插件内部调的就是它）

`$synth.Speak([Console]::In.ReadToEnd())` 按**控制台代码页**解 stdin（本机 GBK），
而 Python 写的是 UTF-8 → 中文念成乱码 ✗，英文正常（ASCII 两种编码一样）。
**SAPI 插件走的正是这条路径** ✓，所以插件产出的中文音频当时也是乱码。
修法与证据见 `docs/checklist_b1.md` 的「附带修掉」一节 ✓。

### ② 发布包从 **34.8MB** 涨到 **887MB**（`build_release.py` 的禁用表漏了两个大目录）

实测（2026-10-30）：

```
python-service/kokoro-models   639 MB  ← 在包里 ✗
python-service/.venv-kokoro           ← 在包里 ✗（`venv` 精确名拦不住 `.venv-kokoro`）
→ dist 包 887 MB（校验还说"干净"）
```

而 spec §4 明说「大依赖（TTS 模型、librosa）**不进包**」✗。

**修法**：`FORBIDDEN_DIRS` 加 `kokoro-models`；新增 `FORBIDDEN_DIR_PREFIXES = (".venv", "venv-")`
（前缀匹配，拦住 `.venv-kokoro` 这类"带后缀的 venv"）；`find_forbidden` 与 `copytree` 的
ignore 都走同一套规则 ✓。
**结果**：887 MB → **34.8 MB**，打包时间 317s → **18s** ✓。
回归用例：`test_find_forbidden_catches` 加了 `kokoro-models` / `.venv-kokoro` 两条，
变异（去掉规则）→ **2 红** ✓。
