# checklist —— TTS 插件系统

上游：`docs/spec_tts_plugin.md`　　tasks：`docs/tasks_tts_plugin.md`

> 每项必须**可勾选、可观测**。**至少一条端到端验收**（§7），且必须**真的自己写一个第三方插件**。

---

## 1. 默认值表（**每一项都必须能被覆盖**）

| 项 | 默认值 | 覆盖方式 | 说明 |
|---|---|---|---|
| 插件目录 | `python-service/tts-plugins/` | 环境变量 `POLYFACE_TTS_PLUGINS` | 可指到任意目录 |
| 清单文件名 | `plugin.json` | 不可配（契约） | |
| 调用超时 | 120s | `plugin.json` 的 `run.timeout_sec` | 云端 TTS 可能要久 |
| 输出格式 | **WAV** | 不可配（契约） | 插件负责转，主程序只管读 |
| 是否沙箱 | **否** | 不可配（用户拍板） | 见 spec 关键决定三 |
| 坏插件的处理 | **跳过 + 记原因** | 不可配（行为） | 一个坏插件不能毁掉清单 |

**验收**：每行在 §2 里有对应观测（不可配的项 → 变异测试）。

---

## 2. 参数与常量

- [ ] 把插件目录指到别处 → 清单跟着变
- [ ] 把超时改小（比如 1s）→ 慢插件**明确超时**（不是静默失败）
- [ ] 插件产出**不是 WAV** → 被拒（不能拿一个坏文件当成功）

---

## 3. 契约与加载器

- [ ] `plugin.json` 缺字段（id/kind/run）→ 该插件**被跳过并说明缺什么**
- [ ] `plugin.json` 不是合法 JSON → 跳过并说明
- [ ] 插件入口不存在 → 调用时**明确报错说清是哪个插件**
- [ ] 入口非零退出 → 报错里带上它的 stderr 片段（不然没法排查）
- [ ] 插件 stdout 不是合法 JSON → 报错，**不当成功**
- [ ] 插件写了 `out` 但 stdout 说 `ok:false` → 以 `ok:false` 为准

---

## 4. 内置也走同一套接口

- [ ] SAPI 以**插件形态**出现在清单里
- [ ] "用户自己的音频"也出现在**同一张清单**里
- [ ] 内置与第三方插件走的是**同一条调用路径**（`grep` 确认没有第二套调用代码）
- [ ] 迁移后 SAPI 合成的音频与迁移前**一致**（不能悄悄变差）

---

## 5. 清单（catalog）

- [ ] 一张清单里同时能看到：SAPI 的音色、"自己的音频"、第三方插件
- [ ] 每个条目带 `network` 标记 —— **要联网的插件必须标出来**
- [ ] 每个条目带 `note`（用户得知道它是干什么的）
- [ ] 清单里有坏插件被跳过的**记录**（不是静默消失）

---

## 6. 逐分镜选不同来源

- [ ] 同一份计划里，分镜 1 用 SAPI、分镜 2 用"自己的音频" → 两个都生效
- [ ] 记录里能查到**每个分镜**用了哪个插件、哪个音色
- [ ] 某个分镜的插件失败 → **说清是哪个分镜、哪个插件**；其余分镜照常

---

## 7. 端到端（**必须自己写一个第三方插件**）

- [ ] 写一个**非 Python** 的插件（shell / Node / 任意）→ 放进目录 → 清单里出现
- [ ] 用它出一段音频 → 成功（证明"不限语言"不是空话）
- [ ] 用内置 SAPI 出一段 → 成功
- [ ] 用"自己的音频"出一段 → 成功，且**没有调任何 TTS**
- [ ] 放一个坏插件 → 被跳过，**其余插件照常可用**
- [ ] 整片出一次 → 记录里能查到每个分镜的来源
- [ ] 上面每一步的**原始输出都留着**

---

## 8. 诚实边界（验收时必须如实填）

- [ ] 明确记录：**不做沙箱** —— 装插件等于执行任意代码，界面上必须明说（不是免责声明，是如实说明）
- [ ] 明确记录：插件**可以联网**，那会改变数据边界（ADR-017）—— 所以 `network` 必须声明并被转述
- [ ] 明确记录：本版**只做 TTS**，别的部分插件化是下一期
- [ ] 明确记录：不做插件市场/在线安装/签名校验
- [ ] 明确记录：**Kokoro 在本机仍有两个坑**（Python 版本、jieba）——
      插件化让它不再是死结（用户可以插别的），但**不代表它现在就能跑通**
- [ ] 明确记录：插件是用户自己装的，程序**不替它的质量与合法性背书**

---

## 9. 变异测试（**必须做，绿不等于有效**）

- [ ] 把"坏插件跳过"改成"整个清单报错" → §3 的断言**变红** → 还原
- [ ] 把 `network` 标记去掉 → §5 的断言**变红** → 还原
- [ ] 把内置插件改成走老路径（不走插件接口）→ §4 的断言**变红** → 还原

---

## 实测（2026-10-11）

### 已验（13 条单测）

| 断言 | 结果 |
|---|---|
| 缺 `plugin.json` / 坏 JSON / 缺字段 / kind 不是 tts → **跳过并说明原因** | ✓ |
| **一个坏插件不影响好的** | ✓（核心断言） |
| 找不到插件 / 入口不存在 → 报错**带上插件 id** | ✓ |
| 非零退出 → 报错**带上它的 stderr** | ✓ |
| 说 `ok:true` 却没产出 WAV → **不当成功** | ✓ |
| 超时 → 明确报"超时" | ✓ |
| `network` 标记如实转述 | ✓ |
| 内置两个（SAPI / 自己的音频）**在默认目录里**且都标 `builtin` + `network:false` | ✓ |

冒烟（真跑）：`catalog()` 一张清单里同时有 `windows-sapi`（3 个音色）与 `own-audio`；
SAPI 插件合成出 3.70s 音频 ✓；"自己的音频"插件 3.70s ✓。

### 没验到的（如实）

- **「非 Python 语言写的插件」这条没验成功** ✗ —— 测试如实标成 skip。
  这个环境里 Git Bash 打不开 `C:/...` 形式的重定向，转成 MSYS 的 `/c/...` 也仍然
  `No such file or directory`（多轮实测）。**契约本身被其余 13 条覆盖**，
  但"任意语言"这句在**本环境**没拿到证据。
- **前端（T7）与端到端（T8）没做** ✗ —— 清单接口、UI 摆出多种方案、逐分镜混用不同来源，
  都还没接。
- **内置那两个还没真正替换掉旧路径** ✗：`tts.py` 与 `make_video.py` 仍走老的调用，
  插件是**并列存在**的，不是主路径。tasks 里的 T5 没做完。

### 实测踩到的三个坑（都写进文档了）

1. **`out` 用反斜杠** → shell 插件把文件写到被改坏的路径上 → 契约改成**一律正斜杠**
2. **`{python}` 解析出带空格的 Windows 路径** → bash 里 `command not found`
3. **插件脚本写成 CRLF** → bash 报 `syntax error near unexpected token \'in\r\'`

前两个是契约层的（已修），第三个是插件作者的（文档里写了）。
