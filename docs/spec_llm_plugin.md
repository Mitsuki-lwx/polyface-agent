# spec —— LLM 插件系统

版本：2026-10-15　　对应 tasks：`docs/tasks_llm_plugin.md`　　验收：`docs/checklist_llm_plugin.md`
上游：`docs/spec_tts_plugin.md`（同一套思路）· ADR-017（数据边界）

---

## 1. 背景

配音已经插件化了（`docs/spec_tts_plugin.md`）：拷个目录进去就多一种声音，
内置的三个与第三方走同一条路。**LLM 还是写死的** —— 换服务商要改 `.env` 再重启，
也不能同时配好几个（便宜的做改写、贵的做质检）。

## 2. 与 TTS 插件的关键差别

| | TTS 插件 | LLM 插件 |
|---|---|---|
| 形态 | **可执行入口**（stdin/stdout JSON） | **声明式**（一个 JSON 说清怎么连） |
| 为什么 | 要跑模型/调引擎，得能写代码 | 绝大多数就是"一个 OpenAI 兼容端点" |
| 联网 | 可能不联网（本地模型） | **一定联网** |

**LLM 插件不做成"可执行入口"** —— 那会让"接一个自己的 API"变成写程序。
声明式更贴需求：填个 `base_url` + 指个 key 的环境变量就完事。
（真需要写代码的场景 —— 自定义请求格式 —— 留给下一期，不在本版。）

## 3. 能力清单

1. **插件就是一个目录**：`llm-plugins/<id>/plugin.json`，声明 `base_url`、
   key 从哪个环境变量取、有哪些模型
2. **一张清单**：所有可用 LLM 摆在一起（内置的 + 用户自己加的），带 `network` 与说明
3. **可切换**：选哪个由环境变量/接口决定，**不用改代码、不用重启**（下一次调用就生效）
4. **模型有角色**：一个插件里可以声明多个模型（生成用哪个、质检用哪个），
   以及回退链的顺序
5. **key 不进仓库、不进日志**：插件只声明**环境变量的名字**，值仍然只在 `.env`
6. **内置的也走同一套**：现有 `.env` 配置就是一个内置插件 —— 迁移不能破坏它
7. **坏插件不能毁掉清单**：与 TTS 插件同一条规矩

## 4. 非功能要求

- **数据边界必须如实**：LLM 一定联网 → 每个 LLM 插件都标 `network: true`，
  界面上明说"素材正文会发到这里"
- **不打印 key**：任何日志、错误、清单里都不能出现 key 的值（只出现变量名）
- **失败说清是哪个插件哪个模型**（现在是"LLM 调用失败"，看不出走的哪家）
- **不破坏现有行为**：没装任何插件时，行为与现在完全一致

## 5. 设计骨架

```
python-service/llm-plugins/
  env-default/            ← 内置：读现有 .env（迁移的起点，保证不破坏）
    plugin.json
  <用户自己拷进来的>/
    plugin.json           ← {id, name, kind:"llm", network:true,
                             base_url, api_key_env, models:[{id, role, note}]}
```

**关键决定一：声明式，不是可执行入口。**

TTS 插件要跑模型所以必须能写代码；LLM 插件绝大多数只是"一个端点 + 一把钥匙"。
做成可执行入口会把"接自己的 API"变成"写个程序"，与需求相反。

**关键决定二：只声明环境变量的名字，不存 key 的值。**

`plugin.json` 会进版本库、会被拷来拷去 —— 里面**绝不能有 key**。
所以它写 `"api_key_env": "MY_LLM_KEY"`，值仍在 `.env` 里。

**关键决定三：模型带角色，回退链可声明。**

现在 `model_chain()` 是写死的顺序。插件里声明 `models: [{id, role}]`，
`role` 是 `generate` / `qa` / `fallback` —— 这样"便宜的做改写、贵的做质检"
不用改代码。

**其它：**

- 选中的插件用 `POLYFACE_LLM_PLUGIN` 指定；不指定时用内置的 `env-default`
- 清单接口 `/api/llm/plugins`；界面上与配音并列摆出来
- 复用 TTS 插件那套"坏插件跳过并记原因"的加载逻辑

## 6. Out of Scope（本版不做）

- **可执行入口型的 LLM 插件**（自定义请求格式）—— 见关键决定一
- **多插件并行/路由**（按场景自动选不同插件）—— 先做"能选"，不做"自动选"
- **key 的加密存储 / 凭据管理** —— 继续走 `.env`
- **本地模型**（llama.cpp 之类）—— 那是"可执行入口型"，留给下一期
- 别的部分（渲染/封面）的插件化
