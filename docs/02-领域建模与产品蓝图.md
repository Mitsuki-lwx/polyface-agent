## 1. 竞品快研（2026-09 桌面调研结论）

### 1.1 竞品地图

| 类别 | 代表产品 | 核心能力 | 与本产品的差异 |
|---|---|---|---|
| 一键分发/矩阵工具 | 蚁小二、易媒助手、融媒宝 | 多账号登录、批量发布到几十个平台、数据汇总、定时 | **只解决"发"不解决"写"**：无平台调性改写，格式常错乱需手改；SaaS 收费，账号/素材在云端 |
| AI 文案/爆款生成器 | 红抖 AI、笔尖AI、Friday、写作兔、七燕 | 单平台文案、爆款仿写、标题生成、敏感词检测 | 生成是"通用文案"，**不含创作者记忆**；多为矩阵/搬运场景，合规风险叙事差 |
| 素材/排版工具 | 135编辑器、Canva、稿定 | 排版、模板、配图 | 解决"呈现"不解决"内容重生" |
| 中台/数据工具 | 新榜、蝉小红 | 榜单、数据、选题 | 数据视角，不做内容生成 |

### 1.2 调研结论（机会窗口）

1. **"跨平台内容再利用"市场验证存在**：多篇 2025 测评确认创作者真实痛点是——多平台运营时
   "格式错乱要手改、文案同质化、不同平台规则不熟、容易被限流"。
2. **现有工具两极分化**：分发工具不管内容质量；AI 写作工具不管平台调性。**中间地带（感知平台
   调性的内容再利用）是空位**。
3. **合规与信任成为新痛点**：平台对 AI/搬运内容治理趋严，"改写自己素材、保留事实、不搬运"
   的合规定位有差异化价值，也适合开源传播。
4. **本地化 = 数据主权卖点**：素材是博主核心资产，本地存储 + 自带 Key + 开源，天然解决
   "我的素材和账号数据在不在别人服务器上"的信任问题。
   ⚠️ **但必须说清楚边界**（ADR-017）：本地化解决的是"**不交平台方 / 无云端账号 / 长期留存**"，
   **不等于生成过程不出网** —— 素材正文仍会发送给用户自配的 LLM 服务商。把它说成"数据不出本机"就是过度承诺。

## 2. 领域建模

### 2.1 核心实体（v1）

```
┌─────────────┐  拥有   ┌──────────────┐
│ CreatorProfile │──────▶│   Material     │ 一份原始素材（源文本）
│ (博主画像/声音) │        │  (素材)        │
└─────────────┘        └──────┬───────┘
                              │ 解析(understand)
                              ▼
                        ┌──────────────┐        ┌──────────────┐
                        │  FactList    │        │ PlatformDna  │ 平台DNA(规则/风格)
                        │ (事实清单,    │        │ (9平台 profile)│
                        │  防幻觉依据)  │        └──────┬───────┘
                        └──────┬───────┘               │
                               │ brief×N 平台          │
                               ▼                        ▼
                        ┌──────────────────────────────────┐
                        │  Draft 稿件 (per platform)        │
                        │  title[]/body/tags/hooks/cover    │
                        └──────────────────────────────────┘
                               │ 人工确认 / 复制发布
                               ▼
                        ┌──────────────────────────────────┐
                        │  Feedback 效果回填               │
                        │  (播放/点赞/收藏/评论 手动录入)    │
                        └──────────────────────────────────┘
                               │ 触发复盘(定期/手动)
                               ▼
                        ┌──────────────────────────────────┐
                        │  Review 复盘报告                 │
                        │  ▶ 回写 CreatorProfile 画像      │
                        │  ▶ 建议 PlatformDna 参数调整      │
                        └──────────────────────────────────┘
```

### 2.2 实体清单

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **Material** | id, title, raw_text, source_kind(长文/口播/大纲/笔记), status | 素材本身；只增不改 |
| **Fact** | id, material_id, text, type(data/story/opinion) | 解析出的事实清单；供 QA 防幻觉比对 |
| **CreatorProfile** | id, name, domain, voice, audience, goals | 品牌声音画像；复盘回写 |
| **PlatformDna** | platform_code, version, rules_json | 每平台一份：风格/结构/标题/标签/红线/字数上限 |
| **Draft** | id, material_id, platform_code, status, payload_json(title[]/body/tags/hooks/cover/rationale), qa_json | 平台成稿；QA 结果挂载 |
| **Feedback** | id, draft_id, platform_code, metrics_json(播放/赞/藏/评/转), note | 效果回填（v1 手动） |
| **Review** | id, material_id, summary_json | 复盘报告；产出画像/参数建议 |
| **GenerationTask** | id, material_id, platform_codes[], status | 一次"素材→N平台"的批任务，支持断点续跑 |

### 2.3 状态机

- **Material**：`raw → parsed → briefed → drafted → reviewed → closed`
- **Draft**：`pending → generating → qa_passed → approved(人工) → published → feedback`
  - 失败分支：`qa_failed → regenerating(≤1次) → qa_passed`
  - 人工可随时 `edited`（手动改稿覆盖 AI 稿）
- **GenerationTask**：`running(记录各平台进度) → done/failed`，重启后可续跑未完成平台

## 3. 产品蓝图（MVP = 素材 → 5 平台成稿全链路）

### 3.1 用户旅程（一位想"一稿多发"的博主）

```
1. 打开本地应用(双击 start.bat)
2. 粘贴自己的一篇旧文/口播稿/大纲 ──────────────┐
3. 查看解析出的"事实清单"，可增删确认          │ ← 用户唯一需要人工介入的质量点
4. 勾选目标平台(小红书/抖音/公众号/知乎/B站)     │
5. 一键生成 → 看到 5 个平台的稿件卡片            │
6. 逐平台审阅：标题候选/正文/标签，可编辑        │
7. 复制到平台发布（工具不自动发布，红线）        │
8. 几天后回填效果数据 → 系统沉淀复盘             │
9. 下次生成自动带上"这个号/这类内容什么风格有效"  ┘
```

### 3.2 页面结构（Web UI）

| 页面 | 内容 |
|---|---|
| 首页/工作台 | 最近素材 + 任务进度 + 新建入口 |
| 素材详情 | 源文本、事实清单编辑、核心观点确认 |
| 生成工作台 | 平台勾选 → 任务进度 → 各平台稿件卡片 |
| 稿件审阅 | 单平台稿：标题候选/正文/标签/封面建议 + 改写说明 + 编辑 + 复制 |
| 复盘页 | 历史效果、洞察报告、画像设置 |
| 设置页 | LLM Key/模型、数据目录、平台 DNA 版本 |

### 3.3 非功能要求（本地工具特有）

- 启动 ≤ 5s（不含首次 LLM 预热）；离线可看历史稿件
- 素材与稿件存**本地 SQLite**（可选升级 Postgres）；**可离线启动并查看历史稿件**（mock 模式全流程离线），但**真实生成必须联网**（ADR-017）
- 无账号体系（单机单用户）；将来要同步再叠加
- 平台 DNA 以 **YAML 文件**形式随包发布，用户可改、可升级（`platform-dna/*.yaml`）

## 4. 技术架构（本地一键启动）

### 4.1 进程拓扑

```
┌─ 用户浏览器 (http://127.0.0.1:8080) ─┐
│   静态资源(React 构建产物)             │
└───────────────┬─────────────────────┘
                │ HTTP
┌───────────────▼─────────────────────────────┐
│ Java 后端 :8080 (Spring Boot)               │
│  ├ 业务编排: 任务状态机/断点续跑/稿件落库      │
│  ├ 静态托管: /web 前端                      │
│  └ 本地存储: SQLite (素材/稿件/画像/复盘)     │
└───────────────┬─────────────────────────────┘
                │ HTTP (本机回环)
┌───────────────▼─────────────────────────────┐
│ Python LLM 服务 :8000 (FastAPI)             │
│  ├ /analyze  素材解析→结构化+事实清单          │
│  ├ /brief    平台策略                        │
│  ├ /draft    单平台成稿                      │
│  ├ /qa       质量门(规则+LLM自评+防幻觉)      │
│  └ LLM 适配: SenseNova(OpenAI 兼容) 可切换   │
└─────────────────────────────────────────────┘
```

- **Java 负责"业务与编排"，Python 负责"LLM 计算"**——职责清晰，两边可独立测试。
- LLM Key 只存在于 Python 侧 `.env`，Java 通过配置转发，**密钥不进入仓库、不上传**。

### 4.2 LLM 配置（SenseNova / OpenAI 兼容）

```env
# python-service/.env
LLM_PROVIDER=openai-compatible   # 实际请求走 OpenAI SDK 兼容层
LLM_BASE_URL=https://token.sensenova.cn/v1
LLM_API_KEY=sk-xxxxxxxx
LLM_MODEL=sensenova-6.8-flash-lite
LLM_QA_MODEL=sensenova-6.8-flash-lite
```

> 与 SenseNova 示例一致：`OpenAI(base_url=..., api_key=...)` 直接可用；将来换 DeepSeek/
> 通义/OpenAI 只改 base_url + model，架构零改动。

## 6. 风险与对策（增量）

| 风险 | 对策 |
|---|---|
| 开源后被复制 | 护城河在平台 DNA 库 + 复盘记忆，非单次生成；先跑通再开源 |
| 平台 DNA 侵权风险 | 全部自研整理，注明"方法论参考公开运营实践"，不逐字复制 |
| 目录名含空格 | git 仓库名独立规范命名（下条决策） |
| 商汤模型在部分任务质量波动 | QA 自评兜底；保留多模型可切换 |
| AI 内容平台治理 | 只产出建议稿 + 标注 AI 辅助，用户自查后发布 |
