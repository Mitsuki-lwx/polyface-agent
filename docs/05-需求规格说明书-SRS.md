## 1. 引言

### 1.1 目的
本文档定义 Polyface 的功能需求（FR）、非功能需求（NFR）、范围与边界，作为后续
M3~M5 开发的验收基线；同时服务开源协作与参赛材料。

### 1.2 产品概述
**一句话**：一份素材进，千面出——把同一份原创素材，自动改写为符合各平台调性、
有机会获得流量的完整可发布稿件。

- 形态：**本地一键启动的 Web 应用**（下载即用，数据不出本机）
- 进程：Java 后端(:8080，编排+存储) + Python LLM 服务(:8000) + 浏览器 UI
- 覆盖：v1 国内 5 平台（小红书/抖音/公众号/知乎/B站），海外 4 平台规划中
- LLM：SenseNova（OpenAI 兼容），未配 Key 自动 mock 离线模式

### 1.3 术语
| 术语 | 含义 |
|---|---|
| 素材 Material | 用户输入的源文本（长文/口播稿/大纲/笔记） |
| 事实清单 Fact | 从素材抽取、供防幻觉校验的可追溯信息项 |
| 平台 DNA | 平台风格/结构/标题/标签/红线/爆款逻辑的结构化规则（YAML） |
| brief | 平台策略（角度/钩子/结构/标签方向） |
| draft | 单平台成稿 |
| qa | 质量门（规则校验 + 自评 + 防幻觉比对） |

## 2. 用户与目标

### 2.1 目标用户
| 用户 | 场景 |
|---|---|
| 跨平台迁移作者 | 已有某平台内容资产，希望复用素材低成本开新平台 |
| 多平台个人博主 | 一份素材发多平台，逐平台人工改写耗时且质量不稳 |
| 工作室/矩阵号 | 素材库统一、批量产出变体、沉淀"什么风格能火"的账号记忆 |

### 2.2 产品目标
1. 把"改写一份素材到 N 个平台"的时间从小时级降到分钟级；
2. 产出**平台化**而非"格式换皮"——语言风格、结构、标题、标签、互动都贴合平台；
3. 守住事实底线：产出不含素材之外编造的数据/头衔/细节（防幻觉）；
4. 数据与账号主权留在用户本机（本地 SQLite + 自带 Key）。

## 3. 功能需求（FR）

> 优先级：M=Must(必备) S=Should(应该) C=Could(可选)。状态：✅已实现 / 🚧进行中 / ⬜待开发。

### 3.1 素材与解析
| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| FR-01 | 录入素材文本并标注类型(长文/口播稿/大纲/笔记) | M | ✅ M1 |
| FR-02 | 解析素材 → 核心观点/语气/受众/事实清单 | M | ✅ M1 |
| FR-03 | 事实清单展示并可人工增删改（发布前的最后把关） | M | 🚧 M3 UI |
| FR-04 | 素材历史管理与再次复用（素材库） | S | 🚧 M4 |

### 3.2 平台化改写（差异化核心）
| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| FR-10 | 内置平台 DNA 库（小红书已建；抖音/公众号/知乎/B站 M3 补齐） | M | 🚧 |
| FR-11 | 平台 DNA 支持随包升级与用户自定义 | C | ⬜ M5 |
| FR-12 | 按平台 DNA 生成策略 brief（角度/钩子/结构/标签方向） | M | ✅ M2 |
| FR-13 | 按策略+事实清单生成各平台成稿 draft | M | ✅ M2(xhs)/🚧M3 |
| FR-14 | 一次性勾选多个平台，并行生成 | M | ✅ 引擎 / 🚧 UI |

### 3.3 质量保障（QA）
| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| FR-20 | 规则校验：字数上限、标签数量/格式、标题缺失 | M | ✅ M2 |
| FR-21 | 防幻觉：正文新增数字/断言须在素材事实清单有依据（无依据→warning 拦截） | M | ✅ M2(规则)/真实 LLM 校验 🚧 |
| FR-22 | 真实模式 LLM 自评（按平台爆款清单打分）；未通过带反馈重写一轮 | M | ✅ M2 |
| FR-23 | 人工审阅时可手动编辑稿件，覆盖 AI 稿 | M | 🚧 M3 UI |

### 3.4 记忆与复盘（护城河）
| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| FR-30 | 效果回填：发布后录入播放/赞/藏/评 | S | ⬜ M4 |
| FR-31 | 复盘：基于效果档案产出"该账号/平台/内容类型什么有效"洞察 | S | ⬜ M4 |
| FR-32 | 创作者画像（品牌声音/领域/受众）配置 | S | ⬜ M4 |
| FR-33 | 复盘结论回写：二次生成自动带上历史经验 | S | ⬜ M4 |

### 3.5 系统与导出
| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| FR-40 | LLM 配置可视化（provider/base_url/key/model + 连通测试） | M | 🚧 M3 UI |
| FR-41 | 稿件复制/导出（平台独立格式） | M | 🚧 M3 UI |
| FR-42 | 生成任务断点续跑（中断后可续未完成平台） | S | ⬜ M3 |
| FR-43 | Web 工作台（素材→平台勾选→稿件审阅） | M | 🚧 M3 |

### 3.6 AI 剪辑（A→C→B 分期）
> 目标平台（抖音/B站/远期 YouTube）本质是视频平台，仅给文字稿会断掉价值链条。
> 分期：A 轻量先上 → C 解决入料 → B 本地自动成片（均只产出文件，不上传不发布）。

| 编号 | 需求 | 优先级 | 阶段 |
|---|---|---|---|
| FR-50 | **剪辑单**：抖音/B站/YT 成稿附带"分镜时间轴+画面建议+字幕断句+BGM/转场提示"的剪辑执行单 | M | M3（与 UI 同批） |
| FR-51 | **视频/音频转文字入料**：粘贴视频/音频路径或链接 → 转录口播稿 → 走现有 understand 管线 | S | M3.5 独立模块 |
| FR-52 | **本地自动成片**：输入图文素材+剪辑单 → ffmpeg 拼接/字幕烧录/可选 TTS 配音 → 输出 MP4 | S | M5+ 专项 |
| FR-53 | 成片任务进度与结果管理（本地产物目录） | S | 随 FR-52 |

> 合规保持：所有剪辑仅在本地完成，产物交给用户自行发布；不自动上传任何平台（沿用 ADR-010）。

## 4. 非功能需求（NFR）

| 编号 | 需求 | 目标值 |
|---|---|---|
| NFR-01 | 本地一键启动 | 双击脚本 ≤ 3 步可用；Python/Java 无外部服务依赖 |
| NFR-02 | 数据本地 | 素材/稿件/画像仅存本地 SQLite，无云端账号 |
| NFR-03 | 密钥安全 | API Key 仅存 .env；仓库零密钥；开源合规 |
| NFR-04 | 响应时间 | 真实 LLM 单平台 ≤ 60s（取决于上游）；mock 即时 |
| NFR-05 | 平台并发 | ≥4 平台并行生成（线程池） |
| NFR-06 | 兼容 | Windows 为主；浏览器端 Chrome/Edge；预留 mac/Linux 脚本 |
| NFR-07 | 可扩展 | 新增平台=新增 1 个 DNA YAML + 注册，不改管线代码 |
| NFR-08 | 可测试 | Python pytest 全绿；Java JUnit 全绿；mock 模式可离线验证 |
| NFR-09 | 合规红线 | 不自动发布、不爬平台数据、只处理自有/授权素材 |

## 5. 范围与边界

**In**：素材解析→策略→多平台成稿→质检→人工确认→复制导出→（M3）剪辑单 →（M4）效果复盘 →（M3.5/M5+）视频入料与本地成片。
**Out**：
- ❌ 自动登录/自动发布到平台（规避封号与平台条款风险）
- ❌ 账号矩阵管理、多账号绑定
- ❌ 图片/封面等视觉素材的**自动生成**（v1 仅文本与封面文案建议；B 阶段仅做素材拼合，不生成画面内容）
- ❌ 素材抓取/搬运/洗稿定位（差异化在"自有素材的再利用"）
- ❌ 热点自动抓取（v1 热点由用户手动提供，不爬平台）
- ❌ AI 剪辑产物自动上传（剪辑仅本地完成，发布仍由用户手动执行，沿用 ADR-010 红线）

## 6. 验收基线（MVP 定义）

**MVP = FR-01~14 + FR-20~23 + FR-40~43 + FR-50（M1~M3）**：
1. 一段真实素材 → 至少小红书可出完整稿件，qa_passed；
2. 稿件可在界面复制/导出，人工可编辑；
3. 多平台勾选生成能并行返回；
4. 视频类平台（抖音/B站）成稿附带**剪辑单**；
5. 全程本地运行，无 Key 走 mock 可演示。

M3.5 视频入料（FR-51）、M4 记忆复盘闭环、M5 开源发布与自动成片专项（FR-52/53）
（验收见 docs/07 用例与验收标准）。
