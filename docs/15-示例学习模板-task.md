## 1. 背景与问题

M5 交付后，用户模板**只能手配**——要用户自己想清楚"我的开头句式/正文结构/结尾互动"并逐项填写。但真实场景里，创作者往往**先有作品、后意识到套路**：

> "我这篇爆了，但我说不清为什么爆、更写不成规则。"

ADR-014 早已规划此能力并明确约束：**拆解产物必须人工确认后才启用**，避免机器学出伪规律直接污染生成质量。

## 2. 目标

让用户**喂一篇自己的爆款/范例 → 系统拆解出结构参数 → 生成"草稿模板" → 人工审阅确认后启用**。

1. 支持粘贴示例文本，自动拆解为模板字段（语气/开头/结构/结尾/标签风格）
2. 拆解结果先落为**草稿态**模板，不进入生成选项
3. 用户可预览、编辑、**确认启用**或丢弃
4. 确认启用后才出现在生成页模板选择器（UC-15）

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 拆解学出"伪规律" | 污染后续生成质量 | 强制草稿态 + 人工确认；UI 明示"AI 拆解结果，请核对" |
| LLM 返回结构不合法 | 模板字段缺失/类型错 | 严格 schema 校验 + 字段兜底为空；mock 路径保证结构完整 |
| 老库无 `status` 列 | 启动报错 | `PRAGMA table_info` 检测后 ALTER；老模板默认 `active` |
| 草稿越积越多 | 模板库混乱 | 草稿在 UI 中独立分组 + 支持一键丢弃；不做自动清理（避免误删用户内容） |
| 草稿模板被生成引用 | 违背 UC-16 验收 | 服务端与前端**双重过滤**：`/api/templates?status=active` 为默认 |
| 示例含他人作品 | 版权风险 | UI 提示"请仅使用自有或已获授权的示例"；不存储原文，仅存拆解结果 + 备注 |

## 7. 待确认项

| # | 问题 | 建议默认 |
|---|---|---|
| Q1 | 草稿模板能否直接编辑后再启用？ | **能**。草稿即普通模板 + 状态标记，编辑沿用现有 PUT |

| Q3 | 是否保留示例原文？ | **否**。仅存拆解结果 + `source_note`（用户自填备注），降低版权与隐私风险 |
| Q4 | 草稿是否计入模板数量上限？ | 无上限限制，UI 单独计数展示 |
