## 1. 默认值表（**每一项都必须能被覆盖**）

| 参数 | 默认值 | 依据 |

| 输出级别 | **正常**（阶段 + 耗时 + 进度 + 重要行 + 心跳） | 安静看不到过程，详细会刷屏 |

## 本轮修掉的两个真问题（都是"我以为接上了，其实没有"）

1. **阶段行跑到了 stderr**。`RunLog` 默认 stream 是 `sys.stderr`，于是"阶段行"
   和"报告"分在两个流里 —— 终端里看着正常（两个流都汇到屏幕），
   一旦被捕获就**顺序全乱、stdout 里什么都没有**。已统一到 stdout。
   > 教训：多流输出在交互式终端下**看不出问题**，只有捕获才暴露。
2. **`verbose` 与 `normal` 行数相同**。我把 `log.raw()` 写好了却没接上调用点。
   已把 `on_raw` 一路接到底层（并且刻意让它输出**实际执行的命令** ——
   成功时 ffmpeg 的 stderr 是空的，光靠错误行撑不起"详细档更详细"）。
